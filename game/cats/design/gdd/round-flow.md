# 回合流程與計分

對照來源：design/reference-original-rules.md（原作規則調查）。
標記：【原作】原作有且已查證；【我們定】原作查不到預設值或我們自己的設計；【未驗證】。

## Summary

一回合三段：準備（貓躲）→ 搜索（狗找）→ 揭曉。時間到還有貓沒被打中，貓隊贏。

## Core Rules

1. 進房後房主開始遊戲。系統抽出狗，其餘是貓。狗的數量【我們定】：≤5 人 1 隻，6–9 人 2 隻，10–14 人 3 隻，房主可改。
2. **準備階段**：貓自由移動、塗色、擺姿勢。狗待在玄關外的等待區，看不到屋內【我們定：原作沒寫狗此時在做什麼】。
3. **搜索階段**：狗進屋。貓還能動、能繼續塗，但動了就容易被看到。
4. 狗打中貓：基本模式該貓出局，轉為觀戰【原作】。
5. 結束條件（任一）：時間到；所有貓出局；所有狗的球數歸零（貓隊立刻贏）【原作】。
6. **揭曉階段**：所有人的位置與塗裝公開，沒被找到的發紅光，被找到的發藍光，全員可用自由鏡頭【原作】。
7. 準備和揭曉階段可以全員投票跳過【原作】。

## States and Transitions

```
Lobby → Prep → Seek → Reveal → (下一回合 Prep | Lobby)
```

| 轉換 | 觸發 |
|---|---|
| Lobby→Prep | 房主按開始，且至少 2 人 |
| Prep→Seek | 倒數結束，或全員投票跳過 |
| Seek→Reveal | 時間到／貓全出局／狗全沒球 |
| Reveal→下一段 | 倒數結束，或全員投票跳過 |

中途斷線：貓斷線視為出局；狗斷線則其球數不計入「全沒球」判定；房主斷線回到 Lobby【我們定】。

## 預設時間【我們定，原作預設值查不到】

| 階段 | 預設 | 房主可調範圍 |
|---|---|---|
| 準備 | 120 秒 | 30–300 |
| 搜索 | 180 秒 | 60–600 |
| 揭曉 | 30 秒 | 10–60 |

## 計分

- **見落とし分**（我們叫「眼皮底下」分）：貓靜止、在某隻狗的畫面內、且沒被打，每秒累積【原作有此機制；公式查不到】。
- 公式【我們定】：每 0.5 秒檢查一次。貓在狗畫面中佔的像素比例 `a`（0–1），貓速度 < 0.05 m/s。`每次加分 = round(10 × sqrt(a × 100))`，`a < 0.0005` 不算。
- 狗的畫面上每 30 秒更新一次見落とし排行【原作】，房主可關。
- 回合勝負只看隊伍；見落とし分用來排個人名次。

## Edge Cases

- 最後一隻貓出局和時間到在同一幀：算狗贏。
- 狗最後一顆球打中最後一隻貓：先結算命中（+1），算狗贏。
- 貓卡進物件：深度超過身體半徑的 60% 時出現警告，持續 3 秒則位置對狗顯示【原作有埋入警告與暴露；數值我們定】。
- 準備階段結束時貓在半空：照常開始。

## Tuning Knobs

狗的數量、三段時間、見落とし係數、排行更新間隔、埋入門檻。全部放在 `data/rules.json`，不寫死。

## Acceptance Criteria

- [ ] 腳本跑完一整回合：Prep→Seek→Reveal，三種結束條件各觸發一次。
- [ ] 見落とし分：貓在狗正前方 3 公尺靜止 10 秒，分數 > 0；貓在狗背後，分數 = 0。
- [ ] 揭曉時紅藍高亮與實際結果一致。
- [ ] 所有數值改 json 不改程式就能生效。
