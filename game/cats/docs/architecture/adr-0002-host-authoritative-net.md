# ADR-0002：房主權威連線

## Status
Proposed（傳輸層未選定，垂直切片之後做技術原型）

## Context
2–14 人好友房，沒有專用伺服器預算。原作也是玩家開房、沒有快速配對。

## Decision
- 一名玩家當房主，房主的模擬結果為準：命中判定、球數、回合狀態、可撞物位置、見落とし分。
- 客戶端送：輸入（20 Hz）、姿勢、塗色筆劃、開槍請求。
- 房主送：狀態快照（15 Hz，角色位置插值）、事件（可靠傳送）。
- 會動的場景物件不同步，由回合時間算出。
- 傳輸層做成介面，三個實作：
  1. 本機迴路（單人測試、腳本試玩）。
  2. WebRTC DataChannel（網頁試玩用，需要一個很小的信令服務）。
  3. Steam 連線（正式版，走 Steam 的中繼，玩家不用開埠）。

## Alternatives Considered
1. 專用伺服器：體驗最穩，但有持續費用和運維。否決。
2. 完全點對點、各算各的：命中判定會吵架。否決。

## Consequences
- 房主離開，房間結束（先不做房主轉移）。
- 房主可以作弊。好友房可接受。
- 見落とし分需要知道「貓有沒有出現在狗的畫面上」：由各狗的客戶端自己算再回報房主，房主做合理性檢查（距離、朝向）。

## Risks / 未驗證
- Electron 裡接 Steam 連線要用第三方橋接函式庫，選型、授權、穩定性都還沒查。
- WebRTC 在部分網路環境連不上，需要中繼服務，會有費用。
- 14 人房的流量還沒量過。

## Validation Criteria
- 兩台不同網路的電腦能進同一房、打完一回合，結果一致。
- 人為加 150 ms 延遲時，開槍命中判定仍讓開槍的人覺得合理。
