## 1. 核心循環（參考結構）

顧客開車到停車場 → 走進超市 → 到一個或多個部門排隊 → 店員處理 → 到收銀台結帳 → 金幣入帳 → 離開。
玩家用金幣做五件事：升級部門、雇店員、提高處理速度、加收銀台、擴停車場。賺得更快後，升級整間超市的星級，或開新店。

原包的機制形狀：
- **部門**：11 個，依次解鎖，建造價格按數量級遞增。每個部門有：底價、最大排隊人數、最多 5 名店員、
  升級花費 = 初始花費 × 成長率^(等級−1)（成長率約 1.06–1.075）、處理速度隨「生產力」等級線性提高。
- **部門外觀階段**：等級跨過門檻（25、50、75、100…）時商品換名、換圖、收益乘一個倍數。
- **超市星級**：16 級，升級價格從 1e9 級到 1e106 級，每級提高全店收益底數。
- **史詩升級**：用鑽石買，永久加成（全店利潤 ×2、顧客速度 +5%、各部門經理 +50%、成本 −2% 等）。
- **任務**：線性任務鏈（升到某級、接待多少顧客、收多少輛卡車），獎金幣或鑽石。
- **隨機事件**：送貨卡車、貴賓車、巴士（一次來一批顧客），點擊領獎或看廣告加倍。
- **離線收益**：按離開時長結算，可看廣告加倍。
- **鑽石來源**：任務、看廣告。原包沒有內購。

## 2. 我們的設計

### 2.1 保留並重做
部門、店員、收銀、停車場、星級、任務、離線收益、隨機事件。數值表重新排（見 §5）。

### 2.2 四個創新
1. **高峰時段（親手上陣）**：每 8–12 分鐘觸發一次，持續 30 秒。玩家可選一個崗位：
   - 收銀：商品從傳送帶滑過，點擊掃碼，連擊越高獎勵越高；
   - 補貨：把箱子拖到對應貨架。
   完成度換成 5 分鐘全店收益倍數（×1.5 / ×2 / ×3）。不參加沒有懲罰。
2. **連鎖版圖**：一家店升到指定星級後可在地圖上開下一座城市。每座城市有不同的部門組合、外觀和一項城市特性
   （例如某城夜間客流更高）。舊店繼續產出。
3. **店長**：每個部門可配一名店長，有一項主動技能（冷卻制）和一項被動加成。直接購買或鑽石解鎖，**不做抽卡**。
4. **季節活動**：白色星期五、齋月、開齋節、國慶等。店面換裝，有獨立任務鏈和活動貨幣。活動日期寫在活動表裡。

### 2.3 砍掉
微信邀請、微信排行榜、分享、原包的全部文字和品牌惡搞招牌。

### 2.4 部門清單（我們的，暫定 12 個）
生鮮蔬果、烘焙、肉鋪、海鮮、乾果椰棗與香料、咖啡與茶、服飾、香氛、家電、手機數位、珠寶、汽車展廳。
部門名稱和商品要由熟悉當地的人審一遍，避免刻板印象；不賣酒類和豬肉相關商品。

## 3. 聯機（第二層，異步）

本地優先：核心玩法不依賴伺服器。伺服器掛掉時經營、升級、內購照常，社交入口顯示「暫時連不上」。

| 功能 | 說明 |
|---|---|
| 帳號 | 遊客帳號自動建立；可綁 Apple 登入；遊戲內可刪除帳號 |
| 雲端存檔 | 本地存檔為主檔，定時上傳；換機恢復 |
| 伺服器時間 | 用於離線收益；取不到時用手機時間，單次離線收益設上限 |
| 內購驗證 | 蘋果扣款後本地先發放，伺服器補驗證；沿用 Lantern 的四條規則 |
| 商會 | 最多 30 人；每週共同訂單；按貢獻分獎 |
| 每週聯賽 | 收入相近的 50 人一組，按週營業額排名，升降級 |
| 拜訪互助 | 每天可到好友店裡幫忙一次，雙方得獎 |
| 全服活動 | 全服共同達標，全員發獎 |
| 交流 | 只有預設短語和表情，不做自由聊天 |

防作弊：聯賽成績由伺服器用同一份規則程式重算離線流水，對不上的只不計入排名，不回收已得物品。

## 5. 數值（待做）

- 用腳本模擬三種玩家（不付費、輕度付費、重度付費）30 天進度，確認不卡死、不過快。
- 每個部門的解鎖時間點目標：第 1 個 0 分鐘、第 2 個 3 分鐘、第 3 個 15 分鐘、第 4 個 1 小時、之後每個約為前一個的 3–4 倍。
- 大數用自寫的大數模組，存檔用字串。

## 6. 技術

- 客戶端：規則核心為不依賴畫面的純邏輯模組（伺服器共用同一份）；3D 用 three.js；外殼沿用 Lantern 的原生框架。
- 伺服器：獨立一台，不和現有站點混用。機房位置、配置待用戶提供。
- 多語言：全部文字進一張表；阿拉伯語右到左，場景本身不鏡像。
