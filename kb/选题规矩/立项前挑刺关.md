## 规矩 1：先打分，过了硬门才准开工

- 候选进 `BACKLOG.md` 时必须带齐评分（原有四科 + 下面第 3、5 条新加的「分发」「热度/竞争」），并写上评分日期。
- **工厂取题时要再核一遍**：分数缺失、任一硬门不过、或评分超过 14 天 → 不准开工，退回日报重新评。
- 禁止「先做后评」。BACKLOG 里凡是评分日期晚于开工日期的条目，一律标成违规。

## 规矩 2：入队前做「最危险假设」小实验

每个候选写一行：**这个 app 最可能死在哪个假设上**，再配一个花钱少的验证办法，例如：
- 价格能不能被接受：落地页放价格按钮，看点击率；
- 比竞品强在哪：找 30 个人把截图和竞品并排比；
- 是否真有人要：Reddit / 论坛里搜，至少 3 条独立的「求这种工具」原帖。

实验结果写进候选条目。没做实验的，最多标「待验证」，不能标「可开工」。

## 规矩 3：四科评分之外加一项「分发」+ 定价核算

**分发**（这一项不过就不开工）：用户会从哪里找到它？
- 商店搜索：主词在 iTunes 美区能不能排进前 10？头部真同类评价数是否 < 5,000？
- 有没有现成的社群或渠道（subreddit、论坛、教程站）可以自然触达？
- 两条都答不上来 → 分发这一项判 0。

**定价核算**：
- 写出目标价，依据是竞品价格区间 + 用户在原帖里的付费意愿。
- 买断制不按 CAC/LTV 那套压分（那是订阅制的算法，会把买断 app 误判成低分），但要说明「价格为什么是这个数」。
- 待复核：切点通 ¥18 可能偏低，校准时的建议价是 ¥28–38。

## 规矩 4：Reddit 采集器换上「抱怨关键词表」和信号维度

借鉴 gapscout（整个工具不引入，它的抓取在我们的环境里跑不通）：
- **查询模板**：`"looking for" app`、`"is there an app"`、`"wish there was"`、`"overpriced"`、`"too expensive"`、`"alternative to"`、`"switched from"`、`"gave up on"`、`"hate that"`、`"subscription"`，每条都与圈子关键词组合。
- **每条信号打这几个标签**：附和人数（评论里的 +1 / same）、付费意愿（明确说愿意付钱或说出价位）、已失败的方案（试过哪个 app、为什么放弃）、是否已有免费替代。
- 改 `collectors/reddit_niche.mjs`：输出里带上这些字段，日报按「附和数 × 付费意愿」排序。
- last30days 不进日常采集；候选已确定圈子后按需复查（`python last30days.py "<具体词>" --search reddit,hackernews --quick --emit md`）。宽泛话题搜不出东西，只能搜具体词。

## 规矩 5：需求热度（Google Trends + 搜索联想），必须和竞争一起看

**做法**：每个候选取 3–5 个核心词，做两件事：
1. **Google Trends**：`pytrends`，`timeframe='today 12-m'`、`geo='US'`（中文 app 另查 `geo='CN'` 意义不大，用百度指数替代或跳过），取 12 个月均值。同一次请求里固定放一个**锚点词**（统一用 `guitar tuner`），不同批次的数才能比较。
2. **Google 搜索联想**：`https://suggestqueries.google.com/complete/search?client=firefox&hl=en&gl=us&q=<词>+`，看联想里有没有 `app` / `free` / `calculator` / `optimizer` 这类工具意图词。

**判读**（看比值，不只看热度）：
- **热度 ÷ 竞争**：竞争取主词 iTunes 美区头部同类的评价数（已有 ASO 实打流程）。热度高、竞争也高 = 红海（TuneBench：guitar tuner 44.8，但满地是免费调音器）。
- Trends 是**相对值**，还会混进别的意思（例如 cut list 里混了 fantasy baseball），要用联想词过滤成明确的工具意图再比（比如比 `cut list optimizer`，不比 `cut list`）。
- 联想里没有任何工具意图词 → 需求存疑，扣分。

**2026-09-25 实测数据**（美区，12 个月均值，同一批比较）：

| 词 | 热度 | 备注 |
|---|---|---|
| cut list | 45.5 | 混入 fantasy baseball，需细化到 optimizer |
| guitar tuner | 44.8 | 热但极挤（TuneBench 反例） |
| circuit simulator | 3.3 | 电路台，偏冷门，上架后重点看转化 |
| metronome app | 2.7 | |
| woodworking app | 1.8 | |

联想词：cut list → optimizer / calculator / generator / optimizer app；circuit simulator → online / free / app / arduino / phet。

**做不到的**：绝对月搜索量要用 Google Ads 关键词规划师（需要广告账号）；App Store 自家的热度分要用 Apple Search Ads（需要 ASA 账号）。用户开了账号之后再接，目前用 Trends 加联想做筛选。

**示例脚本**（已跑通，约 10 秒）：
```python
from pytrends.request import TrendReq
import json, urllib.request, urllib.parse
kws = ["guitar tuner", "<候选词1>", "<候选词2>", "<候选词3>", "<候选词4>"]  # 第1个是锚点词
p = TrendReq(hl='en-US', tz=0, timeout=(10, 25))
p.build_payload(kws, timeframe='today 12-m', geo='US')
df = p.interest_over_time()
print({k: round(df[k].mean(), 1) for k in kws})
for q in kws[1:]:
    u = "https://suggestqueries.google.com/complete/search?client=firefox&hl=en&gl=us&q=" + urllib.parse.quote(q + " ")
    print(q, json.loads(urllib.request.urlopen(u, timeout=15).read().decode('utf-8', 'ignore'))[1][:8])
```
注意：pytrends 被限流会报 429，重试间隔 ≥60 秒；每次最多 5 个词。
