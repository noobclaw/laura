# 05 测试用例推导（TEST-CASES.md）

范例：`apps/haul/TEST-CASES.md`（145 条）。

## 1. 推导规则

| PLAN 里的东西 | 至少要有的用例 |
|---|---|
| 对照表每个 ＝/↑ 行 | 1 条功能用例；↑ 行的「更好」要单独可测（数字、行为） |
| 对照表每个 ✕ 行（合规类） | 1 条「证明没做」的用例（例：视频页面没有下载按钮） |
| 每条创新 | 正常路径 + 至少 1 条异常路径 |
| 每个关键流程 | 端到端 1 条（按 PLAN 第 7 节步骤） |
| 免费/Pro 表每一行 | 免费超限 → 付费页；Pro → 限制解除 |
| 付费墙 | 每个 Pro 入口先弹付费页；价格来自 StoreKit；购买、恢复、取消、失败、待批准、断网、退款 |
| 好评引导 | 触发、两步分流、30 天间隔、禁止时机（<3 天、首启 5 分钟、出错后、付费页上）、设置常驻、红线 grep |
| 分享 | 首屏入口、卡片尺寸、隐私默认隐藏、相册权限、10 语言不溢出 |
| 权限 | 每个 `NS*UsageDescription`：用到才要、说明 10 语言、拒绝给「去设置」 |
| 多语言 | 覆盖率脚本、德/法截屏不截断、切换立即生效、语言在设置第一行 |
| UX 通用 | 照抄 factory `03-UIUX.md` F1–F16 与 V1–V9 的可测部分（动态字体 2.0×、对比度、44pt、深浅色、减少动态效果、返回手势） |
| 稳定性 | 冷启动时长、大数据量滚动、长时间运行无泄漏、Monkey 0 崩溃 |
| 数据安全 | 升级迁移备份与回滚、令牌存储位置、抓包无多余请求 |

## 2. 字段（缺一不收）

`ID · 来源（需求编号） · 前置 · 步骤 · 预期 · 优先级 · 里程碑 · 方式`

- **ID**：`TC-<模块>-<序号>`。
- **预期**必须可判定：看得见的文字、数字、文件校验值、状态；禁止「正常」「流畅」「没问题」。
- **优先级**：P0 阻断上架（崩溃、丢数据、付费、隐私、审核红线）/ P1 核心体验 / P2 边角。
- **方式**：A=XCUITest、U=单元测试、M=人工模拟器、D=真机。能自动的不写 M。

## 3. 环境与夹具

用例文件第 0 节写清：设备、iOS 版本、语言、夹具文件清单（包含边界：0 字节、超长名、emoji、损坏文件、大文件）、测试账号、网络条件、StoreKit 配置。

## 4. 覆盖核对

- 统计数（总数、P0/P1/P2、各里程碑）**用脚本数**，不手写估计。
- 每次改 PLAN，同步改用例并重跑核对；PLAN 里没被任何用例「来源」引用的需求 = 漏测，补上再继续。
- 开工时在 `apps/<app>/scripts/tc_coverage.py` 实现核对（解析两份 md 的编号）。

## 5. 用例必须变成会跑的测试（用户 2026-11-28 拍板：「质量验收你要写测试 case 进行测试」）

写在 TEST-CASES.md 里不算测过。每条用例都要**执行**并留下结果：

| 方式 | 落成什么 | 命名 | 谁跑 |
|---|---|---|---|
| U 单元测试 | `<App>Tests/` 里的 XCTest / Swift Testing 函数 | 函数名带用例号：`test_TC_TRN_08_insufficientSpace()` | CI 每次提交 |
| A UI 自动化 | `<App>UITests/` 里的 XCUITest，关键步骤截屏附件 | `test_TC_IAP_01_everyProEntryShowsPaywall()` | CI 每次出包 |
| M 人工模拟器 | 按用例步骤在模拟器操作，每条存截屏或录屏 | 截屏文件名 = 用例号 | 我（Claude）在验收前跑 |
| D 真机 | 用户装 TestFlight 按清单操作，或我远程指导 | 结果回填 | 用户 + 我 |

- **能自动的必须自动**：U/A 类不许改成人工。一条 A 类用例写不出自动测试，要在用例里写明原因。
- **测试先于功能完成**：一个功能的代码合入时，它的 U/A 用例同时合入；没有对应测试的功能不算做完。
- **夹具入库**：第 0 节列的夹具文件放 `<App>Tests/Fixtures/`，测试只用夹具和本地 StoreKit 配置，不连真实账号（真实云账号只在 M/D 类）。
- **CI 产出结果表**：`scripts/tc_report.py` 读 `xcresult`，按函数名里的用例号生成 `apps/<app>/qa/TC-RESULT-<build>.md`（用例号 · 方式 · 结果 · 耗时 · 截屏链接），并和 TEST-CASES.md 对账：**没有结果的用例 = 未测**，不能算通过。
- **失败处理**：失败的用例开缺陷（按 06 分级），修完**重跑该用例及同模块全部用例**，结果表保留失败记录和重跑记录。
