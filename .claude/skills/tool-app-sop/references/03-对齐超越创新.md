# 03 对齐、超越、创新

## 1. 对照表写法（PLAN 第 4 节）

| 竞品编号 | 竞品功能 | 我们 | 做法 |
|---|---|---|---|
| T-xx | … | ＝ / ↑ / ✕ | ＝：用什么实现、至少一样好；↑：具体好在哪（数字、场景）；✕：原因 |

- 拆解里每一个 `T-xx` 必须出现一次（可多行合并，编号要全）。
- ✕ 只允许四种原因：**审核/法律红线**、**需要服务端且收益不够**、**扰民或骗点击**、**平台不适用**（例如 Android 专有）。「工作量大」不是 ✕ 的理由，放进后面的里程碑。
- 统计 ＝/↑/✕ 条数写进回报。

## 2. 「做得更好」的 10 个方向（逐个过一遍）

1. **去打扰**：无广告；弹窗按成就时刻，不按启动次数。
2. **设计**：factory UIUX，自己的原型、色相、hero 图形。
3. **性能**：默认并发、冷启动、大目录滚动，写成可测的数字。
4. **可靠**：断点续传、升级前备份、离线降级、错误写原因和出路。
5. **隐私**：本地优先、令牌只在 Keychain、App 锁、不收集数据。
6. **语言**：10 种（竞品常只有 4–6 种）。
7. **系统原生**：Live Activity、Widget、Shortcuts、Spotlight、Files、分享扩展、AirPlay、PiP。
8. **少一步**：常用操作的点击次数比竞品少（写出对比）。
9. **合规替代**：竞品违规或灰色的功能，用合规做法达成同样目的（例：视频嗅探 ✕ → 只下载用户点击的文件链接）。
10. **修好它的弱点**：每条 W 都要在对照表或创新表里有回应。

## 3. 创新从哪来（≥5 条，写进 PLAN 第 5 节）

- **弱点反转**：W 条里竞品没解决的（例：传不回电脑 → Wi-Fi 传输）。
- **跨区块组合**：竞品分成两页的东西合成一个（例：本地搜索 + 云端搜索 → 全局搜索）。
- **系统新能力**：竞品多年没跟进的 iOS 新 API。
- **可分享的成果**：把 App 里的数据做成好看的卡片（同时是分享功能）。
- **评论里的愿望**：「希望能…」类评论。
每条创新写：编号 `<缩写>-I01`、解决哪个 W 或场景、放在哪个里程碑。

## 4. 竞品常见增长与变现机制：学什么、不学什么

| 机制 | 竞品常见做法 | 我们 |
|---|---|---|
| 好评 | 启动 N 次 + N 天后弹，每 7 天重复；自绘星星，高星去商店、低星去邮件 | 学「先问再引导」的两步法（只限 iOS）；时机改成成就时刻、30 天间隔；不画星星（factory 铁律 13） |
| 去广告 | 买断 / 看激励广告 / 做问卷 / 邀请 | 不放广告，直接买断 Pro |
| 邀请返利 | 邀请 N 人换 N 个月权益 | 不做：需服务端防刷，且奖励换安装有审核风险 |
| 分享 | 分享 App 链接 | 分享「成果卡」（factory 铁律 10），比分享链接更有转化 |
| 免费限制 | 导出、转格式收费 | 系统本来就能做的不收钱；按「数量、次数、高级功能」限 |
| 远程配置 | 拉黑站点、注入脚本、强制更新 | 不做（无服务端、注入脚本有审核风险）；强制更新用 App Store 的版本提示即可 |
| 推送 | 设备注册到自家服务器 | 只用本地通知 |
| 定价 | — | 参考竞品价格区间，功能更多 + 无广告可高 20–35%，写依据 |
