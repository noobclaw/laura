# 08 选题与立项前挑刺关（SOP 第 0 步、第 3 步的完整规则；2026-11-28 从 tool-app-factory 迁入）

原文：`CLAUDE.md`「选题硬性标准」+ `kb/选题规矩/立项前挑刺关.md`。本页是执行清单。

## 第一步：一票否决（看一眼就排除，不打分）

- [ ] **巨头**：主词头部是 Apple / Google / Microsoft / Adobe / 字节 / 腾讯 / 阿里，或有评价 ≥10 万的免费 App。
- [ ] **系统自带可替代**：闹钟、计时器、手电筒、计算器……（除非付费榜有实证的差异化）。
- [ ] **能力天花板**：需出厂标定（dB 声压、血氧）、内容授权（图鉴、法规库、车史）、行业资质（医疗判读）。服务端也解不开。
- [ ] **垃圾赛道**：清理加速、壁纸、山寨 VPN。
- [ ] **红海同质化**：头部真同类评价 ≥5 万且免费可用 → 热度/竞争科必然 ≤2，不做。

命中任一条：写一句原因进 BACKLOG「❌否决」，永不删行。

## 第二步：找题（主选题源）

四个词缺一不可：**垂直细分 + 巨头注意不到 + 抱怨最多 + 还没人做/做得不好**。

- 渠道：Reddit 职业/爱好 sub（养蜂、木工、暖通、潜水、业余无线电、陶艺、香水、桥牌……），不用泛开发者社区（PH/HN 跟踪 69 天 0 产出）。
- 检索：sub 内搜 `app`，top/year，再用痛点词过滤：`no good app` / `wish there was` / `is there an app` / `alternative to` / `overpriced` / `subscription` / `spreadsheet` / `paper and pen` / `excel`。
- **≥3 条不同作者的抱怨原话**，单帖不算数。
- **「圈里还在用 Excel / 纸笔」是最强正信号**：同时证明需求真实、没人做。
- GitHub 开源项目也是题源：permissive 许可证可移植并署名；copyleft 只读代码 → 写自己的中文规格 → 只看规格重写，一行不抄（PLAN.md 明记）。BACKLOG 条目标 `[GH:owner/repo]`。
- **「已经有人做了」不是否决理由**——只要不是红海，做得比他们好就有机会（用户 2026-11 原话）。

## 第三步：四科评分（100 分）+ 两个独立门槛

| 科 | 满分 | 看什么 |
|---|---|---|
| 信号持续性 | 40 | 出现天数、多源交叉、Reddit 附和数 |
| 付费验证 | 25 | 付费榜/内购里有没有真实体在收钱（评价 <10 条的不算真实体；垂直圈子门槛 ≥20 条） |
| 开发可行性 | 20 | 工程量、平台能力、有无参考实现 |
| 竞品缺口 | 15 | 头部 ★ 低、停更、行业软件公司随手做的移动端弃子 |

**双硬门**：缺口 ≥5/15 **且** 付费 ≥15/25。不过线只进观察池。

**分发（0–10，0 分一票否决）**：
- 商店路 0–6：头部真同类评价 <5,000 → 4；5,000–50,000 → 2；更高 → 0；主词联想有工具意图词 +2。
- 社群路 0–4：有活跃圈子能自然发帖/被推荐 +2；有教程站/厂商论坛/KOL 第二渠道 +2。

**热度/竞争（0–10，≤2 只能「待验证」）**：工具意图联想有 = 3；Trends `vsAnchor`（锚点 `guitar tuner`=100）≥5 +2、≥20 再 +2；头部真同类评价 <5,000 +3、5,000–50,000 +1。
命令：GitHub Actions `trends.yml`（沙箱无网络时用；`gh api -X POST repos/noobclaw/laura/actions/workflows/trends.yml/dispatches -f ref=main -f "inputs[words]=词1|词2"`，结果在 `trends` 分支）；本机有网络时 `python collectors/google_trends.py "<词1>" "<词2>" ...`（429 会自动等 70 秒）。中文 App 用百度联想 + 中区头部。

## 第四步：最危险假设 + 小实验

写一行「这个 App 最可能死在哪个假设上」，配一个便宜的验证：
- 价格能不能接受 → 落地页价格按钮点击率；
- 比竞品强在哪 → 30 人并排偏好；
- 真有人要 → ≥3 条独立「求这种工具」原帖。

没做实验 = 最多「⚪排队（待验证）」，工厂不取。

## 第五步：定价核算

写出目标价 + 依据（竞品价格区间 + 原帖里的付费意愿）。默认对标头部竞品价的 1/3–1/2。买断制不按 CAC/LTV 压分，但要说明「为什么是这个数」。

## 可开工的完整条件

双硬门 + 分发 >0 + 热度/竞争 ≥3 + 最危险假设已实验且未证伪 + 评分日期 ≤14 天。
**评分日期晚于开工日期 = 违规「先做后评」。**

## 用户直接点名做的题

用户直接指定做某个 App 时（例如 2026-11 的鼓谱/陶艺/香水/桥牌/FT8 五个），不退回挑刺关，但仍要在 PLAN.md 补一节「立项评分（补）」：四科 + 分发 + 热度/竞争 + 最危险假设，让风险可见；分数低的要明确告诉用户。

## 数据怎么拿（沙箱无网络时）
- iTunes 头部 + 竞品最近评论：GitHub Actions `keywords.yml`（输入 keywords 用 `|` 分隔、countries、review_ids），结果推到 `keywords` 分支的 `keywords.json` / `reviews.json`。
- 竞品差评：先分主题计数（停播、扫描慢、更新即坏、客服、收费…），再读原文；「真同类」要人工确认，搜索结果会混入词义碰撞的大 App（例：`cloud music player` 英区混入 SoundCloud）。
