# 06 出包、TestFlight、ASO、上架

原文：`PIPELINE.md` G8b、G8 与「首次提审清单」，`kb/做app总规矩.md` 第五、六节。

## TestFlight 出包顺序
1. G8a 审计无 P0/P1（**出包前必审**，包括 TestFlight 包）。
2. 单元测试全绿、模拟器截屏看过。
3. 确认 ASC 已有 App 记录、内购商品已建（没有的话请用户建，告诉他具体填什么）。
4. 触发 TestFlight job，读回上传日志：
   - `altool` 输出无 ERROR；
   - 去 ASC → TestFlight → Build Uploads 看处理结果，Failed 多半是 ITMS-90683（二进制引用了相册/相机/麦克风 API 但 plist 没有用途说明）。
5. 告诉用户：build 号、什么时候能在 TestFlight 里装、真机验收清单。

## ASO 三层（提审前必须做完）
**能被搜到**
- iTunes Search API 实测美区 10–15 个用户真会打的词：命中数、付费在位者、头部评价量 → `store/aso.md`。
- 头部评价 <5,000 的词主攻；10 万以上放弃。
- 标题（≤30）= 主词在前 + 品牌（不和在架 App 逐字相同即可）；副标题（≤30）= 第二主词 + 楔子；关键词（≤100，逗号不加空格）= 长尾，不重复标题/副标题已有的词，**不放竞品商标**。
- 每周复测 4 个主词的排名，改元数据后 7–10 天再看。

**搜到后被点**
- 截图自己出（真实界面 + 标题外框），App Store 1284×2778，中英各一套；第 1 张 = 大字标题 + 一句楔子 + 界面；不许出现 App 里没有的功能。
- 图标 60px 可辨。
- 描述第一句就是楔子，不写「欢迎使用」。

**装了后帮你拉新**
- 第 3 次核心操作后请求评价，90 天冷却，不自己画弹窗、不诱导。
- 分享产物带 `Made with <App>`。
- 首周 ≥5 条真实评价——这件事需要用户去找人，要明确告诉他。

## 首次提审清单（ASC，按顺序）
App 信息（副标题/分类/内容权利）→ 年龄分级 → App 隐私（隐私网址 + 「不收集数据」并发布）→ 定价与地区 → 版本页（描述/关键词/支持网址 `256btc.com/support/`/版权/审核联系人，**取消勾选「需要登录」**，选 build，截图）→ 内购（审核截图，加入审核）→ 提交审核。
- 主语言 English (U.S.)；en-US 本地化填全；更新版本每个本地化都要填 What's New。
- 中国区需要 APP 备案号。
- 只发 iPhone（否则 13 英寸 iPad 截图成必填）。
- 删除 ASC 记录这类永久操作由用户自己做。

## 上架节奏
- 每周 1–2 个（防 Apple 4.3 / Google 重复内容）。
- 上架前：真机验收通过 + 真内购走通「购买 → 卸载重装 → 恢复」。
- 上没上架以 iTunes lookup 实查为准。

## Google Play（Flutter 路线）
封闭测试 12 名测试员连续 14 天，以仪表盘「目前已有 N 名测试人员选择参与」为准；数字商品必须走 Play Billing。
