# 02 工厂 SOP（G0–G8）执行清单

原文：`PIPELINE.md`「⭐工厂标准作业流程 SOP」。适用于 Flutter 壳和原生 SwiftUI 两条路线；路线差异在各关末尾标注。

## G0 防撞车
- [ ] `git log --oneline --since="2.5 days ago" -- apps/`：近 2.5 天有其他新 App 提交 → 本轮跳过（大项目按里程碑算）。
- 用户当面要求开做的 App 不受此限。

## G1 / G1b 取题与复核
- [ ] 取 BACKLOG「⚪排队」指数最高项。
- [ ] 复核三件事：评分齐全（四科 + 分发 + 热度/竞争）、硬门全过、评分日期 ≤14 天。任一不满足 → 条目标「退回日报：<原因>」，改取下一项。工厂只复核，不替日报补评。

## G2 立项评审（写码前，全部写进 PLAN.md）
- [ ] **差异化楔子一句话**：「用户为什么选我而不是 <竞品>」。写不出来 = 换题。
- [ ] **招牌功能架构**：核心可靠性机制定死。例：闹钟 = 系统闹钟 API/前台服务（不是通知）；小组件 = provider 端实时算；相机 = resume 时重建；音频分析 = 后台任务 + 可取消 + 删除时安全中止。
- [ ] **权限流程**：每个危险权限 → 先说明 → 系统框 → 拒绝有可见提示 → 永久拒绝给「去设置」。禁止静默失败。
- [ ] **定价**：见 `05-变现与内购.md`。
- [ ] **设计简报**：`templates/design-brief.md` 逐格填，过并排判定（`03-UIUX.md` §5.4）。
- [ ] **里程碑**：大项目拆 M1/M2/M3，每轮交付一个。
- [ ] **术语表**：10 种语言的核心术语（见 `08-多语言.md`）。
- [ ] **真机验收清单**：权限弹窗 / 核心功能 / 传感器 / 边界各 1 行，给用户照着点。
- [ ] **先出设计稿给用户确认**（用户要求过的 App）：用 Design 类型的 artifact，确认后再写代码。

## G3 开发
**通用铁律**
- [ ] 第一个提交先落 design token（颜色/字体/圆角/时长/曲线）和打包字体，再写页面。
- [ ] 首屏就是工具本身；冷启动 ≤2 次点击看到结果；默认带示例数据。
- [ ] 至少一处 signature 场景：由真实数据驱动、每屏最多 1 个、可按「减少动态效果」降级。
- [ ] 专属图标：贴产品功能 + 本 App 主色，1024 源图，60px 仍可辨认；iOS 去 alpha。
- [ ] 所有用户可见字符串可本地化；英文为源语言；App 名英文；**10 种语言翻译全部写完**（`08-多语言.md`）。
- [ ] 每个付费门 → 付费页（列 Pro 内容 + 商店价 + 解锁 + 恢复购买）。
- [ ] 零联网默认（需要联网单独立项说明：做什么、月成本、挂了能否离线降级）。
- [ ] 禁广告 SDK；免费层必须真能用。
- [ ] 分享/导出产物带 `Made with <App>` 回链。
- [ ] 第 3 次完成核心操作后请求评价，90 天冷却。PLAN.md 写明「核心操作」是哪个事件。
- [ ] 单元测试覆盖核心算法、评分/判定、持久化、导出格式（见下 G4）。

**Flutter 壳路线**：`node scripts/new_app.mjs`；`tr(zh:, en:)`；iOS 走 SPM 不提交 Podfile；`permission_handler` 只靠 plist key 开宏；详见 `PIPELINE.md` G3。

**原生 SwiftUI 路线**：见 `04-iOS原生SwiftUI.md`。

## G4 本地验收
- Flutter：`flutter analyze` 零 issue + `flutter test` 全过（本机严禁 `flutter build`）。
- 多语言覆盖率闸门：10 种语言 × 全部 key 都有译文，否则不过关。
- 原生：本地无 Xcode → 推分支让 CI 编译 + 跑 XCTest；结果分支读回。**测试必须真实断言行为**，至少覆盖：
  - 核心算法（用合成信号/样例数据验证输出数值，带容差）；
  - 判定/计分规则的每个边界；
  - 持久化往返（JSON 编解码、独立 UserDefaults suite）；
  - 导出文件格式（二进制头、XML 可解析且小节时值相加正确）；
  - 免费额度与解锁规则。
- 测试失败要找根因：Groovelens 的节拍测试抓出了真实的 2% 速度偏差（帧量化），不是改测试容差了事。

## G5 独立审计（开发期）
按「装到真机上什么会坏」审：权限流、生命周期（后台/来电/拔耳机）、持久化、边界值、Pro 门、并发（删除进行中的任务、音频线程读主线程状态）。清单见 `templates/audit-checklist.md`。修完复审。

## G6 出包 + 冒烟
- [ ] CI 绿。
- [ ] 模拟器装包 → 启动 → 截屏 → **亲眼看截屏**，不许只看绿勾。
- [ ] 运行日志无 crash / fault。

## G6b 美观复查
`03-UIUX.md` §5.3 打分表：≥75 且无否决项。截屏 + 读冒烟截不到的页面源码。丑就打回 G3。

## G7 记账
- 过冒烟只写「🧪待验收」；用户真机验过核心功能才写「📦可发布」；失败标 ⛔ 附根因。
- BACKLOG 总览表挂 `apps/<name>/PLAN.md` 链接。

## G8a 提审前审计（任何出包前都要过，包括 TestFlight）
8 个面，P0（拒审/崩溃/死路）、P1（用户可见）必须清零：
1. 购买流；2. iOS（usage 说明写用途、iPhone-only、背景模式、横屏锁）；3. Android；4. 语言；5. 错误可见；6. 数据安全；7. 崩溃项；8. **商店文案 vs 实现**（每个卖点都真实存在且可达，不提别的平台）。

## G8c 参考保真（有 GitHub 参考时）
`apps/<app>/REFERENCE.md`：核心函数清单逐条标「一致 / 有意偏离（产品理由）/ 漏掉」，漏掉的补齐并加对照测试；剩余 >0 不准提审。
