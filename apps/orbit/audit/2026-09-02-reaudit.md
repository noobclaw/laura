## iOS 航向源结论(headingForCameraMode 的语义,给源码行号)

`flutter_compass-0.8.1/ios/Classes/SwiftFlutterCompassPlugin.swift`:

- **:20-21** `motion.startDeviceMotionUpdates(using: .xMagneticNorthZVertical)` —— 姿态参考系的 X 轴 = **磁北**。
- **:46-47** `var trueHeading = newHeading.trueHeading; var headingForCameraMode = trueHeading;` —— 仅作**初值/回退**。
- **:50-77** `if let data = self.motion.deviceMotion?.attitude { … T = r2 * r1 * R; yaw = atan2(T[0,1], T[1,1]) + π/2; headingForCameraMode = (yaw+2π) mod 2π }` —— 一旦有姿态数据,`headingForCameraMode` **完全由姿态矩阵算出,不含 `trueHeading`**,因此它是**磁北**机背航向。数值上 `(yaw+2π) mod 2π` 恒落在 [0, 360),不会出现负数。
- **:78-88** 只有 `heading`(`headingForUI`)由 `trueHeading` 按屏幕方向 ±90/180 修正 —— 这才是真北、且是**机顶**方向。

三个问句的答案:
1. **真北还是磁北?** 磁北(正常路径)。只有 `deviceMotion` 为 nil 的瞬间才是真北+机顶(=首轮 R1 的 180° 错),该情况实际只在插件注册后头几十毫秒或无陀螺仪设备出现(iOS 12+ 机型全有陀螺仪),可忽略。
2. **`trueHeading == -1`(未授权定位)时?** `:45` 门槛是 `headingAccuracy > 0`,与定位授权无关,事件照发;`headingForCameraMode` 由姿态算出,是**合法的磁北值**,罗盘照常工作(这是修复后的正向收益:拒绝定位的用户也能用对齐页)。同时 `heading = -1`。只有「姿态也为 nil」时 `headingForCameraMode = -1`,被 `sensors.dart:116` 丢弃 ✓。Dart 侧 `headingForCameraMode` 为 null 只在整个 list 为 null 时发生(`flutter_compass.dart:23`),iOS 实际不会走到 `?? e.heading` 回退;即便走到,`heading` 是机顶方向,会回到 180° 错——但该分支实际不可达,不算问题。
3. **公式是否真给机背方位?** 用 Dart 模拟「手机竖直、屏幕朝脸、机背朝方位 B」的姿态矩阵跑插件公式:在 R 的行 = 设备轴在参考系中的表示(v_dev = R·v_ref)这一约定下,B=0/45/90/180/270 → 输出 **0/45/90/180/270**,逐点吻合;另一约定下恒 90°(退化)。插件公式在真机上 8 年没被报「恒 90°」,基本可断定前一约定即 Apple 的约定,即 `headingForCameraMode` = 机背磁北方位。**仍须 iPhone 真机 45°/60° 仰角各验一次**(首轮已要求)。

`headingIsTrueNorth` 为 `static final` 惰性初始化,首次访问时读 `Platform.isIOS`(dart:io,不依赖 binding),任何时机都安全;Windows/`flutter test` 下为 false,测试不受影响。
