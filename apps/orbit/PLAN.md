## 差异化楔子（第一屏就要立住）

**SkyView 是给你看星座的，Orbit 是告诉你头顶那颗人造卫星几点几分、从哪个方位过境的。**

星空 App 遍地都是，但它们的重心是「这颗星叫什么」。Orbit 只回答一个问题：**今晚几点抬头、朝哪儿看、能看多久、有多亮**——过境预报是主角，天空图只是为了让你把手机举起来对得上。
配套的三条硬承诺：① 全程离线算（SGP4 轨道推演跑在你手机上，不请求网络权限）；② 一次性买断，无订阅无账号；③ 轨道根数的**新鲜度公开显示**，不拿过期数据糊弄你。

## 为什么是它

- 信号 23/40：邻域 AR 天文付费面连续 3 日成立（`SkyView® #7`、`PeakFinder #12`，双双守美区付费 Top15）。
- 付费 15/25：刚好达硬门下限，**依据是邻域旁证**（SkyView/PeakFinder 是 AR 观星/地形，非卫星过境），Orbit 自身品类付费面未验证——这是本项已知的最大风险，写在这里不粉饰。
- 缺口 8/15：SkyView 偏观星图鉴，专注「卫星过境预报 + 抬头对齐」且干净买断的位置有空位。
- 开发 12/20：SGP4 + 传感器姿态，纯本地数学，天然满足「无服务端」硬标准。

## ⚠️ TLE 数据许可裁定（G1 第 2 项闸门，写第一行代码前已解）

**结论：可以捆绑快照，且同时提供用户自带 TLE 的兜底通道。**

1. 双行轨道根数（TLE/GP）由美国太空军第 18/19 太空防御中队生成并公开发布，属**美国政府作品**（17 U.S.C. §105），不受版权保护。
2. 本次快照取自 CelesTrak 的 `visual`（肉眼可见亮星）组，157 个目标，历元 **2026-08-02（26214）**，落盘为 `assets/tle/visual.txt`。CelesTrak 对该数据的使用限制针对的是**服务器抓取频率**，而非静态快照的再分发；本 App **在运行期完全不访问 CelesTrak**（零 INTERNET 权限），不构成抓取负担。
3. **兜底通道照做**（BACKLOG 预案要求）：App 内置「粘贴导入 TLE」——用户在浏览器打开 CelesTrak 拷贝文本、回到 App 粘贴即可覆盖/新增目标。**不引入任何联网更新路径**，零服务端硬标准完整保留。
4. ⚠️ **留给上架前（G8）的人工确认项**：以上是工程判断，不是法律意见。上架前请再核一次 CelesTrak 当期条款页；若届时不允许再分发快照，**删掉 assets/tle/ 即可**——粘贴导入通道已经是完整可用的独立路径，App 不会因此不成立。

### TLE 会过期，这是本品类的真问题，我们的处理是「诚实 + 可自助」

低轨卫星根数过 2~4 周就会有分钟级的过境时刻偏差。**不装作没这回事**：

- 目录页与每条过境卡都显示**元素龄期**，并按龄期给出精度分级：`≤7 天 = 精确`、`8~30 天 = 分钟级偏差`、`>30 天 = 仅供参考，建议更新`。
- 超过 30 天时，首页横幅主动引导去「更新轨道数据」，一步到粘贴导入页（附一键复制 CelesTrak 网址）。
- 这条恰恰是差异化的一部分：竞品要么联网偷偷更新（那就不是离线 App 了），要么闭口不提精度。

## 招牌功能架构评审（G2）

| 关键机制 | 选型 | 为什么不是另一种 |
|---|---|---|
| 轨道推演 | **SGP4 近地模型（WGS-72），纯 Dart 自实现** | 唯一与 TLE 配套的传播模型；开普勒两体解算会有公里级误差。捆绑目录**只收周期 < 225 min 的近地目标**，从而不需要 SDP4 深空修正——目录加载时按周期过滤，深空目标直接不入库。 |
| 过境搜索 | **自适应步长扫描 + 二分求根**，跑在 `compute()` 隔离区 | 固定 30s 步长在 157 目标 × 10 天下要跑上百万次推演，主线程必卡。卫星绝大多数时间深埋地平线下，按仰角负得越多步长跳得越大，实测省掉约一个数量级；升起/落下用二分收敛到秒级，最高点用三点抛物线插值。 |
| 可见性判定 | 几何三条件：仰角 ≥ 阈值 **且** 卫星被太阳照到（圆柱地影模型）**且** 观测者天已黑（太阳高度 < −6°） | 只按仰角报过境会把大白天的过境也报出来，用户抬头什么也看不见 = 差评。 |
| 姿态对齐 | **磁力计朝向（flutter_compass）+ 加速度计俯仰（sensors_plus）**，不上 ARKit/ARCore | v1 明确免 AR（BACKLOG 预案）。相机 AR 要处理相机生命周期、权限、机型兼容三重风险，而「转到这个方位 + 抬到这个仰角」两个数就足以把人对上天。 |
| 定位 | 一次性 GPS 定点（geolocator），**手动输入经纬度为一等公民** | 观测点不需要连续定位；拒权限/室内冷启动都能靠手输坐标走完全流程，不让权限卡死主线。 |
| 过境提醒（推送） | **v1 不做**，改为页内实时倒计时；v1.1 再上 | 干净闹钟的教训：靠通知调度的定时在 Doze/国产 ROM 下会静默不响。宁可不做，也不做一个「你以为会提醒结果没响」的功能。做的话必须走 AlarmManager/前台服务路线，单独立项。 |

## 页面结构

1. **过境预报（首页）** — 渐变夜空 hero（下一次过境倒计时 + 目标名 + 「西北 → 东南，最高 62°」+ 可见性徽章），下方按日分组的过境卡列表（每卡带迷你天空弧线）。空状态：星图图标 + 「先给 Orbit 一个观测点」引导。
2. **过境详情** — 自绘天空穹顶（方位圈 + 仰角环 + 轨迹曲线 + 起/最高/落标记），逐点时刻/方位/仰角表，可见性说明，「去对齐」入口。
3. **对齐** — 大罗盘 + 俯仰指示，实时显示该目标当前方位/仰角，对准时高亮；无传感器时降级为文字指引。
4. **目标库** — 捆绑目录列表（精选在前），每项显示元素龄期与精度分级；Pro 门；入口去「更新轨道数据」。
5. **更新轨道数据** — 粘贴 TLE 文本导入（含一键复制 CelesTrak 网址、解析结果统计、失败原因）。
6. **观测点** — GPS 取点 / 手动经纬度 / 已存点。
7. **设置**（壳提供）— Pro、恢复购买、关于、隐私政策。

## 技术要点

- `sgp4.dart`：TLE 解析（含校验和、隐含小数点、科学计数指数字段）+ SGP4 近地传播，输出 TEME 位置/速度。
- `astro.dart`：儒略日、GMST（IAU-82）、TEME→ECEF、ECEF→测站地平坐标（方位/仰角/斜距）、低精度太阳位置、圆柱地影判定、视星等估算（`m = m₀ − 15.75 + 2.5·log₁₀(d² / f)`，仅对有标准星等的目标给值，其余显示「—」，不编造）。
- `passes.dart`：自适应步长扫描 → 二分求升落 → 抛物线插值求最高点 → 采样成轨迹；跑在 isolate。
- 存储：应用沙盒内单个 JSON（观测点、Pro 标志、导入的 TLE、阈值设置），`path_provider`，不出设备。
- **实测搜索开销**（开发机 desktop、AOT 前的 JIT 下）：免费档 8 目标 × 2 天 = **123 ms**；Pro 满档 157 目标 × 10 天(只要可见过境) = **1385 ms**；157 × 10 天(含暗过境) = **2139 ms**。手机上按 4~6 倍估，最坏约 6~10 s，跑在 isolate 里不阻塞 UI。
- 插件：`geolocator` / `flutter_compass` / `sensors_plus` / `path_provider` / `in_app_purchase`（壳）。原生插件数量与 GoldenScout 同档，`android/gradle.properties` 沿用 CI 档内存（Xmx4096m / Metaspace 1024m）。

## G5 独立审计 + G6b 视觉复审的结果（2026-08-03）

独立审计 agent 通读全部代码出了 21 条；另外用 golden 渲染把 CI 冒烟截不到的屏（过境列表/详情/对齐/目标库/观测点，深浅两套）离线画出来逐屏看过。**已修**：

- **对齐页会在真机上崩**（`CrossAxisAlignment.stretch` 的 Row 直接放进 ListView → 无限高约束断言）。这是招牌功能，等于打开即失败。已改成按可用宽度算高度，并加了**永久回归测试**钉住。
- **Pro 满档只覆盖 24/157 个目标**：过境上限原来在卫星循环里判定，凑够就整个停下，后面的卫星一次没算；排序又在截断之后。列表时间跨度是完整 10 天，用户根本看不出。已改成全量搜完再排序再截断，并在列表底部**明说截到了哪一刻**。
- **「在地影中」这个说法在白天过境上是假的**：卫星明明被太阳照着，看不见只是因为你这边天亮。已拆成三态 `可见 / 在地影中 / 白天,天太亮`，配色与文案分开，详情页解释也分开。
- **磁北 vs 真北**：罗盘读磁北，过境方位是真北，两者差一个磁偏角（北美西岸 +13°、高纬更大），原来直接相减 → 会在指错天区时亮起「对准了」。已在观测点页加**可选磁偏角**输入并参与判定，未填时页面明说「读的是磁北」，容差同时放宽到 12°。
- **传感器关不掉**：`SensorHub` 只有 start 没有 stop、且从不 dispose，进过一次对齐页磁力计就注册到进程结束。已改成引用计数 acquire/release + 应用切后台自动释放，并给读数加了噪声阈值（原来 10 Hz 无条件 notify）。
- **导入只追加不去重**：按 app 自己教的「每月更新一次」，一年后存 12 份重复文本，每次启动在 UI 线程重解析、每次改设置全量重编码。已改成按卫星号合并保留较新历元，存储量恒定；超过 1 MB 的粘贴直接拒绝并说明。
- **免费用户导入后什么都没发生**：Pro 卖点写着「导入自定义目标」，免费用户却能导入且导入无效。现在结果里明说「其中 N 个需要 Pro 才纳入预报（已保存）」。
- **黄昏过境的「升起」时刻是错的**：白昼跳过分支走到天黑时人已在过境中段，那一行给的是半空中某点的方位。已在缺少括号时向回二分找真正的地平线穿越点。
- 其它：`orbit.json` 任一字段类型不对会**静默清空整个目录**（已逐字段容错 + 出错有横幅）；`_save` 非原子写（已改 tmp+rename+bak）；写操作 `await refresh()` 把按钮卡在 busy（已改 fire-and-forget，改设置时列表顶部有进度条，搜索中禁用 chip）；离开几天后预报全是过去的过境而 hero 说「头顶很安静」（已在回到前台时按需重算）；iOS 缺 `NSLocationWhenInUseUsageDescription` 会**直接杀进程**（已补）；iOS trueHeading 的 -1 哨兵会被算成 359°（已丢弃）；geolocator 的非超时异常会把英文异常串甩给中文界面（已统一兜底）；本地 Pro 占位标志会跟着云备份跨设备（已关备份）；首页 1 Hz 定时器每秒重建整份列表（已收进 hero）；极昼地区空态给的建议全都无效（已加纬度判断的针对性提示）。

**已知未做**（写清楚，别当没看见）：
- 磁偏角需要用户手填，没有内置地磁模型。彻底做法是走 Android `GeomagneticField` / iOS `trueHeading` 的原生通道，属 v1.1。
- 被新搜索超越的旧 isolate 不会被 kill（只丢弃结果），靠「搜索中禁用控件」缓解；换 `Isolate.run` 才能真取消。
- 导入的解析仍在 UI 线程（有 1 MB 上限兜底），未搬进 isolate。
- 磁力计校准精度（`CompassEvent.accuracy`）未使用，没有「画 8 字校准」提示。
- `PurchaseService` 全仓零调用方——G8 接真内购时要一并加启动 init + 恢复购买入口。

## 真机验收清单（G7，请照着点）

1. 首次打开 → 出现空状态引导，点「设定观测点」→ **弹出定位权限对话框**（不是静默什么都不发生）。
2. 允许定位 → 数秒内拿到坐标，首页 hero 出现「下一次过境」倒计时且秒数在走。
3. 拒绝定位 → 页面出现红字原因 + 「手动输入坐标」可用；输入任意经纬度后预报照常算出来。
4. 点任意一条过境 → 天空穹顶图画出轨迹曲线，起/最高/落三点时刻方位仰角齐全，数字不跳动错位。
5. 进「对齐」页 → **转动手机，罗盘跟着转**；抬起手机，俯仰角数字跟着变；对准目标方位+仰角时有高亮反馈。
6. 目标库 → 显示「轨道数据 · X 天前」龄期；点 Pro 目标出现购买页（占位解锁后能看到全量 157 个）。
7. 「更新轨道数据」→ 粘贴任意一段 TLE 文本，显示解析成功条数；粘贴垃圾文本，显示失败原因而不是崩溃。
8. 边界：把系统时区改到别的时区，过境时刻应整体平移而不是错乱；飞行模式下全部功能照常（本来就不联网）。
9. 深色/浅色模式各看一遍首页与详情页，都不该有看不清的文字或糊掉的图。
