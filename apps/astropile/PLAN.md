## 一句话定位

把手机连拍的十几张夜空照片对齐叠加成一张更干净的照片；**每一帧都告诉你对上了没有、对不上是为什么**，可以逐帧勾除后重叠。

## G2 招牌功能架构评审（可靠性机制选型，写码前定死）

| 机制 | 选型（定死） | 为什么不是另一种 |
|---|---|---|
| 星点检出 | **游程(run)级连通域 + 并查集**，全分辨率直接做 | 像素级 label 数组在 12MP 上要 `Int32List(12M)=48MB`；游程只在阈值以上的像素上分配，内存与星点数成正比。**不下采样**，因为下采样会把质心精度从亚像素降到 ±1.4px，而对齐残差门槛就是 2px |
| 配准 | **星阵(三角形)不变量匹配 + RANSAC + 相似变换闭式最小二乘** | 角点/特征点法在星图上不成立（星点彼此无结构、互相不可分辨）——这正是参考实现 `astroalign` 的立论。相似变换(4 dof)覆盖手持/赤道仪的平移+旋转+微缩放；不做仿射，自由度越高越容易在少量星点上过拟合 |
| 内存 | **单帧进出 + 对齐后落盘 raw + 叠加按横条(band)流式** | BACKLOG 记「32 帧 × 12MP × float32 ≈ 4.6GB」。实际做法：任一时刻内存里只有 1 帧（解码 RGBA 48MB + RGB 副本 36MB + 亮度 12MB ≈ 96MB 峰值），中值叠加所需的「同一像素的 N 个值」由**按条读盘**提供，峰值 = 条高 × 宽 × 3 × N ≈ 24MB |
| 耗时 | **每帧一个 `Isolate.run`，帧与条的边界即取消点** | 分钟级任务不能占住 UI 线程。取消粒度 = 一帧（数秒），足够；换长驻 isolate + 端口信令会引入泄漏与状态同步风险，收益只是把取消延迟从数秒降到亚秒 |
| 原生依赖 | **M1 不引入 FFI，纯 Dart AOT + `TypedData`**；见下「对 BACKLOG 风险 3 的答复」 | 见下 |
| 结果落地 | 合成结果先落 **raw** 再拉伸编码；拉伸参数改一次不重算叠加 | 让用户拖黑点/亮度滑杆时是**即时预览**（在 1080px 缩略图上算），导出才走全分辨率 |

### 对 BACKLOG「三条工程风险」的逐条答复（G2 必答）

1. **内存 4.6GB** → 见上表。三段式：`对齐(逐帧) → 落盘 → 按条叠加`。峰值 ≈ 96MB，与帧数无关。
   代价是**磁盘**：对齐帧以 8-bit RGB raw 落盘，`W×H×3 × N`。12MP × 32 帧 ≈ 1.17GB。处置：
   - 免费层封 **6 帧**（≈220MB），Pro 封 **32 帧**；
   - 提供**工作分辨率**开关（全分辨率 / 半分辨率），半分辨率磁盘与耗时都降到 1/4；
   - 开跑前在界面上**明写本次预计占用多少临时空间**；写盘失败（`FileSystemException`）单独归一成「存储空间不足，请清理后重试或改用半分辨率」，**不静默**；
   - 结束或取消后立即删除整个临时目录，冷启动再兜底清一次（同 picbox `WorkDirs.clearAll`）。
2. **耗时分钟级** → 每帧一个 isolate，**进度按帧+按条上报**，随时可停止；停止后已完成的逐帧报告仍然保留可看。**不做后台通知/前台服务**：任务生命周期与前台界面绑定，离开页面即停止并说明——比假装能在后台跑完更诚实（这也是免费三支 ★1.00 的高发死法：跑一半黑屏）。
3. **原生依赖（FFI）** → **M1 明确不做，理由写死在这里**：
   - 像素级热点只有两处：`warp`（每输出像素 4 次乘加的双线性）与 `stack`（每像素 N 次读+一次中值）。两者都是 `Uint8List/Float32List` 上的顺序循环，Dart AOT 与 C 的差距在 2–3 倍量级，不是数量级；
   - 真正的大头是 **JPEG 解码**（`package:image` 纯 Dart），而它不是我们写的循环，加 FFI 也绕不开，除非换原生解码器——那是 M2 的事（`flutter_image_compress` 只能整图重编码，拿不到像素）；
   - 引入 FFI 意味着 Android CMake + iOS SPM/podspec 两套构建，**本机不能跑 `flutter build`（8GB 内存，PIPELINE 明令）**，等于把不可本地验证的构建风险塞进 M1；
   - **可证伪**：M1 出包后真机实测 12 帧 × 12MP 全分辨率若超过 **5 分钟**，M2 第一优先级即改为 FFI（或原生解码）。这条写进 M2 待办。

## 参考实现分析（PIPELINE / CLAUDE.md 选题硬性标准第 ①②条）

### `quatrope/astroalign` — **MIT（permissive）**
许可证允许直接依赖或内嵌 + 署名。本项目**未复制任何一行 Python 代码**（Python→Dart 无法复制），实现依据是下面这份自写规格；**署名写进 app 内「关于 → 开源致谢」与 `store/listing.md`**。

规格（读 `_ref/astroalign/astroalign.py` v2.6.2 后自写，含我方改动与理由）：

1. **控制点**：星点按 flux 降序取前 `max_control_points = 50`。少于 3 个 → 判失败（原实现抛 `ValueError`，我方转成用户可读的「星点太少」）。
2. **不变量**：对每个星点取 `NUM_NEAREST_NEIGHBORS = 5` 个最近邻（含自身），在这 5 点里枚举 `C(5,3)=10` 个三角形；三角形不变量 = 边长排序后 `[L3/L2, L2/L1]`（对平移/旋转/缩放不变）。三角形顶点按 `(a,b,c)` 规范排序：`a = L1∩L2`、`b = L2∩L3`、`c = L3∩L1`（`L1<L2<L3`），**保证两图同一星阵的顶点一一对应**。
3. **去重**：不变量重复的三角形只留一个。
4. **匹配**：源不变量与目标不变量在二维不变量空间里做半径搜索，`r = 0.1`（原实现经验值，我方沿用）。每一对匹配产出 3 组点对。
5. **RANSAC**：`PIXEL_TOL = 2`（像素残差阈值）、`MIN_MATCHES_FRACTION = 0.8`、`min_matches = max(1, min(10, floor(0.8 × 匹配数)))`。随机遍历单个三角形匹配作最小样本；用它拟合的变换去测全体，内点数达标即接受，随后**用全体内点重拟合 3 轮**。
6. **变换**：原实现调 `skimage` 的 `similarity`。我方自写闭式最小二乘（见下），结果等价。
7. **重采样**：原实现 `skimage.warp(order=3)` 双三次 + `cval=median`。我方用**双线性**（移动端算力权衡，星点是弥散斑，双线性的差别在肉眼与残差上都不显著）+ 越界像素**不参与叠加**（原实现填中位数，那会在边缘留一圈假背景；我方按覆盖计数求平均，更干净）。
8. **原实现依赖 `sep`（Source Extractor）做星点检出**，`sep` 是 **LGPL**，且是 C 扩展，移动端不可用 → **星点检出这一段由我方从零设计**（见下「星点检出」），只保留其接口语义：`detection_sigma=5`、`min_area=5`、按 flux 降序。

**相似变换闭式最小二乘（我方推导，非抄）**
模型 `u = c·x − d·y + tx`，`v = d·x + c·y + ty`（`c = s·cosθ`，`d = s·sinθ`）。以质心平移后：
```
S  = Σ(x'² + y'²)
c  = Σ(x'·u' + y'·v') / S
d  = Σ(x'·v' − y'·u') / S
tx = ū − (c·x̄ − d·ȳ)
ty = v̄ − (d·x̄ + c·ȳ)
```
逆变换（叠加与重采样都要）：
```
k = c² + d²
x = ( c·(u−tx) + d·(v−ty) ) / k
y = ( −d·(u−tx) + c·(v−ty) ) / k
```

**星点检出（我方规格，无参考实现）**
1. 亮度 `Y = (77R + 150G + 29B) >> 8`，`Uint8List`。
2. 背景：按 `W×H/40000` 步长网格采样约 4 万点，做 3 轮 3σ 裁剪，得 `bkg`、`sigma`（`sigma` 下限 1.0，防全黑图除零）。
3. 阈值 `T = bkg + 5σ`（上限 254）。
4. **游程连通域**：逐行收集 `Y > T` 的游程；与上一行游程按 8 邻接（列区间相交或相邻）并查集合并。每个游程携带 `area / flux / Σfx / Σfy`，`flux = Σ(Y − bkg)`。
5. 过滤：`area < 5` 丢弃（热噪/坏点）；`area > 4000` 丢弃（月亮、地景、云）。
6. 质心 `(Σfx/flux, Σfy/flux)`，按 `flux` 降序取前 50。
7. **保护**：游程总数超过 40 万 → 判「画面过亮或不是星野照片」并把阈值抬到 `bkg + 8σ` 重试一次，仍超则该帧判失败并写明原因（不静默、不 OOM）。

## M2 功能清单

1. **κ-σ 剪切叠加（Pro）** —— 按每个像素自己的均值与标准差剔除离群值再平均，最多 5 轮，κ=2.0（DSS 出厂默认）。比中值多留住降噪，比平均干净。**已知性质**：帧数少于约 8 张时，离群值本身撑大了 σ，2σ 反而容得下它 —— 这写进了模式说明（「八张以上效果最好」）和测试名，不是 bug。
2. **星轨 / 最大值叠加（免费）** —— 取每个像素最亮的一次，**并且跳过星点配准**：地景不动、星星拉弧。相应地，参考帧不再因「太亮 / 星点太少」中止整个任务（月光下的地景正是这个模式的主体）。免费层的 6 帧上限本身就是这个模式的自然分层：弧要长就得买 Pro 的 32 帧。
3. **暗场 / 平场校准（Pro）** —— 各自最多 12 张，取**中值**合成主帧（DSS 自己的推荐引擎在 2–15 张时也推荐中值），在对齐前施加于**包括参考帧在内的每一帧**：`v ← clamp((v − dark) × meanFlat[ch] / max(1, flat[ch]))`。
4. **app 内连拍** —— `camera` 插件，4/8/16/32 张（受 tier 上限约束），拍前锁定对焦与曝光，拍完直接进帧列表。

## M2 的 G8a 提审前审计(2026-09-13,独立只读 agent)

按 PIPELINE 的 8 个面跑了一轮,**2 个 P0、8 个 P1、12 个 P2**。P0/P1 已全部修完,P2 修掉 9 个、其余 3 个记在「已知未修」。修完 `analyze` 零 issue、`test` **78 绿**。

### P0(已修)
1. **`RunPhase.calibrating` 漏进 `isRunning`,整个校准阶段没有停止按钮 —— 而它给出的那个按钮会毁掉任务。** 校准是 M2 最长的新阶段(最多 24 次全分辨率解码),而 `isRunning` 是所有下游的唯一开关:`cancel()` 直接 early-return(**停止在整个阶段里是空操作**)、停止按钮被换成「返回」、`PopScope(canPop: !running)` 与 `automaticallyImplyLeading` 双双**放用户离开**——一离开就 `disposeRun()` **删掉主帧 isolate 正在往里写的临时目录**,再以一个假的「存储空间不足」冒出来;同时进度环画的是「已完成」图标而文案还写着「正在合成校准帧 3/13」。**一行修**:`isRunning` 加上 `calibrating`。
   ⚖️ **这条最值得记住**:它不是 M2 新写的那些算法里的 bug,是**新加了一个枚举值、忘了把它接进既有的状态机**。77 个测试全绿,因为没有一个测试跑真实的 `StackRunner` 相位流转。
2. **iOS 缺 `NSMicrophoneUsageDescription` → ITMS-90683,上传后静默失败。** `camera_avfoundation` 无条件链接音频采集 API(`CameraPlugin.swift:257`、`CameraPermissionManager.swift:52/61/72`),**与 `enableAudio: false` 无关**;插件 README 明写两个 key 都要。**原 PLAN 写「同仓 fieldstamp 用同一套配置已经通过上传」是没有证据的**——审计在全仓找不到任何一条 fieldstamp 通过 ASC 处理的书面记录,而 `apps/picbox/PLAN.md:105` 恰恰把这个风险记为未解决。已在 en + zh-Hans 两侧补上,措辞**以用途开头**(不是「本 app 不用麦克风」——那个句式 09-04 被拒过)。

### P1(已全部修)
3. **连拍拍的是 1080p,不是 2160p** —— `ResolutionPreset.veryHigh` 在 `camera_platform_interface` 里是 **~1080p**,`ultraHigh` 才是 2160p。**M2 的招牌功能原本会产出 2 MP 的成片**,而同一台手机的相机 app 拍 12–48 MP,结果页还写着「导出全分辨率」。改 `ultraHigh`(8.3 MP,仍远低于 26 MP 上限)。
4. **拍完的原片会被删掉,而且从没存到别处** —— 连拍写进 `WorkDirs.fresh('burst')`,帧列表 `dispose()` 递归删掉它。拍 32 张、叠完、返回首页 = **32 张原片永久丢失,全程无提示**。加「把原片存进相册」开关(**默认开**)+ 关掉时明说这组照片叠完就删。

7. **商店文案把免费层拿不到的连拍张数写在通用段** —— 改成「4/8/16/32,以你的叠加上限为准(免费版 6 张)」。
8. **App Store 副标题卖了一个 app 自己在界面上否认的能力** —— `Long Exposure & Frame Report`,而连拍页明写「不能设置长曝光」。副标题是 Apple 按功能声明读的元数据(2.3.1),与 09-04 记下的「付费页卖不存在的功能」同类。改成 `Astro Stacker & Frame Report`,`long exposure` 降进关键词字段。
