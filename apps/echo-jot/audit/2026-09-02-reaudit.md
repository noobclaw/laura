### 🔴
- **L1 `supportsOnDeviceRecognition == true` ≠ 离线模型已就绪,最常见的 iOS 失败被映射成「识别中断,请重试」**(`:355-375`)。iPhone 的离线识别资产跟随「设置 → 通用 → 键盘 → 启用听写」+ 该语言键盘,未启用时 `requiresOnDeviceRecognition=true` 的 task 立即回 `kLSRErrorDomain 102 / kAFAssistantErrorDomain 1101`「Failed to access assets」。现逻辑:每次错误 → `finishSegment` → `beginSegment` 再起 → 4 次(<1 s)→ `recognizer_failed` → Dart 文案「系统语音识别中断了,请重试」。用户怎么重试都一样,而 `capabilities` 又说 onDevice=true 所以**没有横幅**——这是 iOS 版最可能的 DOA 路径,且和首轮 O1 是同一病(「探得到能力、探不到资产」)。修:B6 表里把 102/1101 归到 `on_device_unavailable`,并把 iOS 的 `noOnDeviceHelp` 加上「通用 → 键盘 → 启用听写」这一句(现在 `dictation_controller.dart:272-279` 只说「换语言」)。

### 🟠
- **L2 耳机插拔后引擎静默停摆**(`:438-450`)。`AVAudioEngine` 在 I/O 硬件采样率/声道变化时会**自行 stop 并发 `AVAudioEngineConfigurationChange`**;`onRouteChange` 只重装 tap、不 `engine.start()`,也没监听 configurationChange(首轮 B7 明写要监听)。结果:蓝牙/有线耳机切换后无 buffer → 8 s 空段循环 → 120 s 后 `no_speech`「麦克风被占」。PLAN §7b 第 5 条「插拔耳机继续识别」预计**不过**。修:监听 `.AVAudioEngineConfigurationChange`,`endSegment` + 重装 tap + `prepare()/start()`。
- **L3 同语言回退用 `Set` 顺序,简体用户可能拿到粤语/繁体识别器**(`:158-164`)。`supportedLocales()` 是无序 Set;Dart 因 Y4 未修会把 `zh-Hans-US` 发成 `zh-US` → 精确匹配 nil → 循环里第一个 `languageCode=="zh"` 可能是 `zh-HK`(粤语)。en 亦同(`en-US` 精确命中时没事,但 `en-CN` 这类会随机落到 en-IN/en-ZA)。修:回退时按 `[<lang>-<Dart country>, zh: Hans→CN / Hant→TW, en→US]` 顺序找,或 Y4 落地。
- **L4 探测语言与听写语言不是同一个**。`capabilities` 用 `self.language = Locale.current.identifier`(`:56,126`;iOS 上形如 `zh-Hans_CN`、可能带 `@rg=…`),`start` 用 Dart 传的 `zh-CN`;两者经 `resolveLocale` 走不同分支,横幅「可用/不可用」和实际能否起听写可能不一致。修:`capabilities` 接受可选 `language` 参数,Dart 传同一个 tag。
- **L5 三条非主线程入口直接改状态、动 Timer**:`onInterruption`/`onRouteChange`(`AVAudioSession` 通知不保证主线程)、`speechRecognizer(_:availabilityDidChange:)`。它们调 `failSession → tearDown → segmentTimer?.invalidate()`,而 `Timer.invalidate()` 文档要求在安装它的线程调用;同时与主线程的 `finishSegment` 竞争可能**双发 `final`**(两边都读同一 `segmentText`)。修:三处入口首行 `DispatchQueue.main.async`。`emit` 本身已做 main 派发 ✓。

### 🟡
- **L6 切段间隙丢音**:`endSegment` 后到 `finishSegment` 之间(通常 ~300 ms、上限 700 ms)tap 仍 `request?.append` 到一个已 `endAudio()` 的 request——iOS 静默忽略,不崩;但 55 s「length」切点落在句中时这 0.3–0.7 s 语音**丢掉**(pause 切点落在静音里,损失可忽略)。可在间隙暂存 buffer,新 request 建好后先 append 回去。与 Android 重启 150 ms 间隙同性质,首轮 B4「无缝」目标未完全达成。
- **L7 `reportCapabilities` 每次建 ~60 个 `SFSpeechRecognizer` 并查 `supportsOnDeviceRecognition`**(`:116-125`),该属性走 XPC,单个几十 ms 量级,总耗时很可能 >2.5 s;Dart `refreshCapabilities` 无超时,`probe()` 在启动与每次 resume(未 ready 时)都跑。不阻塞 UI 但设置页会长时间「检测中…」。修:结果按进程缓存(该集合对一台设备是常量)。
- **L8 设置页「已装语言」在 iOS 上是「全部可离线语言按字母排前 6 个」**(`echo_jot_tool.dart:196`),ar-SA/ca-ES/cs-CZ… 用户自己的语言不在其中。B10 已要求 iOS 解释为「可离线识别的语言」并把当前语言排前,未做。
- **L9 `consecutiveErrors` 只在出文本的段重置**(`:390`),长时间沉默 + 零星瞬时错误可累计到 4 → `recognizer_failed`。建议成功完成(含空段)也重置。
- **L10 `.record + .measurement + .duckOthers`**(`:218`):Apple 文档把 `duckOthers` 限于 playback 类,但这正是 Apple「SpokenWord」示例的原句,实机可用,**不算问题**,记录以免下轮再查。
- **L11 数据竞争**:`request` 在主线程置 nil、音频线程读(`:259/:387`),与 Apple 示例同模式,极小概率崩;`lastLevelAt` 同理。可接受。
- **L12 `isAvailable` 在飞行模式下**:`resolveLocale:155/161` 要求 `r.isAvailable`;支持离线的 locale 断网后一般仍为 true,但 PLAN §7b 第 7 条「飞行模式全程可用」必须真机验,若为 false 则 start 报 `on_device_unavailable`。
- **L13 Timer 用 `.default` 模式**(`:304/335`),Flutter 无 UIScrollView 追踪,实际无影响;如日后加 platform view 建议 `.common`。
- **L14 权限双请求**:Dart 先 `Permission.speech`,Swift `start` 再查 `authorizationStatus()`——已授权则不再弹,**无害** ✓;Dart 把 speech 拒绝当永久拒绝(`dictation_controller.dart:239-242`)符合 iOS 语义 ✓。

## 结论:能否进 G6 出包

**iOS 可以进 G6 编译试包,但不能以「iOS 可上架」为目标出包**;Android 侧本轮零改动、无回归,可照旧。按「最可能挂」排序:

1. **真机 DOA 概率最高的不是编译,是 L1**:用户没开「启用听写」或没加该语言键盘 → 每次点话筒 <1 s 内「识别中断,请重试」,且无横幅解释。出包前至少把 102/1101 归到 `on_device_unavailable` + 文案补路径,这是十行改动。
2. **编译本身预计通过**(0 错误、2–3 条 deprecation 警告);唯一我不敢打 100% 的是 `UIDevice` 未显式 `import UIKit`——加一行即闭环。
3. **L2 耳机插拔停摆**会让 PLAN §7b 第 5 条验收失败;**L3/L4** 让中文用户有概率拿错识别器——这两条真机一试就能看出来,建议随 L1 一起改再出包,否则 G6 的 iOS 真机验收大概率要返工两轮。
4. **R2 仍是上架阻塞**:新楔子「不丢字」在代码里是反的(Y3/Y2 未做),listing 卖点没动,PLAN 状态没改;这不挡编译,但挡 G7。
5. 首轮 🟠 O1/O2/O3 与 🟡 全部未动,属已知欠账,不影响本轮出包决策。
