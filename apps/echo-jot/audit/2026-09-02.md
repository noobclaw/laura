## 🔴 阻断项

### R1. iOS 桥接的第二个断点在 Dart 侧:`Platform.isAndroid` 短路,写好 Swift 也不会被调用
- **文件:行**:`lib/tool/dictation.dart:135-139`(`refreshCapabilities` 开头 `if (!_isAndroid) return unsupported`)、`:243-250`(`_isAndroid`);触发链 `lib/tool/dictation_controller.dart:93-103`。
- **现象**:iPhone 上 `capabilities` 根本不会走 MethodChannel,直接返回 `platformSupported=false` → `start()` 在 `:95-101` 给出用户看到的原话「This device has no on-device speech recognition, so dictation is unavailable in this build」。这句话不是原生桥缺失产生的,是 Dart 自己判的。**补了 `DictationBridge.swift` 之后症状一字不变。**
- **真机复现**:任意 iPhone 装包 → 点话筒 → 同样提示;哪怕先把 Swift 桥写好也一样。
- **修法**:`_isAndroid` 改为 `_hasNativeBridge => Platform.isAndroid || Platform.isIOS`(其余平台仍短路);`DictationCapabilities.platformSupported` 注释「iOS is v1.1」同步改。这是 §iOS 接口清单 的第 0 步。

### R2. PLAN.md / listing.md 仍在售卖 08-29 已判「不成立」的楔子,代码兑现的也是旧楔子——上架阻塞未落到文档

- **现象**:PLAN.md 正文没有任何 🔴 标记、没有「楔子须重写」字样(全文 grep `🔴|08-29|逐字|占据` = 0 命中),状态仍写「🟢在做 · M5 待用户真机验收」。任何接手者只读 PLAN.md 会认为这是一个只差真机验收就能上架的 app。

## 🟠 重要项

### O1. 「有设备端识别、但没装当前语言的包」这条最常见的降级路径:探不到、说不清、看不见
- **文件:行**:`DictationBridge.kt:158-182`(`reportCapabilities` 只回 `isOnDeviceRecognitionAvailable`,不比对 `installedLanguages` 与请求语言)、`:94`(`language` 初值写死 `"en-US"`,首次探测用的是 en-US 的 intent)、`:484-490`(API 33+ 收到 `ERROR_LANGUAGE_UNAVAILABLE` 才知道)、`home_page.dart:206`(横幅仅在 `!caps.ready` 时出现)、`home_page.dart:171-180`(错误走 4 s SnackBar)。
- **用户会看到什么**:Pixel 出厂预装英文包、中文要手动下;一台中文界面、没下中文包的 Pixel:首页**没有横幅**(onDevice=true)→ 点话筒 → 权限弹窗 → 进入听写态 → 立刻退出,屏幕底部闪 4 秒一段 60 多字的「请到系统设置 → 系统 → 语言与输入法 → …」,读不完就没了;设置页「设备端识别状态」写着「可用 · 已装语言:en-US」,与首页的失败互相矛盾。API 31/32 更糟:没有 LANGUAGE_UNAVAILABLE 码,Google 引擎对未装语言通常回 NO_MATCH 循环,30 个周期后按 `no_speech` 失败,提示「请确认麦克风没被其它应用占用」——**完全指错方向**。
- **真机复现**:Pixel 设中文,不下中文离线包 → 点话筒说中文。
- **修法**:① Kotlin `reportCapabilities` 在 API 33+ 拿到 `installedOnDeviceLanguages` 后与请求语言做前缀匹配(`zh-CN` vs `zh-Hans-CN`/`cmn-Hans-CN` 都算),不匹配时 payload 加 `languageInstalled=false`;Dart `DictationCapabilities.ready` 改为 `onDeviceAvailable && languageInstalled != false`,横幅文案带上具体语言「还没有 中文(简体) 的设备端语言包」;② `language` 初值改 `defaultLanguageTag()`;③ 这类带操作路径的长提示改成 `SnackBar(duration: 10s)` + 「去设置」动作,或直接复用 `_CapabilityNotice` 横幅(错误码 `on_device_unavailable` 到达时把 caps 标为不 ready 即可自动出横幅)。

### O2. 识别器自行失败时,屏幕上正在显示的 partial 文本被静默丢掉
- **文件:行**:`dictation_controller.dart:193-204`(error 分支只置 idle,不合并 `_partial`)、`:135-136`(`stop()` 在 idle 时早返回 `finalizeTranscript(_committed)`,`_partial`/`_startedAt`/`_levels` 都不清)、`home_page.dart:69-74`(检测到会话自行结束后调 `_finishSession`)。
- **用户会看到什么**:一句「明天上午十点去银行取钱」已经完整显示在 live 框里(partial),此时识别器连续 4 次 ERROR_CLIENT(来电/蓝牙耳机切换/OEM 抽风)→ 会话结束 → 保存的笔记只有之前已 final 的句子,刚才看着出现的那一整句消失,且没有任何提示说少了东西。
- **真机复现**:听写中说一句不停顿,让另一 app 抢麦克风(拨电话/打开系统录音机)。
- **修法**:error 分支在置 idle 前 `if (_partial.trim().isNotEmpty) _committed = appendSegment(_committed, _partial); _partial = '';`;`stop()` 的 idle 早返回路径也要 `_partial=''; _startedAt=null; _levels.fillRange(...)`(否则 `elapsed` 在 idle 时继续增长,只是恰好没人读)。

### O3. 「你的笔记只保存在本机、卸载即删」与系统默认备份相抵触(Android Auto Backup / iOS iCloud)
- **文件:行**:`android/app/src/main/AndroidManifest.xml:18-21`(`<application>` 无 `android:allowBackup="false"`,默认 true → `notes.json` 含全部笔记与 `pro` 标志进 Google Drive 应用数据备份);`lib/tool/note.dart:92-94`(iOS 用 `getApplicationDocumentsDirectory` = `Documents/`,默认进 iCloud 备份);承诺见 `lib/core/branding.dart:33/42`、`store/listing.md:14/61`(数据安全表单勾「不收集/不共享」)。
- **用户会看到什么**:换机/重装后笔记「自己回来了」——对隐私敏感用户(PLAN 定义的核心人群:律师/医生/记者)这正是他们最不想看到的;更实际的是 Play 数据安全表单与隐私政策写「只在本机」,但笔记文本实际上进了 Google 云备份。
- **修法**:二选一并写进隐私政策:**严格版** `android:allowBackup="false"`(Android 12+ 同时加 `android:dataExtractionRules` 排除 `notes.json`)+ iOS 把 `notes.json` 移到 `Application Support` 并设 `NSURLIsExcludedFromBackupKey`(或用 `path_provider` 的 `getApplicationSupportDirectory` + `File.setAttribute` 不可用则走 MethodChannel 设 attribute);**宽松版** 保留备份但隐私政策改成「笔记会随系统备份走,可在系统设置关闭」。Pro 标志随备份恢复是良性副作用,不必处理。

### O4. iOS `NSMicrophoneUsageDescription` 是 whisper 时代的中文残留,且与「不保存录音」承诺矛盾、英文用户看到中文
- **文件:行**:`ios/Runner/Info.plist:7-8`:「需要麦克风权限来录制语音笔记。录音只保存在本机,不会上传。」;对照 `:73-74` 新加的 speech 描述是英文、说的是「Audio never leaves this device」。`project.pbxproj:198-201` `knownRegions` 只有 `en, Base`,无 `InfoPlist.strings`。
- **用户会看到什么**:iPhone 系统权限弹窗写「录音只保存在本机」——app 的整个卖点是**不保存录音**;英文系统用户看到的是一整段中文;App Review 会拿这句和商店描述比对。这是本次查到的唯一一条**用户可见**的 whisper 残留(其余残留只在注释与 `note.dart:149-156` 的旧 `audio/` 目录清理,均无害)。
- **修法**:改为「EchoJot uses the microphone only to feed the system's on-device speech recognizer. No audio is recorded or stored.」;加 `ios/Runner/en.lproj/InfoPlist.strings` + `zh-Hans.lproj/InfoPlist.strings`(含 `CFBundleDisplayName = "回声笔记"`、两条用途描述),pbxproj `knownRegions` 加 `zh-Hans`。

### O5. 全部「去哪下载语言包」的文案写死 Android 设置路径,iOS 用户会被指到不存在的菜单
- **文件:行**:`dictation_controller.dart:255-263`(`_msgNoOnDevice`)、`home_page.dart:366-372`(横幅)、`echo_jot_tool.dart:179-183`(设置页状态)、`echo_jot_tool.dart:223-235`(「原理」页明写 Android 12)、`purchase.dart:40-43`(「需要从 Google Play 安装并登录」)。
- **用户会看到什么**:iPhone 上横幅让你去「系统设置 → 系统 → 语言与输入法 → 设备端语音识别」;购买失败提示让你登录 Google Play。
- **修法**:`l10n.dart` 旁加一个 `platformPath()` 或直接在这 5 处按 `Platform.isIOS` 分支;iOS 路径:「设置 → 通用 → 键盘 → 启用听写」,并在「键盘 → 添加新键盘」加对应语言(iOS 17+ 有独立的「听写语言」下载项);购买文案 iOS 改「需要登录 App Store」。

## 🟡 建议项

### Y1. 每次停止都要硬等 1.2 s「正在收尾…」
- `dictation_controller.dart:142-146` 等 `final`,`:187-192` 刻意不在 `status:stopped` 上放行;而 Kotlin 在最常见的「说完一句、停顿后按停止」场景里,`stopListening` 落在一个还没有语音的新周期上,引擎回 NO_MATCH → `DictationBridge.kt:458-461` 只发 `status:stopped`,不发 `final` → Dart 必然等满 1200 ms。`:519-530` `onResults` 文本为空同样不发事件。
- 修法:Kotlin 在这两处(`!sessionActive` 的 onError、空文本 onResults)追加 `emit(status:"finalized")`;Dart 在 `status` 分支里只对 `finalized` 完成 `_finalWait`。停止即刻收尾,超时兜底保留。

### Y2. 静音超时与「麦克风被占」用同一个错误码,提示指错方向
- `DictationBridge.kt:467-478`:30 个良性周期或 120 s 无进展都 `failSession("no_speech")`;Dart `:275-280` 统一说「请确认麦克风没被其它应用占用」。开会时沉默 2 分钟是常态,用户会被吓到;而且有的引擎 1–2 s 就回 NO_MATCH,30 周期≈45 s 沉默就被踢。
- 修法:分成两个码 `quiet_timeout`(quietMs 超限:「2 分钟没听到说话,已自动结束并保存」)与 `no_speech`(周期数超限但 quietMs 很短 = 引擎瞬回:保留现文案);并把 `MAX_BENIGN_CYCLES` 改成按 quietMs 为主、周期数只作瞬回检测(例如「30 周期且 quietMs < 20 s」)。

### Y3. 长段听写全程只在内存,进程被杀 = 全丢(与本品类被点名的「长录音不可靠」正面相撞)
- `dictation_controller.dart:25-26`、`home_page.dart:120-151`(只在会话结束时 `_store.add`)。从最近任务栏划掉、OOM、崩溃,一个 20 分钟的听写一字不剩;这正是 `reports/2026-08-29.md:152-154` 三支在位者被骂的点。
- 修法:`NoteStore` 加 `draft.json`(每个 `final` 事件写一次,原子写已有);启动时若 `draft.json` 非空 → 直接恢复成一条笔记并用现有 `_LoadErrorNotice` 样式提示「上次听写未正常结束,已恢复 N 字」。与 R2 的方案 A 天然配套。

### Y4. 语言标签丢 script、按地区拼:海外中文用户拿到 `zh-US`
- `dictation.dart:253-259`:`languageCode-countryCode`。iPhone/Android 设「简体中文 + 地区美国」→ `zh-US`;iOS `SFSpeechRecognizer(locale:"zh-US")` 直接为 nil,Android 是否被 Google 引擎容错未知。
- 修法:`zh` 按 `scriptCode`(Hans→`zh-CN`,Hant→`zh-TW`;无 script 看 country 是否 CN/TW/HK,否则默认 `zh-CN`);其它语言若 country 不在该语言常见地区,退回语言码。并把「正在用哪种语言听写」显示在听写态副标题里(`home_page.dart:461-469` 那行),`note.language` 目前存了但从不展示。

### Y5. 落盘失败被吞:磁盘满/权限异常时笔记只在列表里、不在盘上,无任何提示
- `note.dart:159-166` `_persist` 的 `catchError` 只 `debugPrint`。与 G5 审计 #1「静默清空」是同类风险,只是方向相反。
- 修法:`NoteStore` 加 `ValueNotifier<String?> lastWriteError`,`_write` 抛错时置值;首页复用 `_LoadErrorNotice` 显示「笔记未能写入存储(…),请检查空间」。

### Y6. 迟到的 partial 可把同一句写两遍
- `dictation_controller.dart:173-175` 无条件覆盖 `_partial`;若 OEM 引擎在 `onResults` 之后又补一条与 final 相同的 partial(Google 引擎偶发),预览变「买牛奶。买牛奶」,此刻按停止则笔记里真出现两遍。
- 修法:记 `_lastFinal`,partial 文本与之相同(或为其前缀)时忽略。

### Y7. CJK 判定「有一个汉字就算中文」,英文笔记夹一个中文名就会整段按中文拼接
- `transcript_text.dart:40` `cjk = isCjkText(add) || isCjkText(base)`;`logic_test.dart:52-54` 甚至把 `'买牛奶。ok'` 固化成期望。英文用户说「Meet 张三」再说「at noon」→ `Meet 张三。at noon`(无空格、中文句号)。
- 修法:按 CJK 字符占比(>50%)判定主导脚本,或只看 `add` 的主导脚本决定 joiner。

### Y8. 付费墙的「购买后直接开始听写」并未实现
- `paywall.dart:21-24`:`buyPro()` 在拉起商店面板后即返回,`store.pro` 此时仍 false → 返回 false;用户付完款回来发现没开始,得再点一次。注释与行为不符。
- 修法:`buyPro` 返回一个在 `purchaseStream` 收到 `purchased/error/canceled` 时完成的 Future(超时 2 分钟),`checkNoteQuota` 等它;或干脆把注释改成实话。

### Y9. 分享在 iPad 上需要 `sharePositionOrigin`
- `echo_jot_tool.dart:81-85`、`note_detail_page.dart:94-95` 都没传;`project.pbxproj:367` `TARGETED_DEVICE_FAMILY = "1,2"` 含 iPad。share_plus 文档长期标注 iPad 缺此参数会崩(新版本可能有兜底,**须 iPad 真机/模拟器验证**)。
- 修法:传 `sharePositionOrigin: box.localToGlobal(Offset.zero) & box.size`,或把设备族改成 iPhone only(与竖屏锁定一致,也省一套 iPad 截图)。

### Y10. hero 面板的渐变没铺到屏幕底边(手势导航/边到边下露出一条底色)
- `main.dart:74` 外层 `SafeArea` 已把 bottom inset 吃掉,`home_page.dart:435-436` 面板自己的 `SafeArea(top:false)` 拿到的是 0;面板圆角容器下方是一条 scaffold 底色。Android 15 强制边到边后更明显。
- 修法:外层改 `SafeArea(bottom: false, ...)`,让面板用自己的 SafeArea 把渐变延到屏幕边缘。

### Y11. 招牌按钮没有触感反馈
- `ui_common.dart:266-271` `GestureDetector` 无 InkWell 涟漪、无 `HapticFeedback`。一个「盲操」场景(走路/开车)的 app,开始/停止各来一次 `HapticFeedback.mediumImpact()` 成本一行。

### Y12. 中文文案通篇用半角逗号
- 例:`dictation_controller.dart:276`「一直没听到语音,已结束听写。」、`home_page.dart:252`、`branding.dart:16-18`。句号是全角、逗号是半角,排版上不一致。全仓其它 app 若同样如此可视为工厂惯例,但商店审核与截图里会显得不讲究。修法:统一「,」。

### Y13. 小项(一行说清)
- `DictationBridge.kt:94` `language` 初值 `"en-US"`,探测 intent 用错语言(见 O1②)。
- `purchase.dart:88` 把商店返回的 `p.error?.message`(英文技术串)原样弹给用户。

### B. Swift 侧要实现什么(`ios/Runner/DictationBridge.swift`)

**B0. 前置(不做这两条,Swift 白写)**
1. `dictation.dart:135` 放开 iOS(R1)。
2. Dart `_ensureMicPermission` 在 iOS 上追加 `Permission.speech`(permission_handler 已内置,对应 `SFSpeechRecognizer.requestAuthorization`;Android 上它等于麦克风,故可无条件请求两者);或者让 Swift `start` 自己在 `.notDetermined` 时请求。**on-device 识别同样需要这条授权**,不是免的。

**B1. 注册**:`AppDelegate.didInitializeImplicitFlutterEngine` 里(`AppDelegate.swift:13-15`)用 `engineBridge.applicationRegistrar.messenger()` 拿 `FlutterBinaryMessenger`(若当前 Flutter 版本无此属性,用 `engineBridge.pluginRegistry.registrar(forPlugin: "EchoJotDictation").messenger()`),建 `FlutterMethodChannel(name:"echojot/dictation")` 与 `FlutterEventChannel(name:"echojot/dictation/events")`,持有于 AppDelegate 属性,`applicationWillTerminate` 时 dispose。SwiftPM 工程(无 Podfile)下 `import Speech` / `import AVFoundation` 自动链接,pbxproj 不用改。

**B2. `capabilities`**(异步,≤2.5 s 必回,对齐 Kotlin `PROBE_TIMEOUT_MS`):
- 目标 locale = 请求语言(首次探测用 `Locale.current`,不要像 Kotlin 那样写死 en-US)。
- `let r = SFSpeechRecognizer(locale:)`;`onDevice = (r != nil) && r.isAvailable && r.supportsOnDeviceRecognition`(iOS 13+ API,minimum 15.0 已满足;需 A9 及以上芯片)。
- `supportedLanguages = SFSpeechRecognizer.supportedLocales().map { $0.identifier.replacingOccurrences(of:"_", with:"-") }`(iOS 给的是 `zh_CN` 形式,Dart 展示用 BCP-47)。
- `installedLanguages` = 上述集合里 `SFSpeechRecognizer(locale:)?.supportsOnDeviceRecognition == true` 的子集(约 60 个 locale 各建一个识别器对象,放后台队列做、结果缓存;首帧只回当前语言那一条也可)。
- 语言不支持时 `detail` 写明,便于设置页显示。

**B3. `start`**(全部在主线程串行):
1. `AVAudioApplication.shared.recordPermission`(iOS 17+)/`AVAudioSession.sharedInstance().recordPermission` ≠ `.granted` → `permission`;`SFSpeechRecognizer.authorizationStatus()`:`.notDetermined` → `requestAuthorization` 后继续,`.denied/.restricted` → `permission`。
2. 语言归一(Y4):先试请求的 tag,nil 或 `!supportsOnDeviceRecognition` 时按语言码在 `supportedLocales()` 里找同语言且 on-device 的替代(zh+Hans→zh-CN),再不行 → `on_device_unavailable`。
3. `AVAudioSession`:category `.record`(不要 `.playAndRecord`,免得 iPad 扬声器路由),mode `.measurement`,options `[.duckOthers]`;`setActive(true, options: .notifyOthersOnDeactivation)`。
4. 建 `SFSpeechAudioBufferRecognitionRequest`:`shouldReportPartialResults = true`;**`requiresOnDeviceRecognition = true`(硬性,这是产品承诺;设了它 iOS 不会静默上云,不满足直接报错)**;`taskHint = .dictation`;iOS 16+ `addsPunctuation = true`(Dart `appendSegment` 尊重已有标点,`transcript_text.dart:44-46`,不会双标点)。
5. `AVAudioEngine`:`inputNode.installTap(onBus:0, bufferSize:1024, format: inputNode.outputFormat(forBus:0))`——**format 必须每次安装时现取**,缓存旧 format 在耳机插拔后会触发 `required condition is false: format.sampleRate == hwFormat.sampleRate` 崩溃;tap 回调里 `request.append(buffer)` + 算电平(B5)。`prepare()` / `start()` 失败 → `recognizer_failed`。
6. `recognitionTask(with:resultHandler:)`;成功后 `result(nil)`,再 `emit status:"listening"`。

**B4. 把 iOS 的「累计文本」语义翻译成 Android 的「逐 utterance final」语义(最关键的一段)**
- iOS 的 `SFSpeechRecognitionResult.bestTranscription.formattedString` 是**从本次 task 开始到现在的全文**,`isFinal` 只在 `endAudio()`/出错后才为 true;Android 是每个停顿一个 final。Dart 的合并逻辑(`_committed + partial`)按 Android 语义写,所以 Swift 必须自己切段:
  - 每个 task 维护 `taskText`;每次 result → `emit partial: taskText`。
  - **切段条件**(任一满足即 `request.endAudio()`):① 距上次 `taskText` 变化 ≥ 1.8 s 且 `taskText` 非空(静音分句,对应 Android 的 endOfSpeech);② task 存活 ≥ 55 s(见下「1 分钟限制」);③ Dart 调了 `stop`。
  - 收到 `isFinal`(或 endAudio 后 700 ms 兜底)→ `emit final: taskText`(空则不发,但要发 `status:"finalized"` 让 Y1 的方案在 iOS 同样生效)→ 若会话未被 `stop` → **不停 engine、不拆 tap**,只新建 request + task,tap 回调改喂新 request(避免每段都重启音频会话造成 100–300 ms 丢音)。
  - 无文本超时:`taskText` 为空且 task 存活 ≥ ~8 s → 主动 endAudio 重开一段(对应 Android 的 NO_MATCH 周期),计入 `benignCycles`;120 s 无任何文本 → `no_speech`(或按 Y2 拆成 `quiet_timeout`)。
- **关于「iOS 一次识别 ≤1 分钟」**:该限制只针对**服务器识别**;`requiresOnDeviceRecognition = true` 时 Apple 明确无时长限制。但仍按 55 s 切段,理由:① 累计文本越长每次 partial 越大、Dart 每 result 整段 `notifyListeners`;② 与 Android 一致地让 `final` 定期落到 `_committed`(配合 Y3 草稿落盘);③ 万一某机型/语言实际走不了 on-device(该标志会让 task 直接报错而不是上云),分段能把损失控制在一段内。

**B5. 电平**:tap 回调里对 `floatChannelData[0]` 算 RMS → `power = 20*log10(max(rms,1e-6))`(约 -60…0)→ `db = clamp(((power + 50) / 50) * 12 - 2, -2, 10)`,与 Android 量纲一致,≥80 ms 才发一条,并 `DispatchQueue.main.async` 后再调 sink。

**B6. 错误映射**(`NSError` domain `kAFAssistantErrorDomain` / `kLSRErrorDomain`;把 `localizedDescription` 原样放进 `message` 便于真机对照):
- `1110`「No speech detected」→ 良性,等同 NO_MATCH,重开一段;
- `216` → 我方 cancel 引起,忽略;
- 其它(`203` retry、`201` 连接、`1101`/资源类)→ `consecutiveErrors++`,<4 重建 task(必要时重建 recognizer),≥4 → `recognizer_failed`;若 `supportsOnDeviceRecognition` 在会话中翻为 false(`SFSpeechRecognizerDelegate.availabilityDidChange`)→ `on_device_unavailable`。
- 每个 `error` 之后必跟一条 `status:"stopped"`(Dart 依赖顺序)。

**B7. 打断与路由**:监听 `AVAudioSession.interruptionNotification`(来电/Siri):`.began` → 立即 `endAudio` 拿最后一段 final → `failSession("recognizer_failed", "interrupted")`(Dart 文案「系统语音识别中断了,请重试」尚可,若想更准可加码 `interrupted` 并在 Dart `_errorFromCode` 增一项);`routeChangeNotification` 的 `.oldDeviceUnavailable` 与 `.AVAudioEngineConfigurationChange` → 拆 tap、以新 format 重装(不要结束会话)。**不要**加 `UIBackgroundModes: audio`——Dart 切后台就停,和 PLAN §4「不假装后台在听」一致。

**B8. `stop`**:`endAudio()` → 等 `isFinal`(≤700 ms)→ `emit final` → 拆 tap、`engine.stop()`、`setActive(false)` → `emit status:"stopped"`;幂等。

**B9. plist / 工程**:`NSMicrophoneUsageDescription`(改文案 O4)、`NSSpeechRecognitionUsageDescription`(已有)、两者本地化(O4);不加后台模式;`UISupportedInterfaceOrientations` 收成 Portrait(Y13)。

**B10. Dart 侧配套改动清单**:R1 放开 iOS;`Permission.speech`;O5 五处文案分平台;`deviceLanguageTag` 归一(Y4);`DictationError` 可选新增 `interrupted`;设置页「设备端识别状态」在 iOS 上把 `installedLanguages` 解释为「已可离线识别的语言」。

**B11. on-device 语言支持的诚实标注(写进 listing 的 iOS 版)**:iOS 的离线识别语言集合是固定的(英/西/法/德/意/日/韩/普通话/粤语/葡/俄/土等,随 iOS 版本增减),用户**不能在 app 内下载**;iOS 26 的 `SpeechAnalyzer` + `AssetInventory` 才允许 app 内下载,可作 v2 路线,v1 仍用 `SFSpeechRecognizer` 覆盖 iOS 15–25。

## 五维度逐项结论

### 1. 产品设计
- **楔子兑现情况**:代码 100% 兑现的是 PLAN.md:20 的**旧**楔子(买断 / 零网络 / 不留录音),三条都能在 app 内自证(`_HowItWorksPage`、manifest、零音频 IO)。但 08-29 已裁定其中两条被在位者逐字占据、第三条在用户语言里是减分,PLAN.md 与 listing 未更新(R2)。代码结构对报告建议的新楔子是反向的(前台 only / 全内存 / 120 s 自动结束)。**结论:这是一个执行得很好的、方向已被证伪的产品定义;必须用户拍板 A/B 后再谈上架。**
- **免费 30 条 + 买断的门卡在哪**:`paywall.dart:13-25` 卡在「开始听写」之前,按**当前条数**(删一条就能再录一条)计,`echo_jot_tool.dart:71-77` 导出卡「最近 3 条」,详情页单条复制/分享不卡。位置合理(不打断已开始的听写、不锁已有数据)。Pro 标志明文存 `notes.json`(`note.dart:169-172`),无服务端下这是可接受的取舍;Android 12+ 非 debuggable 包无法 adb backup,root 设备可改,不值得防。`RestorePurchasesTile` 在设置页与付费页都有。定价 $4.99/¥28 符合 PIPELINE「对标头部买断价 1/3~1/2」?——头部 `Whisper Notes` $7.99 / `Just Press Record` $6.99,$4.99 是 62–71%,**略高于标准区间**,但报告 08-29 已把付费面证到 $7.99 有人买,可保留;价格显示走 `PurchaseService.price`(`paywall.dart:96-99`),合规。
- **商店文案 vs 实物**:「真离线」✓(`createOnDeviceSpeechRecognizer` 唯一路径,`DictationBridge.kt:310-314`)、「飞行模式照样用」✓、「边说边出字」✓、「自动分句补标点」✓(`transcript_text.dart`)、「全文搜索」✓(`note.dart:214-220`,>4 条才出搜索框)、「编辑/分享/导出」✓、「零网络权限」✓、「不留录音」✓。**不完全成立的一条**:「通常中英文都可下载」暗示能中英文听写,但 app 只按**系统语言**听(`dictation.dart:253`),没有语言切换(PLAN 明写 v2);英文系统的用户说中文,得到的是英文引擎的乱码。listing 应改成「识别语言跟随系统语言」。
- **没装离线语言包的降级路径**(三种情形,用户各看到什么):
  1. **系统根本没有设备端识别服务**(无 GMS 的国产 ROM、Huawei、部分 API 31 老机):`isOnDeviceRecognitionAvailable=false` → 首页常驻橙色横幅(`home_page.dart:326-400`)+ 设置页红色状态 + 点话筒直接拒绝并提示。文案给的路径「系统设置 → 系统 → 语言与输入法 → 设备端语音识别」**只在 Pixel/近原生 ROM 存在**;MIUI/ColorOS 用户按这个路径找不到,而且他们的真实解法是「装 Speech Services by Google」——横幅应该多写这一句。**这条路径整体是诚实的(不上云),但对国产 ROM 等于 DOA,listing 的 Play 首发策略要接受这一点。**
  2. **有服务、没装当前语言的包**(最常见,Pixel 中文用户):见 O1——没横幅、4 秒闪一条长提示、API 31/32 提示指错方向。**这是当前降级路径里唯一「不诚实」的一环,因为它把语言包问题说成麦克风问题。**
  3. **有服务、装了包**:正常。设置页会列已装语言(API 33+),API 31/32 只说「使用系统已安装的语言包」——诚实。
  - 全部路径都**没有云端兜底**,与承诺一致(`DictationBridge.kt` 全文无 `createSpeechRecognizer`)。

### 2. 代码实现(按「装到真机上什么会坏」)
- **麦克风权限流**:请求→拒绝(SnackBar「需要麦克风权限才能听写」,4 s,无按钮)→再点再弹→永久拒绝(SnackBar 带「去设置」8 s,`home_page.dart:153-169`)→`openAppSettings()`。Kotlin 侧再查一次(`DictationBridge.kt:247-251`)。流程完整;唯一瑕疵是首次拒绝的 SnackBar 没有按钮,iOS 上这就是最后一次机会(§C)。权限异常(`Permission.status` 抛错)也有文案。**过关。**
- **录音生命周期**:切后台/锁屏/来电(全屏)→ `paused` → `_finishSession(background:true)` 结束并保存,文案「应用切到后台,听写已结束并保存」(`dictation_controller.dart:160-169`);`inactive`(权限弹窗、下拉通知栏、分屏失焦)不结束——正确,否则权限弹窗一出就会打断启动。Android 12+ 根 Activity 按返回键是「移到后台」而非 finish,所以返回键也走 paused 路径。从最近任务划掉 → 进程直接死 → 未 stop 的内容全丢(Y3)。长录音内存:纯文本 + 27 个 double,无压力;但 partial 每 result 触发整页 `setState`(`home_page.dart:64-66`),长文本下每秒十几次重建整个列表——真机上 20 分钟后是否掉帧值得看一眼,可把 `_DictationPanel` 改成只监听 controller 的 `ListenableBuilder`。
- **识别器生命周期(Android)**:`ERROR_NO_MATCH`/`ERROR_SPEECH_TIMEOUT` → 良性重启(150 ms),预算 30 周期 / 120 s(`DictationBridge.kt:465-479`);`ERROR_CLIENT`/`BUSY`/`SERVER`/`NETWORK*` → 重建识别器,4 次失败报错(`:492-506`);`INSUFFICIENT_PERMISSIONS` → `permission`;`LANGUAGE_*`(API 33)→ `on_device_unavailable`;其它(AUDIO/SERVER_DISCONNECTED/TOO_MANY_REQUESTS)→ 走 else 重启,同样 4 次封顶。连续听写靠 `onResults → final → restartAfterUtterance` 单一 runnable 去重(`:344-348`),分代守卫防迟到回调(`:428-431`)。**设计正确**,问题只剩 O1(语言包)与 Y2(超时提示)。国产 ROM 无 Google 服务:`isOnDeviceRecognitionAvailable` 返回 false 或抛异常均已兜住(`:141-151`),不会崩,显示横幅。`stop()` 后 1500 ms 释放、Dart 只等 1200 ms(Y1)。
- **持久化**:单 JSON、写队列 + `.tmp` rename(`note.dart:158-178`)、坏文件隔离并告知(`:137-147`)、体积在千条量级无问题;失败静默(Y5);备份策略与承诺冲突(O3)。旧 `audio/` 目录首启清理(`:149-156`)——whisper 残留处理正确,可在 1.1 删。
- **Pro 门**:见维度 1;`checkNoteQuota` 只在开始前查,免费用户 30 条后仍可编辑/分享/删除已有笔记——合理。绕过途径只剩改沙箱文件,不防。
- **内购反馈**:`_PurchaseNoticeHost` 挂在根(`main.dart:79-115`),购买/恢复/错误/pending 都有 SnackBar;商店不可用有文案;`completePurchase` 有;价格走商店本地化。缺:购买完成后自动开始听写(Y8);错误串未翻译(Y13)。
- **iOS 差异**:R1、O4、O5、Y4、Y9、§C。

### 3. 逻辑自洽
- **状态机** `idle → starting → listening → finishing → idle`(`dictation_controller.dart:10`):
  - `start()` 期间被 `stop()`/切后台打断:`:118-126` 复核后主动 `stop` 原生——已处理(G5 #7)。
  - 原生在 `listening` 中自行报 `error`:`_onEvent` 置 idle(`:202`)→ home 的 `_wasLive && !live` 触发保存(`home_page.dart:69-74`)——路径通,但丢 partial(O2)。
  - 原生在 `finishing` 中报 `error`:完成 `_finalWait`(`:194-196`),`stop()` 继续走完——通。
  - `stop()` 在 idle 被调(error 之后 home 又调一次):早返回但**不清 `_partial`/`_startedAt`**(O2 后半)。
  - `_finalWait` 只由 `final`/`error` 完成,`status` 一律不放行(`:187-192`)——设计意图正确(stopped 先于 final 到),代价是 Y1。
  - `_ticker` 与 `_finishing` 守卫、`_wasLive` 在 `_toggle` 里晚于 listener 置位——实际由 listener 先置位,`_toggle` 那句是冗余而非错误。
  - **死角只有 O2 一处**,其余边角都有守卫。
- **partial/final 合并**:Android 语义(partial = 当前 utterance 累计、final = 该 utterance 定稿)下,「替换 partial、追加 final」是正确的;不会丢字、不会乱序(同代内引擎保证顺序,跨代由 generation 过滤)。重复的唯一口子是迟到 partial(Y6)。`appendSegment` 对已有标点的尊重、句首大写、CJK 无空格拼接都有单测;`isCjkText` 的「任一汉字即 CJK」在混排时出错(Y7)。
- **时长**:`createdAt = now - elapsed`、`durationMs = elapsed` 在调 `stop()` **之前**取(`home_page.dart:126-127`),不含 1.2 s 收尾,与用户按钮体感一致;error 路径 `_startedAt` 保留所以也准。卡片显示 `m:ss`,超 60 分钟显示 `75:00`,可接受。
- **测试覆盖**:33 个测试全在纯函数与 `NoteStore`,**控制器状态机、事件流、权限分支、能力降级、付费门一个都没有**;widget 测试只覆盖 idle 态首页与列表。见「缺失的测试清单」。

## 缺失的测试清单

以下均可在现有 `flutter test` 下写(用 `TestDefaultBinaryMessengerBinding.instance.defaultBinaryMessenger.setMockMethodCallHandler` 与 `setMockStreamHandler` 伪造两个 channel,`DictationService` 已支持注入 `MethodChannel`/`EventChannel`):

1. **控制器状态机**(`DictationController`):
   - start 成功 → listening;start 期间调 stop → 原生收到 stop、终态 idle、返回 false。
   - listening 中收到 `error` → 状态 idle、`message` 已设、**`_partial` 被合并进返回文本**(现在会失败,对应 O2)。
   - stop 后 1200 ms 内无 `final` → 超时返回、状态 idle;有 `final` → 立即返回且文本含该 final。
   - `status:stopped` 不得提前完成 `_finalWait`;`status:finalized`(Y1 落地后)必须完成。
   - 迟到 partial == 上一 final 时不进入预览(Y6)。
2. **能力降级**:`capabilities` 返回 `onDevice=false` → `start()` 返回 false 且 message 为语言包文案;返回 `MissingPluginException` → `unimplemented` 文案;iOS 平台(用 `debugDefaultTargetPlatformOverride` 无法覆盖 `Platform.isIOS`,需把 `_hasNativeBridge` 改为可注入)→ 不再短路(R1)。
3. **权限分支**:mock `permission_handler` channel 返回 denied / permanentlyDenied / restricted,断言三种 message 与 `permissionPermanentlyDenied`。
4. **语言标签归一**(Y4):`zh-Hans-US → zh-CN`、`zh-Hant-US → zh-TW`、`en-GB → en-GB`、无 country → 语言码。
5. **付费门**:29 条 → 直接开始;30 条非 Pro → 出 sheet;30 条 Pro → 直接开始;sheet 返回 true 但购买未完成 → 返回 false(Y8 定稿后改断言)。
6. **Home widget 测试补齐**:listening 态渲染 `_LiveTranscript`/`LevelMeter`/计时;`loadError` 非空显示 `_LoadErrorNotice`;`caps.ready=false` 显示 `_CapabilityNotice` 且「去系统设置」只在永久拒绝时出现;左滑删除 → SnackBar「撤销」→ 列表恢复原位。
7. **`NoteStore`**:写失败(把 `_indexFile` 指向只读目录)不抛且 `lastWriteError` 置值(Y5 落地后);坏 JSON 启动 → 文件被改名 `.corrupt-*` 且 `loadError` 非空(现有测试只测了 `volatileFallback`,没测隔离路径)。
8. **`transcript_text`**:混排「Meet 张三」+「at noon」的期望(Y7 定稿后写)。
9. **Kotlin**:没有 JVM 单测基础设施,至少把 `Listener.onError` 的分类表抽成纯函数(`classify(error:Int): Action`)并用 Robolectric/JUnit 覆盖 13 个错误码 + 预算边界(30 周期 / 120 s);iOS 桥完成后同样把「切段判定」抽成纯函数测试。
