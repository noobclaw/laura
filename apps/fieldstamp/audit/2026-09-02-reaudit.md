## 新引入的问题

### 🟠 N1 iOS 上「定位服务关闭」被报成「权限永久拒绝」,serviceOff 分支在 iOS 不可达
- `sensors.dart:117-134`:先 `checkPermission` 再查服务开关。iOS 上系统定位总开关关闭时 `CLLocationManager.authorizationStatus` 直接返回 `kCLAuthorizationStatusDenied`(Apple 文档:denied = 用户拒绝 **或全局关闭**),geolocator_apple `AuthorizationStatusMapper.m:16` 映射为 `deniedForever` → `:122` 直接 `_set(deniedForever)`,`isLocationServiceEnabled()` 永远轮不到。
- 现象:iPhone 关掉定位总开关 → 信息带说「定位权限已被永久拒绝 / 请在系统设置里允许 FieldStamp 使用定位」,按钮打开的是 app 设置页(iOS 的 `openLocationSettings` 也只是 app 设置页,`GeolocatorPlugin.m:103-104,172-184`)。用户到了那里看到的是「定位服务已关闭」而非权限行——能自救,但诊断文案是错的。
- 好消息:**不会挂死**。iOS 服务关闭时状态不是 `notDetermined`,`requestPermission` 立即返回(`PermissionHandler.m:47-51`),`_locating` 一定复位。Android 上顺序正确(runtime 权限对话框与服务开关无关,`openLocationSettings` 真开 `ACTION_LOCATION_SOURCE_SETTINGS`)。
- 修法(2 行):`:122` 改成 `if (perm == deniedForever) { _set(!await Geolocator.isLocationServiceEnabled() ? LocationState.serviceOff : LocationState.deniedForever); return; }`。serviceOff 的 hint 文案在 iOS 上也应改成「在 设置 › 隐私与安全性 › 定位服务 打开」。

### 🟠 N2 初始化在飞时 pause→resume(<1–2 s),预览永远转圈、没有重试按钮
- `camera_screen.dart:137-143`:`paused` 时 `_initGen++` 但**不清 `_initFuture`**;紧接着 `resumed` → `_controller == null` → `_initCamera()` 拿到的是还在飞的旧 future,不新起;旧 init 完成后 `:83-88` 发现 `gen != _initGen` → dispose 掉刚建好的 controller 直接 return。结果 `_controller` null、`_cameraError` null → `:273-274` 一直 `CircularProgressIndicator`,快门灰。
- 触发:首启转圈时收到来电/快速切出再切回;Android 上 init(`availableCameras` + camerax `initialize`)常要 1–2 s,窗口不算小。用户要再切一次后台才能恢复,否则以为 app 坏了。
- 修法(3 行):resumed 分支改成
  ```dart
  final f = _initFuture;
  if (f != null) {
    f.whenComplete(() {
      if (mounted && _controller == null && _cameraError == null &&
          WidgetsBinding.instance.lifecycleState == AppLifecycleState.resumed) _initCamera();
    });
  } else if (_controller == null) _initCamera();
  ```

### 🟡 N3 陈旧判定只在有 sensor 事件时才反映到屏上
- `camera_screen.dart:318-321` 信息带只在 `sensors`/`store` notify 时重建;GPS 停止推送后没有任何 notify,是**罗盘事件**在带着它重绘。无磁力计的设备(部分平板)上,进楼后屏幕会一直显示绿色 `gps_fixed` + 门口坐标,直到拍照才发现烧的是「No GPS fix」。`snapshot()` 本身正确,只是屏幕撒谎。
- 修法:`SensorHub` 里加一个 `Timer.periodic(15s)`,`fixIsStale` 翻转时 `notifyListeners()`;或 `_liveInfoBand` 外套 `StreamBuilder(Stream.periodic)`。

### 🟡 N4 `_fixAt` 用到达时间而非 `Position.timestamp`
- `sensors.dart:148`。Android FLP 订阅瞬间会把 ≤interval(5 s)内的缓存位置立即推一次,影响极小;但取证语义上「fix 时间」应取 `p.timestamp`,顺手把它写进 `StampReading`/CSV 才是 O4 的完整形态。

### 🟡 N5 `paused` 释放相机不 `setState`,旧树里 `CameraPreview(已 dispose 的 controller)` 挂到重建完成
- `camera_screen.dart:139-141` 与 `:63-65`。resumed→新 init 完成之前(0.5–2 s)屏幕显示的是已释放纹理(黑/定格),不是转圈;快门按钮按旧 build 的 `ready=true` 仍可点,`_capture` 因 `_controller==null` 静默返回。功能安全,体验上「点了没反应」。加一句 `if (mounted) setState(() {})` 即可。

### 🟡 N6 `_doInitCamera` 里 `old.dispose()` 在 try 外
- `:65`。目前 `old != null` 实际不可达(error 页与活 controller 互斥、resumed 只在 null 时 init),属防御代码;若将来可达而 dispose 抛错,`_initCamera()` 在 `initState` 里未 await → 未处理异步错误。挪进 try 或 `.catchError` 一行。

### 🟡 N7 `deniedForever` 状态下 resumed 每次都重跑 `retryLocation`
- 无害(iOS 上 `requestPermission` 对已决定状态立即返回;Android `checkPermission` 直接 deniedForever 不弹窗),只是每次前台都 cancel/重建流;顺便说明这正是「用户去设置改完回来自动恢复」的路径,是对的。

### 类型/语义确认(无问题)
- `onPressed: SensorHub.openLocationSettings`(`Future<bool> Function()`)赋给 `VoidCallback?`:Dart 函数子类型规则允许任意返回类型赋给 `void` 返回的函数类型,编译通过,返回的 Future 被丢弃;`Geolocator.open*Settings` 失败只返回 false 不抛,不会产生未处理异步错误。`onPressed: _initCamera` 同理。
- `retryLocation` 的 `_locating`:`try/finally` 结构下 `return`/throw 都会复位;`start()` 与 resumed 的重入被它挡住;geolocator 的 `PermissionRequestInProgress` 错误不会出现。
- `locationReady` 在 retry 进行中:`_state` 不预置 pending,保持上一状态;唯一效果是「上次 ok 且未陈旧」时 retry 期间仍报 ready(流已 cancel,几百 ms 内重建),可接受。
- `snapshot()` 陈旧返回 null 坐标:与 `hasFix=false` → 水印「No GPS fix」+ snackbar「尚未获得 GPS 定位」链路一致,取证语义正确(宁缺勿错)。`heading` 不受定位状态影响也对(iOS 未授权时已由 -1 归 null)。
- 指南针 -1:`h < 0` 归 null 且只在从有到无时 notify,正确;Android 侧 `heading` 从不为负,无副作用。
- `dispose()` 与在飞 init:`!mounted` 分支 dispose 新 controller,`_fail` 有 mounted 守卫 ✓(实际 CameraScreen 在 IndexedStack 里不会 pop)。
- `shareOriginOf(State.context)`:矩形 = 整个相册页,iPad popover 会锚在页面而非按钮,能弹出、不精确;`_exportPdf` 在 `await buildPdf` 之前取矩形,长导出期间旋转屏幕会用旧矩形——都可接受,详情页已用按钮 context。
