## 总评(3 句话)

1. 楔子「干净买断 + 离线 + 不啰嗦」在代码里是兑现的:manifest 剥 INTERNET/RECORD_AUDIO/存储权限、真内购非消耗型、无引导页、拍→存→导一条直路;水印烧入像素的主链路(解码→Canvas 叠字→isolate 重编码)方向处理正确、夜间/亮背景可读。

## 🔴 阻断项

### R1. 定位/相机权限流不合规:永久拒绝无「去设置」出口;定位服务关闭后永远无法恢复;拒绝提示是 11px 橙字
- **文件:行**:`lib/tool/sensors.dart:41-66`(`_started` 单次守卫 + 服务开关检查 + 权限检查)、`lib/tool/camera_screen.dart:60-65`(相机异常直接拼进 `_cameraError`)、`camera_screen.dart:298-305`(错误文案 fontSize 11 橙色叠在预览底部)。
- **现象**:
  - 定位服务(系统开关)关闭时,`sensors.dart:50` 提前 return,**连权限都不申请**;用户去系统打开定位再回 app,`start()` 因 `_started=true`(:42)不再执行,**直到杀进程重开前永远显示「Location services are turned off」**,拍的每张都烧「No GPS fix」。
  - 定位被拒(含 iOS 首次拒绝即 `deniedForever`、Android 两次拒绝),只在信息带里出一行 11px 橙字(:302),没有任何按钮跳系统设置(全仓 0 处 `Geolocator.openAppSettings()`/`openLocationSettings()`)。
  - 相机被拒:`_cameraError` 显示原始异常串 `Camera unavailable: CameraException(CameraAccessDenied, ...)`(Android code `CameraAccessDenied`,iOS `CameraAccessDeniedWithoutPrompt`,已核对插件源码),「重试」按钮在永久拒绝下无意义,同样无「去设置」。
- **真机复现**:① 关闭系统定位 → 开 app → 打开系统定位 → 回 app → 信息带仍红、拍照仍无坐标。② 首次弹定位权限点「不允许」→ 看不到任何可点的恢复入口。③ 拒绝相机 → 看到一串英文异常。
- **修法**:
  1. `SensorHub` 加 `retryLocation()`:去掉 `_started` 对定位的守卫(罗盘可保留守卫),在 `CameraScreen.didChangeAppLifecycleState(resumed)` 里若 `locationError != null` 就重跑 `_startLocation()`;服务关闭时**仍先申请权限**再报错。
  2. `_startLocation` 里把状态拆成枚举(`serviceOff / denied / deniedForever / ok`)而不是字符串;信息带对 `serviceOff` 给按钮 `Geolocator.openLocationSettings()`,对 `deniedForever` 给 `Geolocator.openAppSettings()`,对 `denied` 给「重新申请」。按钮至少 44dp 高、放在信息带上方而不是 11px 文字。
  3. 相机:`catch (e)` 里判断 `e is CameraException && (e.code == 'CameraAccessDenied' || e.code == 'CameraAccessDeniedWithoutPrompt' || e.code == 'cameraPermission')` → 显示人话「未授予相机权限」+「去设置」按钮(可用 `Geolocator.openAppSettings()` 同一入口,免加 permission_handler)。

### R2. 首次启动(以及任何权限弹窗/通知栏下拉)会触发相机**并发双重初始化**,结果随机:黑预览 / 错误页 / 泄漏一路相机会话
- **文件:行**:`lib/tool/camera_screen.dart:51-58`(`_controller = controller` 在 `await controller.initialize()` 之前赋值)、`:69-85`(`inactive` 时只 dispose 已初始化的;`resumed` 时只要「没有已初始化的 controller」就再调 `_initCamera()`)。
- **机理**:`initialize()` 内部会弹相机权限对话框(camerax `CameraPermissionsManager` / avfoundation `CameraPermissionManager`)。对话框一出,Flutter 收到 `inactive`(此时 `isInitialized=false`,不 dispose),用户点允许后收到 `resumed`,而第一次 `initialize()` 的 future 往往还没落定 → `:81` 判断为真 → **再起一个 `_initCamera()`**。两个 `CameraController` 同时 `initialize`:camerax 侧 `createCameraWithSettings` 会 `unbindAll()`(插件 `android_camera_camerax.dart:411`),avfoundation 侧 `createCamera` 会 `camera?.close()`(`CameraPlugin.swift:267`)——**谁后绑谁活**,而 `_controller` 固定指向第二个。若第一个后绑,`_controller` 指向的是已被解绑的僵尸 → 预览黑/`takePicture` 抛「camera not bound」;若第一个 `initialize` 抛错,`:62` 会把 `_cameraError` 写成错误页,盖住其实正常的第二个。同一路径也被**定位权限弹窗**(与相机同时弹,`fieldstamp_tool.dart:206` 与 `camera_screen.dart:34` 同帧触发)、下拉通知栏、iOS 控制中心触发。
- **真机复现**:全新安装 → 首启弹相机权限 → 允许 → 观察预览是否黑/是否出现「Camera unavailable」;多试 3–5 次(竞态,不是每次都中)。或:预览转圈期间快速下拉再收起通知栏。
- **修法**:
  1. `_initCamera` 加在飞守卫:`Future<void>? _initFuture; if (_initFuture != null) return _initFuture;` 结束后置空;`resumed` 时若在飞就 `await` 它而不是新起。
  2. 用代次号:`final gen = ++_initGen;` `initialize()` 完成后 `if (gen != _initGen) { controller.dispose(); return; }`,确保被替换的 controller 一定被 dispose。
  3. `inactive` 分支对「正在初始化」的 controller 也要处理:标记 `_disposeWhenReady=true`,初始化完成后立刻 dispose。
  4. 权限弹窗不应触发相机释放:只在 `paused`(真正后台)释放、`resumed` 重建,`inactive` 不动(camera 官方示例即如此)。这一条同时消掉「在相册页开分享面板 → 相机 dispose/重建一轮」的无谓开销。

### R3. iPad 上所有分享/导出全部失败(share_plus 要求 `sharePositionOrigin`),其中两条路径是**未捕获异常**
- **文件:行**:`lib/tool/export.dart:131-132`(`shareBytes`)、`:144`(`sharePhotos`),两处 `ShareParams` 均未传 `sharePositionOrigin`;调用方 `gallery_screen.dart:228-237`(`_shareImages`,无 try/catch)、`gallery_screen.dart:395-398`(详情页分享按钮,fire-and-forget);工程 `ios/Runner.xcodeproj/project.pbxproj:367,493` `TARGETED_DEVICE_FAMILY = "1,2"`(iPad 在售)。
- **机理**(已核对 `share_plus-11.1.0/ios/.../FPPSharePlusPlugin.m:462-478`):有 popoverPresentationController(iPad)且 origin 为空 → 插件直接 `result(FlutterError "sharePositionOrigin: argument must be set ...")`,**面板根本不出现**。PDF/CSV 路径被 catch 后显示 `PDF export failed: PlatformException(error, sharePositionOrigin ...)`;分享图片路径未 catch → Dart 未处理异常,按钮无任何反应。
- **真机复现**:iPad TestFlight → 相册多选 → 分享图片:无反应;→ PDF:红 snackbar 一串英文。
- **修法**:`shareBytes`/`sharePhotos` 增加 `Rect? origin` 参数,调用处用 `final box = context.findRenderObject() as RenderBox?; origin = box!.localToGlobal(Offset.zero) & box.size;` 传入 `ShareParams(sharePositionOrigin: origin)`;`_shareImages` 与详情页分享补 try/catch + snackbar。

### R4. iOS:分享面板里点「Save Image」会**闪退**——Info.plist 缺 `NSPhotoLibraryAddUsageDescription`
- **文件:行**:`ios/Runner/Info.plist:5-10`(仅有 NSCamera / NSLocationWhenInUse)。
- **机理**:UIActivityViewController 的「存储图像」(UIActivityTypeSaveToCameraRoll)在**宿主 app 进程内**写相册,iOS 11+ 要求宿主 app 声明 `NSPhotoLibraryAddUsageDescription`,否则系统以隐私违规直接终止进程。本 app 唯一的「把照片拿出去」路径就是分享面板,而 iOS 用户最自然的动作就是「Save Image」。
- **真机复现**:iPhone TestFlight → 详情页 → 分享 → Save Image → app 闪退(Console 报 `This app has crashed because it attempted to access privacy-sensitive data without a usage description`)。
- **修法**:Info.plist 加 `NSPhotoLibraryAddUsageDescription`(文案:"FieldStamp saves stamped photos to your Photos library only when you choose Save Image in the share sheet."),并在 PLAN「真机验收清单」补一条「分享 → Save Image 不闪退」。

## 🟠 重要项

### O1. iOS 出片只有 1920×1080(2MP),Android 出 3840×2160——同一款「取证相机」两端画质差 4 倍,且都不是传感器全幅
- **文件:行**:`lib/tool/camera_screen.dart:53` `ResolutionPreset.veryHigh`。
- **依据**:`camera_avfoundation-0.9.23+2/.../DefaultCamera.swift:301-305`,`.veryHigh` 映射为 `AVCaptureSessionPreset.hd1920x1080`(4K 是 `.ultraHigh`);camerax 侧 `veryHigh` 绑定 3840×2160(`android_camera_camerax.dart:1566-1570`)。avfoundation 虽 `isHighResolutionPhotoEnabled=true`(:695),但 1080p 视频格式的高分辨率静态尺寸多数设备仍是 1920×1080。
- **用户看到**:iPhone 拍的取证照放大后糊,导出的 PDF 更糊;而 16:9 也把 4:3 传感器上下裁掉了。
- **修法**:iOS 用 `ResolutionPreset.ultraHigh`(4K),或两端统一用 `ResolutionPreset.max`(iOS 走 `.photo` 全幅 4:3 12MP,Android 走 highestAvailable)。注意 `max` 时 `picture.toImage(w,h)`(`watermark.dart:101`)要面对 4032×3024,老 GPU 4096 纹理上限刚好够;>4096 的机型(部分 48MP 直出)需先按长边缩到 4096。建议 `Platform.isIOS ? ultraHigh : veryHigh` 作为最小改动。

### O2. 方位角语义两端不一致且不标注:Android = 磁北、iOS = 真北;iOS 定位未授权时方位被烧成「359° N」;iOS 竖持手机用了「机顶朝向」而非「镜头朝向」
- **文件:行**:`lib/tool/sensors.dart:99` `_heading = e.heading;`;`lib/tool/geo_format.dart:38-43`。
- **依据**:
  - Android(`FlutterCompassPlugin.java:72,178,210-215`):`TYPE_ROTATION_VECTOR` → `getOrientation` 方位角,**相对磁北**,无磁偏角修正;插件按 pitch 判断竖持并 remap,竖持时给的是镜头朝向(正确)。
  - iOS(`SwiftFlutterCompassPlugin.swift:44-89`):`heading` = `trueHeading`(**真北**)按状态栏方向 ±90°;`headingForCameraMode` 才是「机背(镜头)朝向」。本 app 用的是 `heading`。`trueHeading` 在定位未授权/关闭时为 **-1**,插件不过滤(只过滤 `headingAccuracy<=0`),app 的 `formatHeading(-1)` → `((-1 % 360)+360)%360 = 359` → 烧成「359° N」,是错值不是缺值。
  - 美区磁偏角:缅因 −16° … 华盛顿州 +16°,对勘测/保险定损是实质误差;两端拍同一方向,水印差最多 30°。
- **修法**:
  1. iOS 用 `Platform.isIOS ? e.headingForCameraMode ?? e.heading : e.heading`(Android 侧 `headingForCameraMode` 恒为 0.0——插件 `v[1]` 从不赋值——所以必须按平台分支)。
  2. `heading < 0` 视为 null。
  3. 统一北向:要么 Android 加磁偏角(WMM 纯本地算法,pub 有 `geomag`/`wmm` 类包,输入 lat/lon/alt/日期),要么水印和 CSV 表头明确标注 `Bearing 123° NE (mag)` / `(true)`;CSV 列名改 `heading_deg_true`/`heading_deg_mag`。
  4. 罗盘精度(`e.accuracy`,Android 15/30/45°,iOS `headingAccuracy`)现在完全没用——精度差(≥45°)时应在信息带提示「8 字校准」,而不是把提示藏在设置页说明里。

### O3. 海拔语义两端不一致、无效值被烧成「Alt 0 m」
- **文件:行**:`lib/tool/sensors.dart:76` `_alt = p.altitude;`;`geo_format.dart:28-34`。
- **依据**:geolocator `Position.altitude` 非空 double,原生没给时 `_toDouble(null)` → **0.0**(`position.dart:171`)。Android `LocationMapper.java:22` 用 `getAltitude()` = **WGS84 椭球高**(仅 Android 14+ 且 provider 提供 MSL 时才覆盖为海拔,:48-56);iOS 用 `CLLocation.altitude` = **平均海平面高**,`verticalAccuracy<=0` 时不下发 → 0.0。美国本土大地水准面差 −20 … −40 m:同一地点 iPhone 烧「Alt 12 m」,Android 13 烧「Alt −20 m」;室内/网络定位时两端都烧「Alt 0 m」。
- **修法**:读 `p.altitudeAccuracy`,`<= 0` 视海拔为 null(显示「—」);水印/CSV 标注基准(`Alt 12 m MSL` / `Alt −20 m WGS84`),Android <14 或无 MSL 时显式标 `(ellipsoid)`;精度 >30 m 时不烧海拔。PLAN 里「海拔来自 GPS,仅供参考」这句应该出现在水印说明页**和**信息带 tooltip 里。

### O4. GPS 陈旧值/信号丢失后仍以「已定位」烧入当前时间——冷启动与室内是取证相机的两个主场景,现状都不对
- **文件:行**:`lib/tool/sensors.dart:32-39`(`snapshot()` 取最后一次值,不看新鲜度)、`models.dart:23`(`hasFix` = lat/lon 非空,**一旦定过位就永远绿**)、`camera_screen.dart:99-111`。
- **用户看到**:① 户外定位后走进楼内拍 10 张,信息带一直绿色 `gps_fixed`,坐标是门口的、时间是现在的,精度显示的也是几分钟前的 ±5 m;② 冷启动前 30–60 s 拍的照片被永久烧上「No GPS fix」,没有「等一下」的选项。
- **修法**:保存 `Position.timestamp`(GPS 时间,Android 来自 provider,iOS 来自设备钟);`snapshot()` 附 `fixAgeSec`;>30 s 信息带转橙并标「stale」,>120 s 视为无定位;快门在「无定位或精度 >50 m」时先弹确认(「等待定位 / 仍然拍」),Pro 可设阈值;把 `fix_age_s`/`gps_time` 写进 CSV。

### O5. 「取证」承诺没有任何完整性支撑:不查模拟定位、时间戳无时区、EXIF 全部丢弃
- **文件:行**:`sensors.dart:73-80`(未读 `p.isMocked`);`geo_format.dart:45-49` + `models.dart:60`(本地时间无偏移;`toIso8601String()` 对本地时间不带 `Z`/偏移);`watermark.dart:110/122-130`(image 包重编码,不带任何 EXIF);`store/listing.md:54,59,73`(en:「field-evidence camera」「evidence you can trust」「law-enforcement documentation」),`listing.md:17,36`(zh:「取证」「执法与安防取证」)。
- **用户看到**:Android 装个 mock-location app,FieldStamp 会把假坐标烧得漂漂亮亮;跨时区出差的照片「2026-09-02 14:03:07」无从判断是哪个 14:03;文件没有任何 EXIF(连拍摄设备/原始时间都没有),在对方看来反而更像被处理过的图。
- **修法(按性价比排序)**:
  1. `p.isMocked == true` → 信息带红字「MOCK LOCATION」,水印烧 `MOCK`,CSV 加 `is_mocked` 列(Android 一行代码;iOS 恒 false)。
  2. 时间戳加偏移:`2026-09-02 14:03:07 -07:00`(`t.timeZoneOffset`),存 `capturedAt` 用 `toUtc().toIso8601String()` + 单独存 offset。
  3. 商店文案把「evidence you can trust」改为「documentation you can file」,删掉「law-enforcement」(Apple 审核对执法/证据类描述也更敏感),「How stamping works」页加一句「不构成法律证据效力承诺」。
  4. v2:`native_exif` 写回 GPS/DateTimeOriginal(PLAN 已列),并对 JPEG 做 SHA-256 写进 CSV/PDF。

### O6. 元数据 JSON 非原子写、并发写、损坏即「所有照片消失」且无恢复
- **文件:行**:`lib/tool/store.dart:100-118`(`_save` 直接 `writeAsString` 覆盖同一文件,多处**不 await** 地并发调用:`:163,169,184,189,194,199,204`);`:60-98`(load 失败 `catch` 后 `finally` 直接以空库继续)。
- **用户看到**:低内存被杀/断电恰在写 `fieldstamp.json` 时 → 文件截断 → 下次打开相册空空如也,`photos/` 目录里几百张 JPEG 还在但看不到,没有任何提示。两次不同长度的 `_save` 交叠(先短后长再截断顺序错乱)也能得到尾部残留的非法 JSON。
- **修法**:写临时文件 `fieldstamp.json.tmp` → `rename` 覆盖(原子);`_save` 串行化(一个 `Future` 链或 `_saving` 标志 + 排队);load 失败时把坏文件改名保留 `fieldstamp.json.bad`,并**扫描 `photos/` 目录把孤儿 JPEG 以「无元数据」形式重新登记**(至少让用户能看见、能导出)。

### O7. 每拍一张就在 cache 目录留一份**未打水印的原图**,永不清理
- **文件:行**:`lib/tool/camera_screen.dart:100-101`(`xfile.readAsBytes()` 后未删 `xfile.path`)。
- **依据**:camerax `ImageCaptureProxyApi.java:90-93` 写 `getCacheDir()` 临时文件;avfoundation `DefaultCamera.swift:757-759` 写 `temporaryDirectory/camera/`。同样 `export.dart:128-130` 每次导出的 PDF/CSV 也留在 temp。
- **用户看到**:每张 3–8 MB 的「无水印原片」堆在缓存里(设置里显示 app 缓存几百 MB),而且与「拍摄瞬间烧入、无未打标原图」的取证叙事相悖。
- **修法**:`readAsBytes()` 后 `File(xfile.path).delete()`(try/catch);`shareBytes` 在分享完成后删临时文件或启动时清空自家 temp 子目录。

### O8. 横屏时预览变形、水印带吃掉 1/3 画面
- **文件:行**:`camera_screen.dart:201-208`(硬编码把 previewSize 宽高互换,只对竖屏成立;`Info.plist:60-72` 与 Android manifest 都允许横屏)、`watermark.dart:31-33`(字号/内边距按 **宽度** 2.6%/2.2%)。
- **用户看到**:横屏取景预览被拉扁/拉长;横屏拍 3840×2160,body 字号 100 px,四行带高约 810 px ≈ **37% 画面高度**;竖屏才是合理的 ~12%。
- **修法**:字号基准改 `min(w,h)`(或 `sqrt(w*h)`),并给带高设上限(≤ 18% h,超出则减字号/合并为两行);预览按 `MediaQuery.orientation` 决定是否交换宽高,或干脆 `SystemChrome.setPreferredOrientations([portraitUp])` 锁竖屏(现场工具锁竖屏是可接受的取舍,但要写进 PLAN)。

### O9. 相机与 GPS 在相册页/设置页持续运行(IndexedStack 常驻),iOS 常亮绿点/蓝箭头
- **文件:行**:`fieldstamp_tool.dart:212-217`(IndexedStack)、`camera_screen.dart` 无 tab 切换感知、`sensors.dart:67-71`(`best` + `distanceFilter:0` 永不停)。
- **用户看到**:在相册翻照片时状态栏相机绿点一直亮——对「隐私优先」的取证 app 是信任问题;耗电。
- **修法**:`HomeShell` 切到相册时调 `CameraScreen` 的 `pause()`(dispose controller,回到相机 tab 再 init);GPS 在非相机 tab 降到 `LocationAccuracy.low` 或暂停;导出/设置页同理。

### O10. 照片只存沙盒:Android 自动备份 25 MB 上限装不下,无「全部导出/备份」——丢手机 = 丢全部证据
- **文件:行**:`store.dart:53-56,62-63`(仅 documents 目录);全仓无「导出全部」「保存到相册」。
- **用户看到**:换机或丢机后,Android 端照片全部丢失(iCloud 备份 iOS 尚可);唯一出口是每次多选分享。
- **修法**:设置页加「备份/导出全部(zip)」(纯本地,走分享面板);或提供「同时保存到系统相册」开关(Android 用 MediaStore 不需存储权限,iOS 需 R4 的 plist key + `PHPhotoLibrary`);至少在设置页显示已用空间(照片数 × 体积)。

### O11. 免费层导出限额是死代码,导出门槛与 PLAN 不一致
- **文件:行**:`store.dart:16` `freeExportLimit = 5`;`gallery_screen.dart:242-246 / 263-267`(先 `!store.pro` 拦截,`_enforceLimit` 永不触发);`gallery_screen.dart:216-226` 的「免费版报告最多 5 张」文案永远看不到。
- **产品判断**:让免费用户导 ≤5 张 PDF 是最好的「先试后买」——用户亲眼看到报告长什么样才会付 $6.99。建议改成「免费 ≤5 张 / Pro 不限」并删掉 `_proNeeded` 分支;否则删除死代码。

## 🟡 建议项

- **Y1 DMS 秒位进位**:`geo_format.dart:24-25` `sec.toStringAsFixed(1)` 可得 `60.0` → `37°59'60.0"N`。修:先算 `secRounded = (sec*10).round()/10`,`>=60` 则进位到分/度。同理 `formatHeading` `:42` 359.6° 会显示「360° N」,先 round 再 `% 360`。
- **Y2 水印静默降级**:`watermark.dart:108` `byteData == null` 时**返回原图**,而 `camera_screen.dart:109-110` 仍提示「Saved with GPS stamp」。修:抛异常走「拍摄失败」,或返回结构体带 `stamped:false` 并在相册标记。
- **Y3 存元数据失败不反馈**:`store.dart:142` `await _save()` 内部吞异常,`saveCapture` 仍返回 photo → 用户以为存好了,重启后照片不在。修:`_save` 返回 bool,失败 snackbar「元数据未写入,存储空间可能已满」。
- **Y4 PDF/CSV 导出无进度**:`gallery_screen.dart:247-252` 只禁用按钮;50 张以上 `buildPdf`(逐张 `compute` 解码 + `doc.save()` 主线程)要十几秒,界面像死了。修:`showDialog` 进度条,`buildPdf` 接 `onProgress(i,n)`。
- **Y5 CSV 兼容**:`export.dart:32` `\n` 分行、无 UTF-8 BOM。Excel(Windows)打开含非 ASCII 备注会乱码。修:前缀 `\uFEFF`,行尾 `\r\n`。
- **Y6 CJK PDF(已知取舍)严重度评估**:只发美区,项目名/备注多为英文,**可接受**;但 emoji 与带重音字符同样掉字。若加 `google_fonts`-类 TTF 内嵌(NotoSans ~500 KB)顺手就能解;建议 v1.1 前做,不阻断上架。

- **Y9 预览非所见即所得**:`camera_screen.dart:201-207` `BoxFit.cover` 裁掉预览边缘,烧字带位置也与屏上信息带不重合。取证相机建议 `BoxFit.contain` 黑边显示完整取景框,并让屏上信息带模拟最终水印位置/字号。
- **Y10 漏 `tr()`/英文兜底**:`store.dart:37,41,89`(`'Default'`/`'Default project'` 在 zh 界面直接显示英文);`geo_format.dart:7` `'No GPS fix'` 同时用于屏上、详情卡、PDF——烧入像素固定英文是对的,屏上/详情卡应 `tr()`。`Branding.appNameZh`(`branding.dart:12`)与 `values-zh/strings.xml` 都是 `FieldStamp`,而隐私文案用「现场印记」——三处统一一下。

## 五维度逐项结论

### 1. 产品设计
- **楔子兑现**:✅ 买断(`purchase.dart` 非消耗型 + 恢复购买)、✅ 离线(manifest `tools:node="remove"` 剥 INTERNET,隐私政策措辞与之一致)、✅ 不啰嗦(无 onboarding,三步到快门)。
- **「取证」过度承诺**:⚠️ 见 O5。代码提供的是「带信息的照片 + 本地台账」,商店文案说的是「evidence you can trust」「law-enforcement」。差距不在功能多少,而在**没有任何一项反伪造机制**(模拟定位、时钟、EXIF、哈希)。建议文案降级 + 做 O5 的 1、2 两项(半天工作量),让「取证」至少有「标注了来源与局限」的诚实度。
- **免费层可用性**:✅ 可无限拍、看、分享原图;角标小(0.8 倍字号、右上角)不影响使用。❌ 导出全部锁 Pro,`freeExportLimit=5` 死代码(O11)——免费用户从未见过 PDF 长什么样,转化缺乏「体验钩子」。
- **Pro 门合理性**:多项目/PDF/CSV/去角标 = 合理;DMS = 不合理(Y8)。$6.99 对标 Timestamp Camera Pro $4.99、Solocator $0.99 偏高,只有当 PDF 报告质量明显高于竞品时才站得住——目前 PDF 是「一图一表」的最简形态(`export.dart:49-100`),没有封面/汇总页/地图缩略。建议要么加汇总页(项目名、日期范围、照片数、坐标范围)撑住价格,要么降到 $4.99。

### 2. 代码实现(装到真机上什么会坏)
- **权限流**:🔴 R1。相机权限由插件在 `initialize()` 内申请,拒绝后只有原始异常串;定位有服务开关/权限两级判断但无恢复、无出口。**定位关闭(非拒绝)**:显示「Location services are turned off」后永久停摆(R1)。**GPS 冷启动无信号**:直接拍,烧「No GPS fix」,snackbar 提示一次,相册角标 `gps_off`(`gallery_screen.dart:171-177`)——诚实但没给「等」的选项(O4)。
- **相机生命周期**:切后台/来电 → `inactive` 释放、`resumed` 重建,基本对;但**权限弹窗与初始化期的 `inactive→resumed` 会双重初始化**(🔴 R2)。旋转:Android `configChanges` 含 orientation,不重建 Activity;预览宽高硬编码只对竖屏对(O8)。低内存被杀:状态在 JSON,重启可恢复;但 JSON 非原子写(O6)。
- **水印合成正确性**:✅ `decodeImageFromList` 应用 EXIF 方向后再叠字,`image` 包重编码不写 EXIF → 输出物理方向正确、任何看图软件一致;✅ 字号随宽度自适应(但横屏过大,O8);✅ 70% 黑底白字在夜景/亮背景都可读;✅ `TextPainter` 不受系统字体缩放影响;✅ 长项目名 2 行省略。⚠️ `byteData==null` 静默返回原图(Y2)。内存峰值:3840×2160 RGBA 33 MB × (src 纹理 + composited 纹理 + rawRgba + isolate 拷贝) ≈ 130 MB,主流机可承受;若改 `max` 预设需注意(O1)。
- **后台 isolate 编码失败反馈**:`compute` 抛错 → `_capture` catch → 「拍摄失败:…」snackbar,✅;但 camera 临时原图残留(O7)。
- **存储**:磁盘满 → `writeAsBytes` 抛 → 返回 null → 「照片保存失败」✅;元数据写失败静默(Y3);删除确实 `file.delete()` ✅;删项目级联删照片 ✅(`store.dart:172-180`);无体积管理(Y12)。
- **PDF/CSV 导出**:逐张 `compute` 下采样到 1200 px 控体积 ✅;`doc.save()` 主线程、无进度(Y4);失败有 snackbar ✅;iPad 失败(🔴 R3);iOS Save Image 闪退(🔴 R4)。
- **Pro 门绕过**:`pro` 存明文 JSON(`store.dart:70,106`),需 root/越狱才能改,$6.99 产品可接受;无服务端校验属设计取舍。Android 自动备份会把 `pro:true` 随 JSON 迁到新机(合法用户受益)。
- **内购反馈**:`PurchaseNotices` 仅在设置页(Y7);`pendingCompletePurchase` 有处理 ✅;`restore` 有 ✅;价格走商店 ✅(fallback `$6.99` 仅美区无害)。
- **iOS 差异汇总**:R3(iPad 分享)、R4(Save Image 闪退)、O1(1080p)、O2(真北/`-1`/机顶朝向)、O3(MSL)、R1(首拒即 deniedForever)。`compute` 在 iOS 无特殊限制 ✅。`share_plus` 分享 JPEG 走 temp 副本 ✅。

### 3. 逻辑自洽
- **方位角**:来源 = flutter_compass;Android 磁北(rotation vector)、iOS 真北(`trueHeading`);**无磁偏角处理、无标注**;Android 竖持已由插件 remap 成镜头朝向,iOS 用的是机顶朝向字段;iOS 无定位授权时为 −1 被格式化成 359°(O2)。
- **海拔**:GPS 高程,Android 椭球高 / iOS 海拔,无精度标注,无效值 0(O3);无气压融合(可接受,但要标注)。
- **坐标格式**:十进制 6 位 ✅;DMS 半球/补零 ✅,秒位 60.0 进位缺(Y1);测试覆盖了半球与基本格式,未覆盖进位边界。
- **时间戳**:本地时间、无时区,存储 ISO 无偏移(O5-2);未用 `Position.timestamp` 做时钟交叉校验。
- **数据模型**:`StampPhoto.projectId` 可变但无迁移 UI(设计留白);删项目级联 ✅;`currentProjectId` 失效兜底 ✅(`store.dart:92-94`);`_newId` 用微秒 + 序号,同进程唯一 ✅。`hasFix` 只看经纬度,不看新鲜度/精度(O4)。
- **测试覆盖**:`geo_format_test.dart` 覆盖格式函数与 JSON 往返(116 行,质量尚可);`widget_test.dart` 只验启动。**水印、store、sensors、export、Pro 门零测试**(见末节)。

### 4. 用户体验
- **主路径**:打开 → 两个权限弹窗同时叠出(Y13)→ 取景(预览被 AppBar+项目条+快门条+NavBar 四层夹住,可见画面偏小)→ 拍(72 px 绿钮,有转圈反馈 ✅)→ snackbar 2 秒 → 切相册 tab 才能看到成片(**拍完没有缩略图/最近一张入口**,用户不知道烧成什么样;建议快门旁放最近一张小图,点开即详情)→ 长按/「选择」多选 → 导出。整体顺,断点在「拍完看不到结果」和「导出要去设置买」。
- **实时值与成片一致性**:`snapshot()` 在点击瞬间取值(`camera_screen.dart:99`),屏上信息带与烧入值同源 ✅;但屏上带用 `tr()` 中文标签、烧入固定英文——中文用户看到屏上「海拔」成片却是「Alt」,应在说明页讲清「水印固定英文以便跨语言归档」(现有说明页未提)。
- **错误反馈**:相机错误有重试 ✅;定位错误 11px 橙字无操作(R1);导出失败有 snackbar ✅(但内容是异常串);分享图片失败无反馈(R3)。
- **文案**:zh/en 都通顺,术语一致(项目/工单、台账、巡检);漏 `tr()` 见 Y10;`'${n} project(s)'` 可改 Flutter `Intl.plural`,小事。
- **无障碍**:快门是 `GestureDetector` 裸容器(`camera_screen.dart:319`),无 `Semantics(button:true,label:)`,TalkBack/VoiceOver 读不出「拍照」——取证类 B 端用户里有戴手套/强光场景,至少补语义标签与 48 dp 最小触区(现 72 ✅)。

## 缺失的测试清单

1. **水印合成 golden/尺寸测试**(`watermark.dart`):给 1080×1920、1920×1080、4032×3024 三种输入,断言带高占比 ≤ 18%、文字不溢出、`appTag==null` 时无角标;`byteData==null` 路径必须抛错而非返回原图。
2. **DMS 进位边界**(`geo_format.dart`):`_dms(37.9999999)` 不得出现 `60.0"`;`formatHeading(359.6)` 不得出现 `360°`;`formatHeading(-1)` 应视为无效(配合 O2 修法)。
3. **Store 持久化**:并发 `_save` 后文件必须是合法 JSON;写入中断(用假 FileSystem 或写半截)后 `load` 不得丢照片记录;`deleteProject` 级联删除文件与记录;`currentProjectId` 指向已删项目时的兜底。
4. **SensorHub 状态机**(用 mock Geolocator/compass):serviceOff → 用户打开 → `retry` 后进入 ok;`denied` → `deniedForever` 文案与出口;`isMocked=true` 传播到 `StampReading`;`altitudeAccuracy<=0` 时 `altitude==null`;iOS `heading=-1` 归 null;fix 陈旧 >N 秒时 `hasFix=false`。
5. **CSV**:BOM/CRLF、含逗号/引号/换行备注的转义、时区列、`is_mocked` 列。
6. **PDF**:50 张导出内存不超阈(至少跑通不 OOM)、含非 Latin-1 备注不抛错、`(image unavailable)` 分支。
7. **Pro 门**:`pro=false` 时 `_exportPdf`/`_exportCsv`/新建项目/DMS 均被拦且给出可操作的 snackbar;`pro=true` 全放行;`freeExportLimit` 若保留必须有测试证明它触发过。
8. **Widget 测试**:`CameraScreen` 在 `availableCameras` 抛 `CameraException(CameraAccessDenied)` 时显示「去设置」按钮;`resumed` 时若 `_initCamera` 在飞不得二次调用(用计数 mock 断言 `availableCameras` 只被调一次)。
9. **iPad 分享**:`shareBytes`/`sharePhotos` 必须带非空 `sharePositionOrigin`(可用 fake `SharePlatform` 断言参数)。
10. **i18n 扫描**:脚本级检查 lib/ 下用户可见字面量是否都在 `tr()` 内(当前至少 3 处漏,Y10)。
