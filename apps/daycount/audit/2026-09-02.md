# daycount 审计报告 2026-09-02

> 范围:`D:\toolapp\apps\daycount` 全部业务代码(lib/tool 6 文件、lib/core 4 文件、main.dart、test 2 文件)、Android 原生(Kotlin 2 文件 + manifest + 全部 res)、iOS Info.plist / AppDelegate、pubspec、PLAN.md、store/listing.md。只读未改。核对了 `home_widget 0.7.0+1` 与 `in_app_purchase_android 0.5.2` 的插件源码(D:\dev\pub-cache)以确认桥接行为,不靠猜。已知的 iOS 问题(WidgetKit 缺失等)按要求不重复。

## 总评

1. **Android 版现在不能发**:招牌功能「桌面小组件」的天数是 Flutter 端在保存时烤死的字符串,原生 Provider 只是把字符串贴出来,**跨零点后小组件继续显示昨天的天数**(包括「就是今天🎉」会在第二天继续庆祝),直到用户冷启动 App。这直接违反 PIPELINE G2「小组件=provider 端实时计算,非 Flutter 端烤死数值」的架构评审要求,也是 PLAN 验收清单第 9 条「跨零点」在小组件上必挂的原因。
2. **最大的一个问题**就是上面这条;其次是 App 内的日期也只在 build 时算一次——从后台切回来不重算、不推小组件,一个从不冷启动的用户小组件会一直停在几天前。
3. **最值得夸**:日期数学层(`models.dart`)干净、UTC 整日差、闰年 2/29 兜底、三态判定和排序规则全部正确且无 off-by-one;R8 keep 规则、`FLAG_IMMUTABLE`、`tools:node="remove"` 剥 INTERNET 这些「装机会炸」的坑都已避开;内购接线(购买/恢复/pending/error/completePurchase)是完整的。

## 🔴 阻断项(不修不能上架)

### R1. 小组件天数是烤死的字符串,跨零点不更新
- **文件**:`lib/tool/widget_bridge.dart:17-37`(`sorted.first` 与 `s.absDays` 在推送时算好,以 `dc_num`/`dc_label` 字符串写入 prefs);`android/.../CountdownWidgetProvider.kt:21-35`(只 `getString` 后 `setTextViewText`,零计算);`android/.../xml/countdown_widget_info.xml:7`(`updatePeriodMillis=86400000` 只会让系统在任意相位再贴一遍同一个字符串);`AndroidManifest.xml:37-46`(receiver 只收 `APPWIDGET_UPDATE`,没有零点闹钟、没有 `TIME_SET`/`TIMEZONE_CHANGED`)。
- **现象**:小组件的数字只在 App 的 `load()`/`_save()`(store.dart:54、60)或设置页「刷新小组件」时变化。
- **真机复现**:① 加一条「明天」,置顶,添加小组件→显示「还有 1 天」;② 等过零点(或系统日期 +1)→ 小组件仍是「还有 1 天」,App 内已是「就是今天」;③ 再过一天→小组件仍「还有 1 天」,而 App 内已进入「已过去 1 天」。用「就是今天」的事件复现更直观:小组件会连着几天🎉。
- **修法**(按 G2 的口径,provider 端算):
  1. `WidgetBridge.push` 改为写**原始数据**而非结果:把排序后前 N 条(或全部)的 `title/emoji/yyyy-mm-dd/yearly/pinned` 序列化成 JSON 字符串存 `dc_events`,并存一份 `dc_lang`(zh/en)供原生选文案;
  2. `CountdownWidgetProvider.onUpdate` 用 `java.time.LocalDate.now()` 在 Kotlin 里复刻 `models.dart` 的 `nextYearlyOccurrence`(`withDayOfMonth(min(day, lengthOfMonth))`)+ `ChronoUnit.DAYS.between` + 同一排序规则,选出 featured 再渲染;文案用 `res/values{,-zh}/strings.xml` 而不是 Flutter 传字符串;
  3. 在 `onUpdate` 末尾用 `AlarmManager.setAndAllowWhileIdle(RTC, 下一个本地零点+1min, PendingIntent.getBroadcast(显式指向本 Provider, ACTION_APPWIDGET_UPDATE))`,`onEnabled` 时也排,`onDisabled` 时取消;另在 manifest 的 receiver intent-filter 里加 `android.intent.action.TIME_SET` 与 `android.intent.action.TIMEZONE_CHANGED`(这两条在 Android 8+ 隐式广播豁免名单内),`onReceive` 收到就转 `onUpdate`;
  4. 给 `models.dart` 的排序/日期逻辑和 Kotlin 复刻各写一组相同用例(见「缺失的测试清单」),防两端分叉。

### R2. App 从后台切回不重算日期、不推小组件
- **文件**:`lib/tool/daycount_tool.dart:88-168`(`_HomeBodyState` 没有 `WidgetsBindingObserver`,没有零点 Timer);`:149`、`:209`(`DateTime.now()` 只在 build 时取);`lib/tool/store.dart:54`(`WidgetBridge.push` 只在 `load()` 与 `_save()` 触发,而 `load()` 只在进程创建时跑一次)。
- **现象**:Android 上 App 常驻在最近任务里(尤其 8GB+ 手机),用户每天从最近任务切回来,**列表和小组件都停在上次改动那天**;这和 R1 叠加后,「次日回来」主路径整体失效。
- **真机复现**:23:58 打开 App 看列表→按 Home 键→00:02 从最近任务切回→数字没变;小组件也没变。
- **修法**:`_HomeBodyState` `with WidgetsBindingObserver`,`didChangeAppLifecycleState(resumed)` 时 `setState(){}` + `WidgetBridge.push(store.events)`;前台期间起一个到下一个本地零点的 `Timer`(resume 时重排、pause 时取消)到点 `setState` + push。R1 修完后 push 变成「写原始数据」,这里仍要保留以覆盖 R1 闹钟被 ROM 杀掉的情形。

## 🟠 重要项(上架前应修)

### O1. 从首页触发的购买,所有失败/不可用提示都是静默的
- **文件**:`lib/tool/daycount_tool.dart:20-22`(`PurchaseNotices` 只挂在设置页的 `buildSettingsItems`)、`:126-134`(免费上限弹窗直接 `PurchaseService.instance.buyPro()`);`lib/core/purchase.dart:105-119`(`_unavailableMsg`、「商品暂不可用」只写进 `notice`,没人监听就没人显示)。
- **现象**:侧载/无 Play 的机器、或商品还没在 Console 上架时,用户在首页点「解锁 Pro」→**什么都不发生**,没有任何提示(违反 PIPELINE「禁止静默失败」)。购买成功时首页也没有「Pro 已解锁」反馈,只是列表能继续加了;那条 notice 会滞留到下次打开设置页才莫名弹出来。
- **复现**:用 CI 出的 APK 直接 adb install(非 Play 安装)→加 5 条→第 6 条→点「解锁 Pro」→无反应。
- **修法**:把 `const PurchaseNotices()` 也放进 `_HomeBody` 的 `Scaffold` body(例如包在 `Stack` 里),或者挪到 `main.dart` `_HomeScaffold` 的 body;`PurchaseNotices.initState` 里补一次 `_show()` 消费已滞留的 notice。

### O2. 「恢复购买」查不到订单时零反馈
- **文件**:`lib/core/purchase.dart:132-143` + `:79-102`;插件 `in_app_purchase_android_platform.dart:210-235` 在没有历史订单时把空列表发到流上,`_handlePurchases([])` 循环体不执行。
- **现象**:PLAN 验收第 8 条「卸载重装→恢复购买」若因换了 Google 账号/未购买而查不到,用户点了没有任何回应,会以为按钮坏了。
- **修法**:`restore()` 里记一个 `_restoreInFlight=true`,`_handlePurchases` 收到列表时若 `_restoreInFlight && 无 restored 项` → `notice.value = tr(zh:'未找到已购项目', en:'No previous purchase found')`;再加 8s 超时兜底。

### O3. 详情页天数 ≥5 位被裁掉
- **文件**:`lib/tool/event_detail.dart:140-170`(`SizedBox 172×172` → `Stack`(默认 `clipBehavior: Clip.hardEdge`)→ `Text` 76sp w800 无 `FittedBox`)。
- **现象**:「出生至今」「在一起」这类累计项很容易过 10,000 天(27.4 年),76sp 粗体 5 位数宽约 210px > 172px,**最后一位被硬边裁掉**,读数直接错。列表页徽章(daycount_tool.dart:329-338)没有宽度上限所以没事。
- **复现**:加一条 1995-01-01 的非重复事件→进详情→数字右侧被切。
- **修法**:数字外包 `FittedBox(fit: BoxFit.scaleDown)`,或把 `SizedBox` 宽度改成 `double.infinity` 只固定高度。

### O4. 持久化非原子 + 损坏即静默清空并被下一次保存覆盖
- **文件**:`lib/tool/store.dart:58-73`(`writeAsString` 直接截断重写,无临时文件+rename);`:38-56`(解析失败 → catch → `events` 空,`loaded=true`,UI 显示空列表);之后任何 `add/togglePin` → `_save()` 用空列表**覆盖**原文件。另外 `_save` fire-and-forget、无队列,快速连点置顶会有两次并发 `writeAsString` 同一路径。
- **现象**:写到一半被杀(低电、ROM 清后台)→ 下次打开全部日子「消失」,用户只要再加一条,旧数据就永久没了。PLAN 本身把「更新丢数据」列为竞品首位差评,这是自己踩同一个坑。
- **复现**:难以稳定复现,但可用 `adb shell` 往 `files/daycount.json` 写半截 JSON 后重开验证「空列表→加一条→覆盖」。
- **修法**:写 `daycount.json.tmp` + `flush` 后 `rename`;`load()` 解析失败时把坏文件改名为 `daycount.corrupt-<ts>.json` 保留并弹一条可见提示,而不是当作空库;`_save` 串行化(保存一个 `Future` 链)。

### O5. `PurchaseService.init` 与 `store.load()` 竞态,可能把 Pro 或事件写丢
- **文件**:`lib/main.dart:17`(init 不等 load)+ `lib/tool/store.dart:42-47`(`load` 用文件值覆盖内存 `pro`)+ `:116-119`(`unlockPro` 立即 `_save()`,而 `_save` 的 `jsonEncode` 在 `await _file()` 之后取 `events` 快照)。
- **现象**:Play Billing 连接后会把已购订单重新推到 stream。若这条 `restored` 早于 `load()` 读完:`unlockPro()` 把 `{pro:true, events:[]}` 写盘,随后 `load()` 用旧文件内容把 `pro` 改回 false → 用户看到「已付费却不是 Pro」,直到手动恢复;或磁盘上暂时只剩空列表。概率低但后果是数据/权益丢失。
- **修法**:`unlockPro()` 里 `if (!loaded) { _pendingPro = true; return; }`,`load()` 的 `finally` 里应用 `_pendingPro`;或让 `main()` `await tool.store.load()` 再 `init`。

### O6. 深色模式下卡片没有可辨的面
- **文件**:`lib/tool/daycount_tool.dart:224`(`Card(color: color.withValues(alpha: 0.06))` 覆盖了主题 `surfaceContainerHigh`,elevation 0,无边框)。
- **现象**:深色下 6% 的珊瑚色叠在近黑背景上几乎不可见,卡片与背景融为一体,只剩 emoji 方块和右侧徽章漂在黑底上;浅色下也只是极淡的粉。PLAN 验收第 12 条「深浅色…没有撞色」会以「看不出卡片边界」的形式挂掉。
- **修法**:`color: Color.alphaBlend(color.withValues(alpha: 0.10), scheme.surfaceContainerHigh)`,深浅都保留 tonal 面。

### O7. iOS:小组件相关入口与文案在 iOS 上照样出现并「成功」
- **文件**:`lib/tool/daycount_tool.dart:28-40`(设置页「刷新桌面小组件」→ iOS 上 `HomeWidget.saveWidgetData` 因未 `setAppGroupId` 直接返回 `notInitializedError`(插件源 `SwiftHomeWidgetPlugin.swift:66-68`),被 try/catch 吞掉,然后**仍弹「已刷新小组件」**);`:189-190` 空状态「并放上桌面小组件」;`lib/tool/event_edit.dart:142-143` 置顶说明「并显示在小组件」;`lib/core/branding.dart:24` 关于页。

### O8. iOS:显示名没有中文本地化
- **文件**:`ios/Runner/Info.plist:9-10`(`CFBundleDisplayName=DayCount` 写死,无 `zh-Hans.lproj/InfoPlist.strings`,也无 `CFBundleLocalizations`);对照 Android `values-zh/strings.xml:4` 已是「倒数日」。

## 🟡 建议项(v1.1)

### Y1. 小组件里的硬编码中文与不合语言的兜底
- `CountdownWidgetProvider.kt:22`(`?: "倒数日"`)、`res/layout/countdown_widget.xml:21`(`android:text="倒数日"`)。英文机器装完 App 还没打开就先添加小组件 → 显示中文。改 `@string/app_name` / `context.getString(R.string.app_name)`。R1 修完后 label 文案也应走 strings.xml。

### Y2. 小组件数字无 `maxLines`,5 位数会折行
- `countdown_widget.xml:32-40`。40sp 粗体 5 位约 112dp,2×2 格减 28dp 内边距后约 110-130dp,边缘机型会拆成「1000 / 0」两行。加 `android:maxLines="1"` + `android:autoSizeTextType="uniform"`(XML 属性在 RemoteViews 里有效)。

### Y3. 小组件小字对比度不足、外观未跟随事件色
- `countdown_widget.xml:27-30、45-49`(11sp 白字)叠 `countdown_widget_bg.xml:4`(#E7625F)对比度 ≈3.3:1,低于小字 4.5:1;`bg` 固定珊瑚色,不用事件自己的主题色(App 内详情页却用);`corners 22dp` 不取 `?android:attr/system_app_widget_background_radius`;`countdown_widget_info.xml:9` `previewImage` 用的是启动图标,选件器里看到的是被拉伸的 App 图标而非小组件样子,也没有 `android:description`。建议:label/date 提到 12sp 并用不透明白;背景用 `setInt(R.id.root, "setBackgroundColor", eventColor)` 或 `setColorFilter`;加 `android:previewLayout="@layout/countdown_widget"`(API 31)+ `description`。

### Y4. 「添加到桌面」缺入口
- 楔子①「小组件是主体验」,但 App 内没有任何把它加到桌面的路径,空状态只说「放上桌面小组件」不给按钮。插件已带 `requestPinWidget`(`HomeWidgetPlugin.kt:158-183`,Android 8+)。建议空状态与设置页各加一个「添加到桌面」按钮,`isRequestPinWidgetSupported` 为 false 时降级成一段「长按桌面→小组件→倒数日」说明。

### Y5. 小组件文案「还有 · 天」
- `widget_bridge.dart:30-31`。`·` 是给数字占的位,可数字在另一行,读起来是「还有 · 天 / 12 / 2026-10-01」。改成 label「还有」+ 数字行 + 单位「天」单独一个 TextView,或直接合成「还有 12 天」。英文 `days to go / days ago` 没问题;但 App 内徽章的英文 `past`(daycount_tool.dart:218、event_detail.dart:95)读作「past 10 days(过去十天这段时间)」,改 `ago`/`since` 更准。

### Y6. 「每年重复」和「累计」互斥,做不了「恋爱第 N 天 + 周年倒数」
- `models.dart:89-90`:yearly 永远前滚,不会出现负数,PLAN/关键词里的「恋爱天数」只能靠不勾重复来实现,而周年就要再加一条。竞品(倒数日/时间规划局)通常同时显示「已 N 天 · 距周年 M 天」。v1.1 可在 yearly 详情页多给一行「自首次起已 N 天」(`daysBetween(e.date, today)`)。

### Y7. 排序无稳定次序、无二级键
- `models.dart:132-152`:同天数的事件没有 tie-break,`List.sort` 非稳定(>32 条时),Pro 用户列表可能在两次 build 之间互换。加 `title`/`id` 作末位比较。

### Y8. 标题无长度上限、Pro 门兜底价
- `event_edit.dart:107-116` 无 `maxLength`(建议 40);`daycount_tool.dart:71` `ProPriceText(fallback: r'$1.99')`:商店不回价时中文用户看到「$1.99」,与 PLAN 中区 ¥2-3 不符,建议 fallback 改成 `tr(zh:'解锁', en:'Unlock')` 不带价。

### Y9. 编辑页小对比与信息行英文换行
- `event_edit.dart:287-289` 白色锁/勾图标叠在 #F2B705 琥珀上对比 ≈1.8:1;`event_detail.dart:226-229` 标签列固定 64px,英文「From today」会折成两行。

### Y10. 强行停止后小组件不再刷新(平台限制,写进验收说明)
- Android 对「强行停止」状态的 App 不投递 manifest receiver 广播,国产 ROM 的一键清理常等于强行停止。R1 的闹钟方案也会受此影响。无需改码,但 PLAN 验收第 5 条要注明「被强停后需打开一次 App」。

## 五维度逐项结论

### 1 产品设计
- **楔子兑现**:①「小组件是主体验」——代码里只有一个 2×2 单事件小组件,数据烤死(R1)、无添加入口(Y4)、不随事件色(Y3),现状是「有一个小组件」而不是「小组件是主体验」;②「一次买断零广告」——`PurchaseService` non-consumable + 无广告 SDK,兑现;③「零联网」——`AndroidManifest.xml:7` `tools:node="remove"` 剥 INTERNET,可验证,兑现(iOS 无对应概念,英文文案「requests no INTERNET permission」在 App Store 侧不成立)。
- **功能清单 vs 实现**:PLAN 列的 10 项全部存在(列表/三态/每年/置顶/排序/增删改/日期与 emoji 颜色选择/小组件/免费 5 条/设置项)。emoji 是 16 个固定预设不可自定义,商店文案「emoji 图标」不算失实。
- **定价与免费层**:免费 5 条 + 2 色(`kFreeColorCount=2`),Pro = 无上限 + 8 色。5 条对「生日+纪念日+考试+发薪日」一类用户刚好够用,转化点合理;但 Pro 的内容(6 个颜色)对 ¥8 偏薄,PLAN 自己也承认——这是「¥8 卖的东西还没到位」的代码侧证据。
- **商店文案承诺核对**:listing.md 承诺的 小组件/三态/每年+闰年/M3+emoji+颜色/置顶驱动小组件/本地/无网络权限/免费 5 条 — App 里都有。**「一键导出全部日子」没有出现在 listing.md 任何一处,没有提前承诺**;同时 PLAN 08-28 要求「提到最前」的「小组件不额外收费」也**还没写进 listing.md**,行动项两条都未落地。英文标题仍是 PLAN 判定必须改的「DayCount」。

### 2 代码实现(装到真机上什么会坏)
- **小组件全链路**:添加 ✅(`initialLayout` 占位→首次 onUpdate 贴上一次推送的值);点击回 App ✅(`getLaunchIntentForPackage` + `FLAG_IMMUTABLE`,`CountdownWidgetProvider.kt:37-46`);App 内改动刷新 ✅(`_save`→`push`→`updateWidget` 显式广播,prefs 用 `commit()` 同进程读得到,插件源 `HomeWidgetPlugin.kt:63`);**跨零点 ❌(R1)**;**后台切回 ❌(R2)**;App 被划掉 ✅(prefs 持久、receiver 正常收);强行停止 ⚠️(Y10);R8 ✅(`proguard-rules.pro:6-8` keep work/room,`build.gradle.kts:57-60` 已挂上;Provider 由 manifest 引用不会被剥)。
- **持久化**:写失败被吞、非原子、损坏即清空(O4);init/load 竞态(O5)。
- **边界值**:2/29 ✅(`clampToMonth`);跨时区 ✅(ISO 无 Z、字段保真,`daysBetween` UTC 整日);跨零点 App 内 ❌(R2);1900–2200 ✅(picker 限定,月 13 日 0 归一化正确);空标题被 `_valid` 拦 ✅、超长标题列表省略 ✅ 但无上限(Y8)、emoji ✅;5 位数详情裁切 ❌(O3)、小组件折行(Y2)。
- **Pro 门**:`atLimit` 在打开编辑器前查、颜色锁在点击时查,普通用户无绕过路径;JSON 存在私有目录,不构成可绕过面。免费用户编辑一条已有 Pro 色的事件可保留该色(无害)。
- **内购反馈**:购买/恢复/pending/错误在**设置页**都有 snackbar;从**首页**触发全部静默(O1);恢复无结果静默(O2);`completePurchase` ✅;价格走商店下发 ✅。

### 3 逻辑自洽
- `daysBetween`(models.dart:64-68)UTC 整日差,DST 安全 ✅;`nextYearlyOccurrence`(:78-85)「今天算今年、已过跳明年、2/29→2/28」✅;`progressOf` prev 也用 clamp ✅;三态 `days==0/>0/<0` 无 off-by-one(今天=0、明天=1)✅;`compareEvents` 置顶→未来(含今天,0 最小自然排首)→过去按最近 ✅ 与 PLAN 一致;`sortedEvents` 缺 tie-break(Y7)。
- 「已过去 N 天」不含当天(搬家当天=0),与「还有」对称,自洽;PLAN 验收清单写的「已经 N 天」与 App 文案「已过去 N 天」不一致,属文档措辞。
- 测试:`countdown_test.dart` 17 项 + `widget_test.dart` 1 项 = 18 项,与 PLAN 相符;覆盖了整日差/闰年 clamp/年滚动/三态/排序/JSON。**缺口**见文末清单,最要紧的是 JSON 回环没断言 `yearly`(:108-115)、`nextYearlyOccurrence` 没直接测 2/29 输入、`progressOf` 零覆盖、排序未测「今天」的位置。

### 4 用户体验
- **主路径**:首开→空状态(图标+标题+两行引导,FAB「添加日子」)→编辑页(标题/日期/每年/置顶/图标/颜色/备注,保存键随标题有效性亮灭)→列表→详情。这段顺。**断在「加小组件」**:App 内没有入口(Y4),用户要自己去桌面长按;**再断在「次日回来」**(R1/R2)。
- **错误反馈**:首页购买静默(O1)、恢复无结果静默(O2)、保存失败静默(O4,只 `debugPrint`)、iOS 刷新假成功(O7)。删除有确认框 ✅、免费上限有弹窗 ✅、锁色有 snackbar 并指路 ✅。
- **文案**:zh 自然;en 基本准确,`past N days` 歧义(Y5),`in / 12 / days` 徽章三行拼读尚可。`tr()` 漏网:Dart 侧无硬编码用户可见串(`weekdayLabel` 已 tr);原生侧 `CountdownWidgetProvider.kt:22`、`countdown_widget.xml:21` 硬编码「倒数日」(Y1)。
- 「刷新桌面小组件」tile 在 Android 上无论有没有小组件都提示成功;可保留但建议合并进 Y4 的「添加/刷新」。

## 缺失的测试清单

1. `nextYearlyOccurrence(DateTime(2000,2,29), DateTime(2026,3,1))` → `2028-02-29`;`(…, DateTime(2027,2,28))` → `2027-02-28`(当天);`(…, DateTime(2028,2,29))` → 当天。
2. `statusOf` 对 2/29 每年重复项在平年 2/28 当天 `isToday==true`。
3. `progressOf`:非重复 → null;重复项在 target 当天 → 1.0;跨 2/29 周期 total=365/366。
4. `compareEvents`:「今天」排在所有未来项之前、置顶的过去项排在未置顶的未来项之前;同天数 tie-break 稳定(Y7 修后)。
5. JSON 回环断言 `yearlyRepeat`(现有用例漏掉);`fromJson` 缺字段/旧版本兼容。
6. `daysBetween` 跨真实 DST 日期(如 `2026-03-08 → 2026-03-09`、`2026-11-01 → 2026-11-02`)= 1。
7. `EventStore`:用 `path_provider` mock 到临时目录做 保存→重载 回环;损坏 JSON → 不清空/保留备份(O4 修后);`atLimit` 在 5 条时为 true、Pro 后为 false;`unlockPro` 在 `loaded=false` 时不落盘(O5 修后)。
8. `WidgetBridge`:featured 选择(置顶优先/今天优先/最近过去兜底)与空库文案;R1 修后改为断言写入的原始 JSON。
9. Kotlin 侧(R1 修后)`androidTest` 或纯 JVM 单测:同一组日期用例与 Dart 结果一致(2/29、跨年、今天)。
10. Widget 测试:空状态渲染、第 6 条触发上限弹窗、锁色 snackbar、详情 5 位数不溢出(用 `tester.takeException` / golden)。
