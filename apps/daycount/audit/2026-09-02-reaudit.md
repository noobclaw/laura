## 新引入的问题(🔴/🟠/🟡:文件:行 / 现象 / 修法)

- 🔴 **N1 `java.time` 在 minSdk 24 无 desugar → Android 7.0/7.1 真机崩**
  `CountdownWidgetProvider.kt:11-16, 60-68, 118-125, 145-149` / `android/app/build.gradle.kts:20-24, 32`(`minSdk = flutter.minSdkVersion` = 24,`compileOptions` 无 `isCoreLibraryDesugaringEnabled`,无 `coreLibraryDesugaring(...)` 依赖)。
  现象:`java.time.LocalDate/YearMonth/ChronoUnit/ZoneId` 在 API < 26 不存在。**编译、D8、`flutter build` 全绿**(lint NewApi 不在 flutter build 里跑),CI 抓不到;装到 Android 7 上,系统或 `home_widget.updateWidget` 一发 APPWIDGET_UPDATE → `onUpdate` 抛 `NoClassDefFoundError` → receiver 崩 = **App 进程崩**(用户在 App 里保存事件时当场闪退),小组件永远停在 initialLayout 占位。Play Console 会计入崩溃率。
  修法(三选一,推荐 ①):① `defaultConfig { minSdk = 26 }`(Android 8.0+,2017,一行,顺带把 DATE_CHANGED/隐式广播语义统一到 O+);② `compileOptions { isCoreLibraryDesugaringEnabled = true }` + `dependencies { coreLibraryDesugaring("com.android.tools:desugar_jdk_libs:2.1.5") }`(R8 已开,可用,但会加包体和 CI 时间);③ 改用 `java.util.Calendar` 重写 4 个函数。改完须真机/模拟器 API 24 装一次验证。

- 🟡 **N2 `DATE_CHANGED` 是死过滤项,注释误导**
  `AndroidManifest.xml:46`、`CountdownWidgetProvider.kt:36`。`ACTION_DATE_CHANGED` 不在 Android 8+ 隐式广播豁免名单(只有 TIME_SET / TIMEZONE_CHANGED 在),manifest receiver 收不到。无害(零点靠闹钟 + 30min),但文件头注释「on the system's time / zone / date broadcasts」让人以为有三重保障。建议删该行或注释说明「仅 <26 有效」。

- 🟡 **N3 O4 残余:JSON 合法但某条 `fromJson` 抛错 → 部分加载后被下一次保存覆盖**
  `store.dart:38-49`:`events.clear()..addAll(map(fromJson))` 在第 k 条抛(如 `date` 缺失/非法、`id` 为 null)→ 外层 catch → `events` 只含前 k-1 条,`loaded=true`;`JsonFileStore.read()` 因 JSON 能解码**不会**改名保留;用户下一次改动即用残缺列表覆盖原文件。现实概率低(文件是自己写的),但正是 O4 想堵的那类洞。修法:逐条 `try/catch` 跳过坏条(同 `importJson` 的写法),或整批解析失败时把 `raw` 原文另存 `.corrupt-*`。

## 小组件新架构专项结论(①-⑨)

① **`LocalDate.now()` vs Dart `dateOnly/daysBetween`:一致。** 两端都取系统默认时区的本地日历日;Dart `daysBetween` 把 y-m-d 塞进 `DateTime.utc` 再 `inDays`,Kotlin `ChronoUnit.DAYS.between(LocalDate, LocalDate)` 都是纯日历差,DST 无影响。`dc_date_iso` 由 Dart `dateOnly` 后的 y-m-d 拼出(`widget_bridge.dart:72-73`),无时区串扰。时区切换:Dart 下次 build 重算,Kotlin 收 TIMEZONE_CHANGED 重绘,同步。
② **`nextYearly` 与 Dart `nextYearlyOccurrence/clampToMonth`:逐字等价。** `clamp(year)=min(day, lengthOfMonth)` ≡ `DateTime(year, month+1, 0).day` 兜底;`thisYear.isBefore(today)` 严格小于 ≡ Dart `candidate.isBefore(t)`;今天=今年、已过=明年、2/29→2/28 三条均同。
③ **显式广播可达。** `midnightIntent` 用 `Intent(context, CountdownWidgetProvider::class.java)` 设了 component → 显式 Intent,不受 Android 8+ 隐式广播限制,也不需 filter 命中;Android 12+ 已带 `FLAG_IMMUTABLE`;Android 14 的 receiver export 规则只管运行时注册,manifest receiver 无影响;系统投递 APPWIDGET_UPDATE 需 `exported=true`,正确。唯一前提是 App 未被「强行停止」(首轮 Y10,平台限制)。
④ **requestCode 不冲突。** 点击是 `getActivity(…, 0, launch)`,闹钟是 `getBroadcast(…, 1, midnight)`——类型不同本就不互撞,requestCode 也分开了。`FLAG_UPDATE_CURRENT` 使每次 render 重排闹钟时复用同一个 PendingIntent,不会堆积。
⑤ **`onDisabled` 取消闹钟正确。** `am.cancel(midnightIntent(context))` 以同 component+action+requestCode 匹配,能命中。`onEnabled` 没排闹钟但系统紧接着必调 `onUpdate`(会排),OK;`refreshAll` 在 ids 为空时不重排,与 onDisabled 一致。
⑥ **`R.string.app_name` 存在。** `res/values/strings.xml`「DayCount」、`res/values-zh/strings.xml`「倒数日」;`namespace = "com.noobclaw.daycount"` 与 Kotlin package 一致,`R` 可解析。
⑦ **`{n}` 替换正确。** Kotlin `String.replace(String, String)` 是字面替换;zh「还有 12 天」「已过去 3 天」;en「12 days to go」「3 days ago」;单数走独立键 `dc_label_future_1/past_1`(「1 day to go」「1 day ago」),0 走 `dc_label_today` + 数字位「🎉」。模板缺失时兜底 `"{n}"` → 只显示数字无单位,仅在「旧版本 prefs 升级」时出现,而此前版本从未发布,可忽略。
⑧ **无事件显示。** 有过 push:title=App 名(按 App 语言)、num「—」、label「还没有添加日子」、date「打开 App 添加」;**从未打开 App 就加小组件**:prefs 全空 → `dc_has_event=false` → title 走 `R.string.app_name`(跟系统语言)、num「—」、label/date 空。可接受。
⑨ **Kotlin 编译层:代码本身能过,API level 不能。** import 齐全;`intent.action`(String?)在 `when` 里比常量 OK;`Math.abs/minOf/toInt()` OK;`runCatching { LocalDate.parse("") }.getOrNull()` 正确兜住 `DateTimeParseException`;`Intent.ACTION_TIME_CHANGED` 就是 `"android.intent.action.TIME_SET"`,与 manifest 对上。`setAndAllowWhileIdle` 需 API 23 ≤ minSdk 24 ✓;**`java.time` 需 API 26 > minSdk 24 且无 desugar ✗ → N1 🔴**。`updatePeriodMillis=1800000` 恰为系统允许的最小值 ✓。
