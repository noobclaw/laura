## 🔴 阻断项(不修不能上架)

### R1. 存盘非原子 + 读盘失败后照常写盘 = 一次异常就永久清空全部数据
- **文件:行**:`lib/tool/store.dart:58-72`(`_save`)、`:39-56`(`load`,`finally` 无条件 `loaded = true`)、`:121-124`(`unlockPro`);触发点 `lib/main.dart:16`。
- **现象**:
  - (a) `writeAsString` 是「截断 + 顺序写」,进程在写到一半时被系统杀掉(低内存、用户上滑杀、断电)→ 文件是半截 JSON → 下次 `load()` 的 `jsonDecode` 抛错 → `catch` 只 `debugPrint` → `finally` 仍把 `loaded=true` → 首页显示**空状态「还没有牌组」**,用户一建牌组(或任何操作)`_save()` 就用空 decks **覆盖**那个本来用文本编辑器就能救回来的文件。
  - (b) `main.dart:16` 在 `load()` 完成前就订阅了购买流。iOS StoreKit 会在**每次启动**重投未 `finish` 的交易(购买过程中 app 被杀、或上次 `completePurchase` 失败都会留下),`_handlePurchases` → `unlockPro()` → `_save()` 写出 `{pro:true, decks:[]}`。若这次写先于 `load()` 的 `readAsString`,**所有牌组被清空**;若晚于,内存态 `pro=false` 会在下一次 `_save` 把文件里的 `pro:true` 又写回 false(Pro 丢失)。两种结果都是坏的。
  - (c) `_save()` 之间无串行化:连点四档评分时多次 `_save` 并发,`getApplicationDocumentsDirectory()` 的 await 让写入顺序不保证,旧状态可能后落盘。
- **真机复现**:
  - (a) 建 1 个牌组加 300 张卡(JSON 明显变大),在「保存」瞬间从多任务上滑杀 app 反复几次;或直接用 adb `run-as` 把 `remcard.json` 截掉最后 20 字节 → 重开 → 空状态 → 新建牌组 → 原文件被覆盖。
  - (b) iOS 沙盒账号购买 Pro 时在支付弹窗出现后强杀 app → 重开(交易会重投)→ 观察牌组是否还在。
- **修法**(约 20 行):
  1. `_save`:先写 `remcard.json.tmp`,再 `rename` 覆盖(POSIX rename 在 Android/iOS 上原子)。
  2. `load`:`catch` 里把损坏文件 `rename` 成 `remcard.json.corrupt-<ts>` 保留,并设 `loadFailed=true`,UI 给一条可见提示「上次数据未能读取,已备份为 …」;**不要**在 `loaded` 之前允许任何 `_save`(`_save` 开头 `if (!loaded) return;` 或把 `unlockPro` 排队到 `load()` 之后:`await _loadDone.future`)。
  3. `_save` 用 `_saveChain = _saveChain.then((_) => _doSave())` 串行化,且把 `jsonEncode` 放到 await 之前(拿到当时快照)。
  4. 顺手:`_save` 失败目前只 `debugPrint`(磁盘满等)→ 用户以为保存了。至少置一个 `saveError` 通知 UI 弹一次 snackbar。

### Y1. `epochDayOf` 在 UTC+0 夏令时地区(英国/爱尔兰/葡萄牙)每年错两次一天

## 五维度逐项结论

### 1 产品设计
- **楔子兑现度**:三要素「纯本地 / 无账号 / 一次买断」在代码里全部成立:Manifest 主动剥 INTERNET(`AndroidManifest.xml:10`),无任何账号或网络代码,`in_app_purchase` non-consumable 单商品。**兑现**。
- **功能清单 vs 实现**:PLAN §2 v1 七项全部有对应代码(牌组 CRUD、卡片 CRUD、SM-2 会话、进度/空状态、JSON 持久化、原理页+隐私、免费门)。但 PLAN §7 验收清单第 3 条(重来很快再现、简单可见更远)**与实现冲突**(O2、O3),第 5 条「弹购买页」实现为 snackbar(O5)。**清单先于代码写了产品期望,代码没跟上**。
- **定价/免费层**:免费 2 牌组 + 无限卡片,核心闭环完整可用,符合 PIPELINE「免费层真可用」。Pro 门卡在「第 3 个牌组」是对的位置(导入上线后每个文件一个牌组,门会更有效)。$4.99 对标 AnkiMobile $24.99 的 1/5,符合定价阶梯。缺点:门的呈现太弱、价格不可见(O5)。
- **商店文案承诺**:「每个牌组显示今日到期数」✓、「4 档评分自动安排」✓、「深色模式」✓(跟随系统)、「Material 3」✓、「零网络权限商店可验证」Android ✓ / iOS 概念不适用(Y3)。**无虚假承诺**。「答错很快重来」这句在 O2 修之前只算「明天重来」。

### 2 代码实现(按真机会坏什么)
- **权限流**:本 app 零危险权限、零 UsageDescription 需求,Info.plist 干净;N/A,无风险。
- **生命周期**:无后台任务;唯一断点是跨天不刷新(O4)。切后台/来电无状态丢失(每次评分即时落盘)。
- **持久化**:🔴 R1(非原子写 + 损坏后覆盖 + 启动竞态 + 并发写乱序);写失败静默(R1.4)。`fromJson` 对缺字段都有默认值,**向前兼容**没问题;但没有 `schemaVersion` 字段,v1.1 导入/字段变更时无迁移钩子——建议现在就加 `'v': 1`。
- **边界值**:空名/空白名被 `trim` 拦住 ✓;超长牌组名 AppBar 自动省略 ✓;超长卡面复习页可滚动 ✓;特殊字符走 JSON 无问题 ✓;`ease` 有 1.3 地板,`interval` 有 `max(1,…)` ✓,无上限(Anki 上限 36500 天,可忽略)。
- **Pro 门绕过**:`pro` 明文存在 `remcard.json`,root/越狱可改——与全厂一致,$4.99 产品可接受。真正的绕过风险在 Y8(导入不经门)。
- **内购流程**:购买 / 恢复 / pending / error 四态都写了 notice,但 (a) notice 只在设置页可见(O5.②),(b) 恢复无命中零反馈(O6),(c) 原始错误串直出(O6),(d) `pendingCompletePurchase` 有 `completePurchase` ✓。`restore` 与 Apple 3.1.1 要求一致 ✓。
- **iOS 与 Android 差异**(用户点名要找):
  | 项 | Android | iOS | 判定 |
  |---|---|---|---|
  | 桌面显示名(zh) | 记得 | Remcard | O1 |
  | 按 app 切语言 / 商店语言列表 | N/A | 缺 `CFBundleLocalizations` | O1 |
  | 商店不可用文案 | 对 | 提 Google Play | O6 |
  | 启动重投未完成交易 | 少 | 每次启动 | R1(b) 主要在 iOS |
  | 数据备份 | Auto Backup 默认开 | iCloud 备份 | Y3(文案) |
  | 横屏 | 未锁 | 未锁 | Y9 |
  | 字体 | Roboto | SF | 无问题,tabular figures 两边都支持 |

### 3 逻辑自洽
- **SM-2**:间隔序列 1 → 6 → ×ease、ease 公式、1.3 地板、q<3 归零——与 SM-2 主流实现一致,**单测覆盖了这四点**。偏差:未实现 SM-2 第 7 条「当日重复到答对」(O2);Hard 无独立间隔系数、Again 扣 ease 过猛(Y2);Easy 首次 = 1 天使「简单」无感(O3)。
- **到期日/跨天/时区**:`epochDayOf` 在固定时区内单调正确;UTC+0 夏令时区和跨时区飞行会错 1 天(Y1)。`reviewCard` 在评分时刻取 `today`,会话跨零点也正确 ✓。
- **状态机**:会话快照 + `_index` 推进,`_index >= length` 即完成,无死角;空队列不可进入(按钮禁用)✓。快速双击评分理论上可连评两张,可忽略。
- **数据模型**:删除牌组对象引用移除、卡片随牌组一起没了,无残留 ✓;ID = 微秒时间戳 + 进程内序号,足够唯一 ✓;`Dismissible` key 用 card.id ✓。缺 `schemaVersion`(见维度 2)。
- **测试覆盖**:核心算法有;**持久化、日期计算、会话队列、免费门、页面主路径全部无测试**(清单见文末)。

### 4 用户体验
- **主路径**:首启空状态(图标 + 引导 + 按钮,有温度)→ 建牌组对话框 → 牌组页(此时按钮「今日已复习完」+ hero「0 🎉」,Y4 两处误导)→ 加卡对话框(漏栏静默丢,O7)→ 复习(顺;但看不到间隔,O3;重来不再现,O2)→ 完成页(有庆祝图标 ✓)→ 次日:冷启动正确、热恢复错(O4)。**顺,但每一步都有一个小坑**。
- **错误反馈**:存盘失败无提示(R1.4)、恢复购买无命中无提示(O6)、编辑漏栏无提示(O7)。三处静默失败,违反 PIPELINE「禁止静默失败」精神。
- **文案**:英文自然、语气一致。中文语义准确,但半角标点通篇(Y6)、一句拗口(:29)。多语言覆盖:`lib/` 内**没有漏 `tr()` 的用户可见硬编码**(逐文件核对;`import_deck.dart` 的英文默认值由调用方覆盖,不算)。Material 自带对话框走 `GlobalMaterialLocalizations.delegates` ✓。ja 只有设置页三条,其余回落英文,符合「ja 可选」。
- **多余/困惑**:牌组重命名/删除藏在 ⋮ 菜单可接受;卡片行的 ⏰ 图标无解释;设置页把「原理」放第一位、「解锁 Pro」第二,顺序合理。

## 缺失的测试清单

1. **`store.dart` 持久化**(全无):save→load 往返;损坏 JSON 加载后不覆盖原文件且保留备份;`load()` 前调用 `unlockPro()` 不丢牌组;并发 `_save` 最终落盘为最新状态;`_file()` 抛异常时 `loaded` 行为。需用 `path_provider_platform_interface` mock 或把文件路径注入。
2. **`epochDayOf`**:连续 400 个本地日期映射严格 +1(当前实现在 UTC+0 DST 机器上会挂,正是 Y1 要抓的);同一天不同时刻映射相同。
3. **`Flashcard.review` 补充**:Hard 于 rep 1/2 的间隔;Again 后 ease 的具体值(锁定 Y2 决策);`isDue` 在 `dueDay == today` 边界;Easy 首次间隔(锁定 O3 决策);`intervalDays` 从 JSON 读到负数/0 时的行为。
4. **会话逻辑**(`_StudyScreenState` 抽成可测的 `StudySession` 类后):快照不受中途新增卡影响;Again 重入队列直到 ≥Hard;`reviewed` 计数;空队列直接完成。
5. **免费门**:`atDeckLimit` 在 pro=false 时 2 个满、pro=true 时不限;**导入路径**建牌组也受限(Y8)。
6. **Widget 主路径**:`pumpWidget` → 建牌组 → 加卡 → 开始复习 → 显示答案 → 评分 → 完成页;免费第 3 个牌组被挡;`Dismissible` 删卡后列表更新。现在的 `widget_test.dart` 只断言标题存在。
7. **本地化**:同一 widget 在 `zh` / `en` 下均能找到关键文案(防漏 `tr`);`tr()` 对 `zh_Hant` 返回中文。
8. **购买服务**:用 `InAppPurchasePlatform` fake 驱动 `purchased / restored / error / pending / canceled` 五种事件,断言 `notice` 文案与 `onUnlocked` 调用;`restore` 无命中时产生提示(O6 修后)。
