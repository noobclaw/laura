# Accord — Independent audit (G5), 2026-11-26

Scope: `Accord/`, `project.yml`, `Info.plist`, `PrivacyInfo.xcprivacy`, string catalogs, `PLAN.md`, checked against `tool-app-factory/templates/audit-checklist.md`.
Method: I read the code; I could not compile or run it (Linux, no Swift). Every finding below was traced in the source. Items marked **(confirm on device)** rely on known SwiftData runtime behaviour, not on a run.

Totals: **P0 1 · P1 8 · P2 20**

---

## P0 (crash, data loss, rejection)

### P0-1 Deleting a material reads and writes the deleted object (confirm on device)
- **Where:** `Accord/Features/Library/MaterialDetailScreen.swift:137-139` (delete, save, dismiss) and `:131-134` (`onDisappear`).
- **What happens:** "Delete material" calls `context.delete(material)`, then `try? context.save()`, then `dismiss()`. When the screen pops, `onDisappear` reads `material.name`. If the name is blank it also writes `material.name`, and then it calls `context.save()` again. The pop animation also re-renders the `Form`, which reads `material.*` and `material.formulas`. On iOS 17 SwiftData, touching an attribute of a model that has been deleted and saved commonly ends in `Fatal error: This model instance was invalidated because its backing data could no longer be found in the store`. The deployment target is iOS 17.0, so this can crash on an ordinary action.
- **Fix:** keep a `@State var deleted = false`. In the button: `deleted = true; dismiss()`, then delete in `.onDisappear { if deleted { context.delete(material); try? context.save(); return } … }`. As an alternative, guard every access with `material.isDeleted || material.modelContext == nil`. The same pattern also applies to P1-6.

## P1 (real user-facing bugs)

### P1-1 Candle, soap and diffuser batches get "Perfumer's alcohol"
- **Where:** `Accord/Engine/FormulaMath.swift:242-251`; `Accord/Features/Weigh/ScaleSheet.swift:33-34, 90-96, 185`; `Accord/Features/Bench/Panels.swift:97-102`.
- **What happens:** in bottle mode, `ethanol = mass * (1 - c) * (1 - w)` is computed for every product type. `isAlcoholic` only forces `waterShare` to 0. Take a 200 ml candle at 8 %: the weighing sheet and the weigh flow tell the user to add about 92 % ethanol, and the mass is computed with ethanol density. The "Per 50 ml bottle" cost adds alcohol price to candles and soap in the same way. A user who follows the sheet adds flammable ethanol to wax.
- **Fix:** add `isAlcoholic` (or a diluent kind) to `ScalePlan.Mode.bottle`. For non-alcoholic products, either (a) ask for the base weight (wax, soap or diffuser base) and output only the fragrance grams, or (b) label the balance row "Base (wax/soap/carrier)" with its own density and no ethanol step. Apply the same rule in `bottleCost`.

### P1-2 CSV import reads a "1 %" dilution as neat (100×)
- **Where:** `Accord/Export/CSVImport.swift:117-120`.
- **What happens:** `number()` strips `%`. Then `v > 1 ? v/100 : v` turns `1` or `1%` into `1.0` (neat) and `0.5%` into `0.5` (50 %). In perfumery, 1 % is one of the most common dilutions. The imported line is then counted at 100× its active material in the analysis, the pyramid, the limit check and the stock deduction.
- **Fix:** if the raw cell contains `%`, always divide by 100. Treat a bare number as a fraction only when it is ≤1 and contains a decimal point, or add a "Dilution %" header variant. Show a summary after import ("12 lines diluted; 1 % read as 1 %").

### P1-3 Deleting a formula that is used as a base silently breaks other formulas
- **Where:** `Accord/Features/Bench/BenchScreen.swift:134-138, 310-315`; `Accord/Features/Shelf/ShelfScreen.swift:103-111`; `Accord/Model/Models.swift:96-98` (`usedAsBaseIn` is `.nullify`), `:196-209`, `:118`.
- **What happens:** the confirmation only says "Batches you already made keep their records." It says nothing about the other formulas that use this one as a base. After deletion, those lines have neither `material` nor `base`:
  - They show "Missing material".
  - `mixLine` returns nil, so they drop out of the analysis, limits and cost.
  - `Formula.totalGrams` still counts their grams, so the % shown on each Bench row and in exports no longer matches the analysis.
  - "Missing material" becomes a weighing step.
  
  This is easy to hit with the samples: deleting "Amber Base" breaks "Evening Amber".
- **Fix:** if `!formula.usedAsBaseIn.isEmpty`, say so in the dialog ("Used as a base in N formulas"). Offer "Unpack into those formulas", which replaces each base line with its scaled material lines, or block the delete. Make `totalGrams` and `LineRow` share use the same set of lines that `mix()` uses.

### P1-4 "Restore purchase" in Settings gives no result; the message pops up later in the paywall
- **Where:** `Accord/Features/Settings/SettingsScreen.swift:130-135`; `Accord/Store/ProStore.swift:104-114`; the only place `store.message` is shown is `Accord/Features/Store/ProSheet.swift:115`.
- **What happens:** when no purchase is found, or restore fails, Settings shows nothing. The message stays set in `store.message`, and it appears as an unrelated alert the next time any paywall opens. The checklist requires restore to "tell the user the result".
- **Fix:** in `SettingsScreen`, add the same `.alert` bound to `store.message`, or copy `store.message` into the local `message` after `await store.restore()`. Clear `store.message` when `ProSheet` appears.

### P1-5 App Lock does not cover sheets; Face ID is attempted while still in the background
- **Where:** `Accord/App/RootView.swift:33` (`.overlay { LockScreen }`), `:39-40`, `:104` (`LockScreen.onAppear { lock.unlock() }`).
- **What happens:**
  - The lock is an overlay on the root view. Sheets and full-screen covers are presented above the root, so they stay above the overlay. If the user leaves the app with a sheet open (Settings, Line editor, Plan a batch, Weigh, Export) and comes back, that sheet is visible and usable on top of the lock. App Lock is sold as a Pro feature ("Keep your formulas behind Face ID").
  - The overlay is inserted at `.background`, so its `onAppear` → `evaluatePolicy` can fire while the app is not interactive. The prompt then fails and the user sees an error string under "Accord is locked" instead of an automatic Face ID prompt (confirm on device).
- **Fix:** host the lock in its own `UIWindow` at `windowLevel = .alert + 1`, shown on `.inactive`/`.background` and hidden after successful auth. Call `unlock()` on `scenePhase == .active` rather than in `onAppear`.

### P1-6 Other delete paths touch deleted models during dismissal (confirm on device)
- **Where:**
  - `Accord/Features/Bench/LineEditorSheet.swift:153-157`: "Remove from formula" deletes and saves, then dismisses. The sheet body stays alive during the dismiss and re-renders (it reads `formula.lines`), and `others` reads `line?.id`.
  - `Accord/Features/Lab/LabScreen.swift:178-184`: the batch is deleted and saved, then popped. The pushed view re-renders `batch.formulaName`, `batch.entries` and so on.
  - `Accord/Features/Bench/BenchScreen.swift:310-315`: the formula is deleted while `BenchContent` (which holds `@Bindable formula`) is still on screen.
- **What happens:** this is the same SwiftData failure mode as P0-1, but timing-dependent.
- **Fix:** dismiss first and delete in `onDisappear` or after the dismissal completes. For Bench, set `state.currentFormulaID` to the next formula before deleting, and guard `BenchContent` with `formula.isDeleted`.

### P1-7 Editing a line shown in % silently rewrites its grams
- **Where:** `Accord/Features/Bench/LineEditorSheet.swift:189` (load), `:58-64`, `:229-233` (save); `Accord/Engine/FormulaMath.swift:113`.
- **What happens:**
  - **(a) Single-line formula.** If the formula has one line and its unit is %, the editor loads "100". `grams(forPercent: 100, othersTotal: 0)` returns **1**. Tapping Save, for example after only changing the flag or the note, sets that line from 12.5 g to 1 g. "Total on the scale", the Multiply and Concentrate plans, and cost all change.
  - **(b) Several lines.** The % is shown with 3 decimals and then converted back to grams. Every open-and-save in % mode therefore moves grams slightly, even when the user changed nothing.
- **Fix:** store the loaded `amountText`. In `save()`, keep `line.grams` unless the text changed. For percent with `othersTotal == 0`, keep the existing grams.

### P1-8 `store/` is empty
- **Where:** `apps/accord/store/` (directory exists, no files).
- **What happens:** checklist items 8 and 9 and the SKILL's G8a/G8b need `store/listing.md` (in 10 languages) and `store/aso.md`. As it stands, the build cannot pass G8a, and the copy-versus-implementation check has nothing to check.
- **Fix:** write them before any TestFlight upload. Note that the claims in `PLAN.md §4` are already implemented except the review prompt (P2-19).

## P2 (polish / correctness at the margin)

1. **Bottle density is an arithmetic, mass-weighted average.** `FormulaMath.swift:245-246`. The volume of a mix is the sum of mass over density, so the mixed density should be harmonic: `1 / (c/ρc + (1-c)/ρd)`, and the diluent should be computed the same way. The current error is about 0.5 % at EdP strength. This also ignores ethanol–water contraction; the footer could say so.
2. **Negative limits produce a negative "max safe" value.** `FormulaMath.swift:150-155`. `Compliance.check` skips `limit < 0`, but `maxSafeConcentration` does not, so the user sees "allow up to −x %". `DecimalField` (`Components.swift:245`) accepts `-`, so cost, stock and limit can also be negative. Clamp them to ≥ 0 in `numberRow`.
3. **Wrong error message for a % amount on the first line.** `LineEditorSheet.swift:106`. On the first line, any % below 100 shows "A single line can't be 100 % while others are in the formula", but there are no others. Show "With no other lines, this line is 100 %" instead, or switch the unit to grams.
4. **Plan-a-batch fields clamp on every keystroke.** `ScaleSheet.swift:136-137`. In "Multiply by", typing `0` becomes `0.05` immediately, so `0.25` cannot be typed naturally (the Stepper can't reach it either). "Concentrate" behaves the same way (`0` → `0.1`). Fix: keep a local text state and commit on submit or loss of focus.
5. **The evaporation chart steals scrolling.** `Graphics.swift:125`. `DragGesture(minimumDistance: 0)` inside the Bench `List` captures vertical drags that start on the chart. Use `minimumDistance: 8` and apply it only when the movement is mostly horizontal, or use `.simultaneousGesture` with a horizontal check.
6. **The tab bar rides above the keyboard.** `RootView.swift:15-30`. The custom `TabBar` sits in the VStack, so it moves up with the keyboard on Shelf and Library search, and together with each screen's bottom button this takes about 120 pt. Add `.ignoresSafeArea(.keyboard, edges: .bottom)` to the outer VStack, or hide the bar while the keyboard is up.
7. **No way to dismiss the decimal pad.** `MaterialDetailScreen` number rows, `ScaleSheet`, `WeighScreen` and the Settings alcohol price use `.decimalPad` with no Done button. Add `ToolbarItemGroup(placement: .keyboard) { Spacer(); Button("Done") { focus = nil } }` and/or `.scrollDismissesKeyboard(.interactively)`.
8. **Switching tabs throws away navigation and screen state.** `RootView.swift:16-22`. The `switch` rebuilds each `NavigationStack`, so a pushed Material or Batch detail, the Bench section and the timeline hour are lost on every tab switch. Keep all four stacks alive (a ZStack with opacity) or keep their paths in `AppState`.
9. **The app-switcher snapshot is not covered.** The lock is applied only on `.background` (`RootView.swift:39`), and the snapshot can be taken before the overlay renders. Cover on `.inactive` (this is part of the P1-5 window fix).
10. **Changing the language closes the Settings sheet.** `.id(language.code)` at `AccordApp.swift:35` rebuilds the whole tree. That is acceptable, but the user ends up on the Formulas tab without Settings open. Consider reopening Settings after the switch.
11. **No plural forms anywhere.** Strings such as "1 ingredients" (`BenchScreen.swift:160`), "1 days resting" (`LabScreen.swift:66`), "1 formulas use it" (`MaterialDetailScreen.swift:142`) and "1 materials have no price yet. Add it in Materials." (`Panels.swift:84`) read wrong in English, German and other languages. The catalog has zero `variations`. Add plural variants for the %lld keys.
12. **Hard-coded "h" on the chart axis.** `Graphics.swift:119` uses `Fmt.number(h) + "h"`. Use `Fmt.hours` or the localized `"%@ h"` key.
13. **System error text and over-broad restore error.** Import, restore and purchase messages use `error.localizedDescription`, which follows the device language rather than the in-app language (`LibraryScreen.swift:165`, `ProStore.swift:100, 113`). Restore also maps every error, including a security-scope or read failure, to "This file isn't an Accord backup." (`SettingsScreen.swift:153-155`).
14. **Samples come back after the library is emptied.** `SampleData.swift:98-99` seeds whenever the Material count is 0, so a user who deletes every material gets 53 materials and 3 sample formulas back on the next launch. Use a `UserDefaults` "seeded" flag.
15. **Backup restore gaps.** `Exporter.swift:231-287`.
    - Restored batches do not reschedule their reminders. Call `Reminders.schedule` for batches with future days.
    - Restoring onto a new install duplicates the samples, because the fresh seed and the backup samples have different IDs. Skip `isSample` formulas whose name already exists as a sample.
16. **Stock deduction skips bases and missing lines.** `ScaleSheet.swift:349-358`. Materials inside a base are not deducted (the base line has `materialID == nil`). "Missing material" lines still become weigh steps. Expand bases using the same scale as `mix`.
17. **"Naturals %" only unpacks one level of bases.** `Panels.swift:54-64`. Carry `isNatural` on `MixLine`/`MixComponent` instead.
18. **PDF export truncates long notes.** `Exporter.swift:119, 151-157`. `boundingRect` is capped at 200 pt, and the Total row and notes are not paginated, so long notes get cut off.
19. **PLAN deviations.**
    - §10 review request after the 3rd completed weigh sheet is not implemented; no `requestReview` anywhere.
    - §5 asks for a global drops-per-gram setting (default 20); the code is per-material with default 25. That is fine, but update PLAN.
    - §5 and §12.1 say cold start opens "Bergamot Cologne"; `SampleData.swift:131` returns "Evening Amber".
20. **Privacy manifest declares APIs that are not used.** `PrivacyInfo.xcprivacy:20-29` declares `SystemBootTime` (35F9.1) and `FileTimestamp` (C617.1), but no app code calls uptime or file-date APIs. This is harmless, but remove them (or note why they are there) so the manifest matches the code. `UserDefaults` CA92.1 is correct. No collected data and no tracking is correct (StoreKit is the only network use).

Minor, not numbered:
- The CSV export writes base lines by name, so re-importing turns a base into a new plain material.
- `LibraryScreen.addMaterial` inserts "New material" before the user confirms, so backing out leaves a stray row.

## Checked and OK

- **Paywall gates.** Every Pro gate opens `ProSheet` first, and each one is presented from a context that can present:

  | Gate | Where | Presented from |
  |---|---|---|
  | Formula limit | Bench empty state, Shelf New / Duplicate / Version, Bench "Save as new version" | Root sheet; no sheet is up at those points |
  | Bases | `LineEditorSheet` | The sheet's own `.sheet(item:)` |
  | Batches | `WeighScreen` | The full-screen cover's own `.sheet` |
  | Batches | Lab empty state | Root sheet |
  | Compare, Export | Bench menu, Shelf context menu | Root sheet |
  | Import | Library | Root sheet |
  | Backup, Restore, App Lock, Unlock | Settings | Settings' own sheet |
  | Inventory | Analysis cost card, Material detail (pushed, not a sheet) | Root sheet |

  No direct `purchase()` call exists outside `ProSheet`.
- **Price and transactions.** The price comes from `product.displayPrice` and shows a spinner or retry until it loads; nothing is hard-coded. Only verified transactions are accepted, refunds are handled through `revocationDate`, `finish()` is called, `Transaction.updates` is listened to from launch, and restore is reachable on the paywall and in Settings. The free limit (5 non-sample formulas, returned on delete) matches PLAN.
- **SwiftData model.** Inverses are declared on both `FormulaLine` → `Formula` relationships (`formula` cascade, `base` nullify), `Material.lines` nullifies, and `Batch.agingNotes` cascades. Batches keep `formulaID` and the name as values, so they survive a formula delete. Every property has a default. A store that won't open falls back to memory and shows an alert.
- **Cycles.** The picker excludes self and any formula that contains the current one (`contains(base:)`, depth-capped). `mixLines(visited:)` turns a loop into an opaque line, and `accumulate` caps depth at 6. I found no infinite recursion path.
- **Math.**
  - The dilution split, nested-base scaling (by active grams, with the base's own solvent), aggregation of the same material, percent entry (`p/(1-p)·others`), compliance (share of the concentrate × load), max safe load, and the diff (percentage points of the concentrate) are all correct and covered by `EngineTests`.
  - Divisions are guarded: `share`, pyramid, family ring, compare bars, weigh deviation, `dominant`, longevity, and an empty mix. I found no NaN reaching the UI.
- **Localization.** All 468 catalog keys have all 10 languages, and the code-built strings I checked use `bundle: .l10n`. `Text(verbatim:)` is used only with already-localized or user strings. The ternaries use `as LocalizedStringKey`. `InfoPlist.xcstrings` covers the display name and the Face ID string in 10 languages. The in-app language switch works for both `Text` and `String(localized:)`.
- **Permissions.**
  - `NSFaceIDUsageDescription` is present and localized. A device with no passcode is handled: the lock refuses to enable and never traps the user.
  - Notifications are requested only when a batch is saved or a reminder day is toggled. When they are denied, the user sees "Notifications are off" with an "Open Settings" button.
  - No camera, microphone or photos permissions are needed, and none are declared.
- **iOS project settings.** `TARGETED_DEVICE_FAMILY=1` is set on the target, the app is portrait-only, `UIRequiresFullScreen` is set, and `ITSAppUsesNonExemptEncryption=false`. The 1024 icon is RGB with no alpha, and the launch colour exists. The font PostScript names (`BodoniModa-Medium/-MediumItalic/-SemiBold`) match `Theme`. Dynamic Type is capped at accessibility2.
