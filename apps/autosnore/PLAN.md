## 1. 差异化楔子(G2 必填:用户为什么选我而不是竞品)

> **「云端鼾声 app 要把你整夜的睡眠录音上传到服务器换订阅费;AutoSnore 在手机上直接分析,连网络权限都没有,一次买断、永不上传。」**

竞品(SnoreLab / Sleep Cycle / SnoreClock 等)几乎全是**订阅制 + 云同步**:麦克风整夜录你,音频/趋势要上传或锁在账号里,退订即失去历史。AutoSnore 的三重楔子:①**零联网**(manifest 剥离 INTERNET,可验证)②**一次买断**(无订阅疲劳)③**录音数据不出机**(v1 甚至不落地音频文件,只在设备上算响度事件)。睡眠数据是最私密的数据之一,「不出机」对隐私敏感人群是一击必杀。

## 2. 招牌功能架构评审(G2:可靠性机制选型定死)

**招牌可靠性机制 = 「整夜持续采麦 + 稳定检测响声事件」。** clean-alarm 教训是选错了 Android 原语(通知调度冒充闹钟),本项必须先把原语钉死:

- **采麦原语(v1 定死):前台录音 + 保持屏幕常亮(`wakelock_plus`),不走后台服务。**
  - 录音会话期间 App **始终在前台**(专用录音页),屏幕常亮(息屏会触发系统后台限制/Doze,直接规避)。用户把手机放床头、接充电即可。这是白噪音/睡眠类 App 的成熟做法。
  - **明确不做**「锁屏后台采麦」:Android 10+ 后台麦克风受限、Android 14 需前台服务 microphone 类型 + 各家 ROM 省电策略会掐断——不可在无真机验证下承诺。后台服务版列入 **v1.1**(前台服务 `FOREGROUND_SERVICE_MICROPHONE`),不进 v1。
  - 屏幕常亮功耗提示:录音页自动压暗为近黑背景 + 文案提示插电,PLAN 真机清单里核对整夜续航。
- **音频不落地(v1 定死):`record` 的 `startStream`(PCM16 mono 16kHz)→ 每 ~200ms 计算 RMS→dBFS,只保留响度时间线,绝不写音频文件。** 隐私最强(录音真的不出机、连本地都不存)、footprint 极小(整夜只存几百个事件的元数据)。「回放你的鼾声」需存音频片段,列 v1.1(需真机验证后台/文件管理)。
- **检测逻辑纯 Dart、可单测**:`SnoreDetector` 吃 dBFS 采样流,维持自适应噪声基线(仅静默时更新的 EMA)+ 绝对地板 + 阈值 + 最短时长 + 合并间隔 → 吐 `SnoreEvent(起始/时长/峰值/均值 dB)`。聚合层算鼾声次数、鼾声占比、鼾声指数(次/小时)、最响事件、节律事件数(呼吸周期性)、0–100 鼾声评分。全部确定性,`flutter test` 覆盖。

## 3. 运行时权限流程评审(G2:禁止静默失败)

用到的唯一危险权限:**麦克风 `RECORD_AUDIO`**(经 `permission_handler`)。

- 点「开始记录」→ 显式 `Permission.microphone.request()`。
- **被拒**:录音不启动,页面显示可见提示「需要麦克风权限才能记录鼾声」+「重新授权」按钮,**不静默排程**。
- **永久拒绝**(`isPermanentlyDenied`):提示 + 「去系统设置」按钮 → `openAppSettings()`。
- 无网络权限、无通知权限(v1 不发通知,前台录音不需要)。

## 4. 功能清单(v1 只做核心)

**免费层(真可用)**:整夜记录、当晚晨间报告(时长/鼾声次数/鼾声指数/最响时刻/0–100 评分/整夜响度时间线图/事件列表)、灵敏度设置、**保留最近 3 晚**历史。
**Pro 一次买断解锁**:①无限历史留存 ②跨夜趋势图(鼾声指数走势)③两晚对比 ④CSV 导出(`share_plus`)⑤全部强调色主题。

## 8. 真机验收清单(G7:用户照此逐条点)

1. **权限弹窗**:首次点「开始记录」弹麦克风授权;拒绝→有可见提示 + 「去系统设置」出口(点一次验证跳转)。
2. **核心功能**:安静环境录 1 分钟、故意在麦前发出几声「呼噜」→ 停止后报告里鼾声次数 > 0、时间线有峰、最响事件有值。
3. **传感器/采麦**:整夜(或长时段)录音——屏幕保持常亮不息屏、结束后时长与实际接近、App 未被系统杀。
4. **续航**:插电整夜记录,早晨电量/发热可接受(不插电场景在说明中提示)。
5. **边界**:全程静音房间 → 报告鼾声次数≈0 不误报;录音中途来电/切后台再回→ 会话状态正确(v1 允许中断即结束并保存已录部分)。
6. **Pro 门**:免费仅存 3 晚(第 4 晚后最旧被裁);解锁后无限 + 趋势/对比/CSV 导出可用。

## 8b. G5 独立审计结论(2026-07-27)

独立审计通读全部代码,**无编译/安装/首启阻断**。三处「真机才暴露」问题,已处理:
- **R1 事件计时用采样时钟(已修)**:`record` 平台通道可能一次投递多窗口共享同一墙钟毫秒 → 1 秒鼾声算成 0ms 被 `minEventMs` 丢弃。改为按「已处理字节/采样率」推进音频时钟给检测器打时间戳(每窗恒 200ms),墙钟只用于 UI 显示。加单测覆盖。
- **R3 稳态噪音基线锁死(已修)**:风扇/空调整夜高于阈值时基线冻结、事件永不闭合 → 整夜一条假事件、评分 100。加 `maxEventMs=20s` 硬上限,超时强制闭合并把基线抬到当前电平重新校准。加单测「持续 60s 高声只出 1 条 ≤20s 事件」。
- **R2 离开前台即结束(设计限制,已诚实标注)**:v1 无后台服务,`paused` 即停并保存,标 `endedEarly` → 报告顶部显示「记录提前结束、仅覆盖到此」横幅,不谎报整夜。真正后台采麦是 v1.1 前台服务工程。
- 附带修:一坏记录不再清空全部历史(逐条解析跳过)、灵敏度滑杆改 `onChangeEnd` 落盘(去写风暴)、CSV 导出失败弹提示、`dispose` 先清理再释放录音器。

## 9. 已知限制 / v1.1 路线

- v1 仅前台常亮采麦(需 App 开着 + 屏幕亮);**锁屏后台采麦(前台服务 microphone 类型)= v1.1**。
- v1 不保存音频片段;**「回放你的鼾声」音频片段 = v1.1**(需真机验证后台文件写入与体积管理)。
