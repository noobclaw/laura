### 4.2 页面结构（4 屏，M1 全部本地、零联网）

1. **导入屏**：从相册多选 / 直接连拍（相机内置连拍 8–64 帧，锁定 AE/AF/WB）。显示每帧的 EXIF 曝光时间、ISO、焦距，标出**不一致的帧**（曝光参数不同的帧会毁掉叠加）。
2. **对齐屏（本 app 的核心与全部风险所在）**：星点检测 → 帧间配准 → **逐帧给出对齐质量分与失败原因**（星点太少 / 拖线 / 云挡 / 位移超限），用户可逐帧勾除。**这一屏就是楔子第三条的产品化。**
3. **叠加屏**：叠加模式（均值 / 中值 / **kappa-sigma 剪切** / 最大值[星轨]）+ 帧数滑杆，**实时预览用 1/4 分辨率、导出时才全分辨率**。
4. **导出屏**：拉伸曲线（直方图 + 一键「银河」/「星轨」预设）、降噪强度、导出 JPEG/HEIF/TIFF。**M1 不做暗场/平场标定**（那是 M2）。

### 4.3 技术要点（与参考实现的对应关系，逐条写明许可证处置）

| 步骤 | 做法 | 参考实现与处置 |
|---|---|---|
| 星点检测 | 局部阈值 + 质心细化（亚像素） | `quatrope/astroalign`（**MIT**）可直接读与依赖思路，署名 |
| 帧间配准 | **三角形（asterism）不变量匹配 → 相似变换** | 同上，~600 行，Dart 重写 2–3 天 |
| 特征匹配（备选 / 云天与低星密度场景） | 轻量局部特征 | **`verlab/accelerated_features`（XFeat，Apache-2.0，★1,726，为移动端 CPU 设计）** —— 可内嵌 + 署名 |
| 方法对照与参数选型 | 不打包，仅选型 | `gmberton/vismatch`（BSD-3，★911） |
| 叠加模式与标定规格 | 均值 / 中值 / kappa-sigma / 暗场平场 | **`deepskystacker/DSS`（NOASSERTION = 视同不可用）** → 按 CLAUDE.md 两步走：**先读代码写自己的中文规格（PLAN.md「参考实现分析」节），再只看规格用 Dart 从零实现，不复制任何一行、不移植任何资源** |
| 重投影与像素合成 | 双线性 / Lanczos | 自实现，无外部依赖 |

**三条工程风险（G2 必须先答）**：
1. **内存**：32 帧 × 12MP × float32 ≈ 4.6GB —— **必须分块（tile）流式叠加**，不得整帧驻留。这是本项目做过的 app 里内存压力最大的一个。
2. **耗时**：32 帧全分辨率配准 + 叠加在中端机上是**分钟级**。→ **必须做可中断的后台任务 + 进度可见**，否则会被打成「卡死」（免费三支 ★1.00 很可能死在这里）。
3. **Flutter 层不够**：像素级循环必须走 **Dart FFI + C/C++（或 Rust）**，纯 Dart 会慢一个数量级。**这是 tunekit「节拍器精度必须原生调度」之后第二个明确的原生依赖项。**
